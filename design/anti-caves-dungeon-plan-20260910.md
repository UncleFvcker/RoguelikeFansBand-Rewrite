# 反魔洞穴／反近战洞穴生成与接入计划

## 1. 目标与基线

本批交付原版 16/17 替代组：反魔洞穴禁用相应施法、保留天生怪物能力；反近战洞穴阻止玩家和怪物近战、保留远程行为。两者只有入口守卫，没有最终首领或固定征服奖励。到达 50 层后正常返回与召回即构成探索闭环，不补造首领、神器或通关属性奖励。

- 工作树：`D:/codex/RoguelikeFansBand-Rewrite-dungeons-towns`，分支 `codex/dungeons-towns`，规划基线 `8239bce30`，正式包 `1.401.6`。当前世界含 26 个地牢条目，其中包括既有替代分支。
- 来源：`D:/codex/Frogcomposband/master` 的 `master` Git ref，实际提交 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`；本次通过 `git show` / `git grep` 读取 Git 对象。
- 核对时 main 为 `b374f4344`，本方向尚未同步。最新主线已有心灵术士相关工作；实施时按实际合入状态覆盖其施法入口，不把当前分支六职业当作永久边界。本计划不执行合并或修改其他工作树。
- 本树、main 和法术道具分支尚未找到本组正式地牢 ID 或地牢级禁魔/禁近战实现。既有反魔装备/状态不能直接替代地牢规则。

### 生成标记的实际执行边界

`src/generate.c::gen_caverns_and_lakes` 对水湖要求深度 **>50**、熔岩湖 **>80**；本组深度内不能因声明了标记就安排这两类湖。碎石类要求 >35、树木类要求 >5，可以出现。`DESTROY`、湖泊与普通洞窟在源选择流程中有互斥；`ARENA` 还受生成选项和概率控制，不是每层固定空房。

同文件的河流选择先抽取 1/7，再要求 `randint1(depth)>5`；水/熔岩选择使用 `MAX_DEPTH=128`，无其他模式干预时，熔岩分支概率为 `(depth+1)/256`。源不会在碎石/树木湖层叠加水河或熔岩河。生成计划需保留这些来源事实，再明确当前引擎的适配，不能把“源声明”当作“该深度实际发生”。

反近战的 `GLASS_ROOM` 也不能直接当作强制玻璃房间：本次检索该 ref 的全部 src，除定义/解析外只找到 `rooms.c:4554` 的空条件分支。房间模板另可包含玻璃地形，但不由这个空分支强制生成。本批在来源计划保留该标记，不新增专门玻璃层、玻璃门或局部玻璃房间机制。

### 战斗与生态的实际执行边界

- `src/dungeon.c` 的 `m` 入口按职业/形态处理 `NO_MAGIC`；书本施法与心灵术士等魔法职业会被阻止，不能只检查 `AbilitySourceDto::Learned`。源列有狂战士等特殊技艺例外，本批只映射实施时已经支持的实际职业/形态，不新增这些职业。种族/变异能力以及卷轴、装置、装备激活不能因为最终也调用 effect 就一律封禁；个别近战效果另按来源处理。
- `src/monspell.c::mon_spell_cast` 对敌对怪物先正常选能力，再拒绝非 `MSF_INNATE` 的结果并回到普通行动；不能预先清空魔法候选，变相提高吐息等天生能力频率。怪物对怪物的分支另有 AI 过滤和 `_spell_fail`，包括 `STUPID` 的差异，不能假定两种目标共用同一拒绝时机。
- `src/monster2.c::restrict_monster_to_dungeon`：反魔要求 `mon_race_has_innate_spell`，`MON_CHAMELEON` 例外；反近战要求 `mon_race_has_attack_spell`，后者仅指 BREATH/BALL/BOLT/BEAM/CURSE 类型，不等于“有任意能力”。反近战的变色龙例外与 `summon_specific_who != -1 || !allow_pets` 条件均须核对实际召唤调用。入口守卫是固定地表实例，不经过洞内普通生态白名单；恐虐钢牛没有天生法术也不能因此消失。
- `src/cmd1.c::py_attack`、`melee1.c`、`melee2.c` 阻止玩家、怪物对玩家及怪物互殴。源 `devices.c EFFECT_STUNNING_KICK`、`spells_s.c` 等还在特殊近战效果入口检查；仅拦移动撞怪会漏掉这些消费者。远程攻击不因相邻目标而被归成近战。

## 3. 当前缺口与最小实现方向

1. **无最终守卫目前非法。** `DungeonDefinition.guardian_actor_kind_id` 和导入器 `DemoWildernessDungeonPlan.guardian` 都是必填；`validation/worlds.rs` 要求所有叶子层都有 guardian，且至少有一个最终守卫。改为可表达无最终守卫，保留层链连通、叶子/末层一致和已有守卫引用完整性，不使用空字符串或入口守卫充当最终守卫。
2. **缺地牢级限制。** 在现有 DungeonDefinition 上增加本批必要的限制字段，核心根据当前楼层所属地牢读取；不另存玩家状态、不创建前端规则或新的规则管理器，也不把地牢禁魔写进装备 AntiMagic 被动以免影响豁免等其他语义。
3. **怪物能力分类不完整。** 现有 `monster_ability_is_innate` 为减伤/闪避识别吐息和少数特殊伤害形状；它不是完整 `MSF_INNATE`，例如 SHRIEK、射箭、狂暴等不能靠伤害骰或“是否物理伤害”判定。优先在已有怪物能力候选记录保留源天生/攻击法术分类，并由导入器从真实 token/类别给出，供施法限制与分配读取。保持已有能力 ID；注意按伤害形状去重的 ability 可能丢失源身份，不能随意给共享 ability 打标签导致其他来源一起改变。
4. **生成底座足够复用。** 现有房间、洞窟、碎石/树木地形、破坏区、普通楼梯及河流 alternative 已有表达。采用下面的代表层适配，不为本批重建完整原版随机地图生成器。

## 4. 分批实施

### A1：支持无最终守卫的地牢

- 将正式地牢与来源计划的最终守卫声明改为可选，更新实际校验及守卫排除消费者。有守卫的既有地牢仍必须满足原有末层绑定；没有守卫的地牢不允许偷偷声明末层守卫或守卫奖励。
- `finalFloor` 继续表达层链终点，50 层没有向下楼梯。终点不自动写入 `conquered`，入口守卫击杀也不触发最终奖励。复用已有入口守卫状态、深度记录、返回与召回。
- 覆盖一座最小无守卫楼层链，以及既有有守卫地牢的引用错误拒绝和正常征服回归；不为 26 个旧地牢复制新测试。

**完成标准：**合法无首领地牢可生成、保存和返回，既有首领与奖励校验没有被放松。本批底座完成前不把 16/17 写成两个假首领地牢。

### A2：反魔规则与能力分类

- 接入地牢禁魔字段和源能力分类；来源审计列出受影响的正式候选，定向更新，避免重导其他内容。普通怪物分配、后续补怪及召唤分类共用已有候选路径，在真实调用边界保留召唤语境。
- 玩家执行与可用性投影消费同一规则：书本法术和已支持的魔法职业技能被拒绝，已支持的非魔法技艺按源例外保留。种族/变异、卷轴、装置与装备激活选最小对照验证，不把资源类型或 ability source 当作唯一魔法判断。
- 怪物对玩家按正常频率/候选抽取后拒绝魔法，保留普通行动；怪物互相施法按源 AI/失败语义处理，明确实际支持的 STUPID、友军与变形消费者。拒绝不能扣掉本不该消耗的玩家资源，也不能重新抽取直到获得天生能力。
- 天生/攻击分类只补当前缺口。若复用分类会改变既有魔法减伤或闪避行为，单独解释影响并验证，不顺带把旧消费者全部改写。

**完成标准：**真实地牢上下文中，禁魔执行、投影与怪物分配一致；吐息/火箭等应保留行为正常，纯魔法候选被拒绝，离开地牢后恢复。存在不明源分类时先核实，不以默认标签掩盖。

### A3：反近战规则与生态

- 接入地牢禁近战字段；覆盖 `resolve_player_melee`、怪物近战、玩家召唤物/宠物近战和已存在的特殊近战入口，修正在实际调度层应当拒绝的尝试。普通移动、射击、投掷、施法及远程伤害照常工作。
- 检查本树 `monster_ai.rs` 的凝视能力会复用 `resolve_monster_melee_target` 的现状，按源实际凝视/攻击语义判定，不能仅凭函数名一刀切。源主动近战拒绝与法术不可用的回合处理不同；核定能量/回合、命中 RNG、消耗和反击，禁止把所有拒绝强制改成免费动作。
- 自然生态使用“有攻击法术”筛选；只有治疗/加速/召唤的怪物不因此算攻击施法怪物。玩家允许宠物召唤的源例外须在当前已有召唤调用中保留，不能借地牢过滤悄悄提升宠物候选。

**完成标准：**玩家、敌人、友军近战均无伤害或附带命中效果，远程行为正常；攻击法术筛选与天生分类分别生效，不能用一份“会施法”白名单替代两座洞穴的规则。

### A4：接入替代组、22 层和真实入口

拟用稳定 ID：`demo.dungeon.anti-magic-cave` / `demo.dungeon.anti-melee-cave`；楼层为 `demo.floor.anti-magic-cave-depth-40` 至 `-50` 与对应 anti-melee ID，入口和生态表沿用相同命名模式。实施前再次查重。

1. 在 `legacy-wilderness-selection.json` 登记两个位置和完整来源计划，16 指向 17。来源同步审计写临时 world 副本，正式 world 仅追加本批内容，保留其他地点。
2. 复用现有种子化替代选择，只显示所选地点自己的原版坐标、入口与地表守卫。源两座坐标不同，不把替代入口都搬到 (84,6)。另一座不能通过地图、旧目标或召回进入。保存恢复不重选。
3. 源替代函数对旧 `seed_dungeon=0` 和 melee/no-melee challenge 有特殊分支。本项目开发从新档开始，沿用当前 seed 选择，不增加旧档兼容或未支持的挑战模式；明确该适配，测试两个正常种子，不把源旧档特殊值当作本项目新档默认双开。
4. 入口守卫复用 `demo.actor.juggernaut-of-khorne` / `demo.actor.bazooker`，使用现有实际局部入口定位，安排在合法相邻格；生成、死亡、重访、读档和地表返回保留实例状态。无需新增 actor 或物品定义。
5. 各 11 层使用下述生成方案，40 层可从真实地表入口进入，50 层是无首领终点。生态走已有全局分配，`specialDiv=0` 不等于空怪物池；限制字段按实际候选能力过滤，继续遵守深度、稀有度、唯一怪、归属与其他首领排除。

**生成适配方案：**

- 基础采用 66×22、普通房间/通道、地板与花岗岩、岩浆/石英矿脉；不套用拉莱耶混合水地板预算。普通楼梯沿用现有数量表达，根层保留返回入口，50 层只有向上通路。
- 默认普通布局；拟在 42 层表达洞窟、45 层表达 ARENA 开阔布局、46 层表达碎石类湖区、48 层表达树木类湖区、49 层表达破坏区。其余层保留普通房间。具体面积沿用已验证预算并按本批生成抽查调整，不预先堆满所有地形。
- 普通/洞窟/开阔/破坏层按现有 `river.chanceOneIn=7`，water 为主、lava alternative 的分子为 `depth+1`、分母为 256；46/48 层不配置河流。当前表达省去源 `randint1(depth)>5` 的第二次门控，实际河流略多，此差异须在交付记录中保留，不宣称 RNG 或频率逐次复刻。
- 40–50 层不安排水湖、熔岩湖。水与熔岩按既有通行、视线、投射和承物规则执行，不能用 walkable 代替所有判断；普通门不会因 `GLASS_ROOM` 变成玻璃门。
- 代表层是当前生成器的明确适配，并非原版每层概率抽取 ARENA/洞窟/湖泊/破坏区。无需新增通用布局变体框架；若抽查发现真实生成缺陷，只修本批实际使用的既有职责。

**完成标准：**两个种子分别选中两座洞穴，从各自真实局部入口到 50 层并返回原位置；入口守卫不重复，无最终首领/奖励，规则只在所属地牢生效。A1–A3 尚未到位时不开放入口。
