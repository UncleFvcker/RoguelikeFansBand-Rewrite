## 目标与边界

把当前“从改编表按层级过滤并加权选一项”升级为源端的类别选择、底材分配、完整物化、必要重试，
让 Acquirement 使用同一条路径，完成已开放构筑的实际偏好与结果检查。

区分两个验收指标：**分配规则完整性**和**源内容覆盖率**。前者核对当前真实入口的全部分支；
后者逐项记录 source kind 到正式 stable ID 的映射、未导入条目和原因。
不能通过悄悄删除候选或给缺失类别补默认装备，让局部内容池看起来等价于完整原版内容池。
当前已可用内容缺少分配数据属于本任务；底材依赖尚未实现的内容能力时列明依赖，不能提前标记全源覆盖。

继续复用 E8.1–E8.6 的有符号 power、固定神器、Ego、随机神器、首饰价值重试和实例保存。
指定 kind/affix 的出生、地图和固定任务奖励保持各自显式入口；Craft 不重新抽底材。
程序式 QUEST 奖励、神器卷轴和未开放身份不新增恒假开关，待真实入口具备后接入。

### B5：生成重试与 Acquirement 事务

   每次成功才减少目标数量；允许耗尽后只得到部分物品或零物品，不补默认奖励。
4. 对“被拒绝候选的固定神器登记、随机神器名称登记、实例 ID、知识和 found”列出状态副作用表，

验收：首轮成功、先失败后成功、内部耗尽、外层耗尽、部分成功、两层嵌套、成品不合用、

## 版本与完成标准

- B0 改内容时更新 pack 与 lock；类型变化才生成 Schema，不手改生成物。
- B1 的持久计数/去重状态预计影响 save、hash 及相关 DTO；实施时按真实结构决定版本，不提前预定版本号。
- 临时 hook、候选列表、类别权重不进存档；前端不复制分配规则或需要书本的判断。
- 每批提交记录实际检查及尚缺内容。分布统计只辅助检查偏差，不能替代谓词、边界和 RNG 顺序验收。
- B6 后只有已开放构筑的完整调用链、计数、偏好、重试和消费者均通过，才关闭“当前可玩范围底材分配”缺口。
  未开放身份或源内容覆盖仍有缺口时，全范围 `runtimeParityComplete` 继续为 `false`。
