### 2.1 竖井不能照搬现有金字塔土丘配置

`src/floors.c` 1021–1027：普通竖井基础跨两层；阿斯加德／金字塔土丘向下出发深度 **<78** 时再加两层，向上出发深度 **<82** 时再减两层。正常路线为：

`地表 → 64 → 68 → 72 → 76 → 80 → 82 → 84 → 86 → 88`

这是 25 个定义中的 **9 个常规访问深度**，不能写成“走遍 25 层”，也不能删除其余深度。源 `bldg.c` 1911–1917 的可达层判断同样采用 80 以下相对起始深度模 4、其后模 2。地表进入仍落在根层 64，向上越过最浅层则回地表。

AS4 前金字塔土丘正式 connections 全部按两层配对，[内容校验](../crates/rfb-content/src/validation/worlds.rs)也只允许 Shaft 的深度差为 2，并要求静态目标成对互指。AS4 已按下述记录补齐源跨度与实际保存回程，仍保留同地牢、方向、目标存在和保存完整性约束；统一验证尚未运行。

源 `floors.c` 先寻找已有保存连接；实际回程不能每次仅按深度公式重算。重点验证 76↔80、80↔82、从非通常路径抵达 77／78／79／81 等层后的往返，以及最浅／最深边界。金字塔土丘使用同一已确认的源条件，AS4 同步纠正其受影响连接及直接相关回归、当前交付说明，不扩展到该地牢的其他规则。

### 2.3 超出物品静态旗标的行为

- **雷神之锤与手套：** `py_throw.c` 将雷神之锤设为回旋投掷并给回返判定 +20，不是必中回手；`obj_kind.c` 排除其双手持握；`xtra1.c` 在同时装备 ART_MAGNI 时给该武器额外 100 百分之一攻击并解除 heavy_wield。保留源的回返／接住失败落点和物品唯一实例，联动不误加给另一把武器。
- **乌勒尔戒指：** `equip.c` 使其命中／伤害只进入射击，不进入近战；`object3.c` 有相应戒指伤害估值分支。复用已有弓术 Ego／射击加成消费者，不能把 +21／+36 作为全局近战收益。
- **号角：** `defines.h` 明确 tval 4 是 TV_WHISTLE；`equip.c:12` 将其放在护身符颈槽。`cmd6.c::_activate_p` 对当前开放身份只允许装备中的此类物品激活，不能因 prompt 列举背包／地面就声称允许背包激活。源 `devices.c::EFFECT_RETURN_PETS` 召回现有宠物，跳过当前坐骑，按源宠物排序逐个被动传送。复用主人、占位、传送和宠物身份；不生成替代宠物，不引入吟游诗人／音乐系统。kind 708 冷却为 150，神器 370 为 20 源回合，以神器覆盖为准。
- **维达靴：** `EFFECT_STUNNING_KICK` 使用源 power×2 的相邻目标 GF_STUN；不是普通近战伤害。保留 NO_MELEE、目标取消、抗性和实际状态判定，沿用现有状态／投射消费者。
- **钓鱼竿：** `EFFECT_FISHING` 选择相邻无怪水格后进入 ACTION_FISH。`dungeon.c` 持续消耗行动，每次 1/1000 判定有事发生，再用 AQUATIC、非 UNIQUE、源字形 `Jjlw` 筛选并作 1/2 成功抽选，实际生成怪物或提示鱼饵丢失，随后停止；玩家输入可中断。进入既有持续行动和生态路径，不实现一个界面倒计时或一次性赠鱼替代。目标取消、错误地形、阻挡各自的耗能／冷却按源分支核对。

### 2.4 死亡事件与当地药水

**奥丁→维达。** `xtra2.c` 1320–1348：奥丁死亡后，维达仍可用时在死亡位置附近半径 20 内最多尝试 100 次，找到合法位置再实际召来；奥丁为宠物时保留宠物归属。此分支不以 `drop_chosen_item` 为门槛，不得套入“宠物不掉神器”的过滤。使用已有唯一额度／跨楼层保存规则，维达已存在、已死或没有落点时不复制／复生；不借此把维达改成第二个地牢最终守卫。

使用 Tauri standalone 及专用 WebDriver，覆盖地表彩虹桥／入口、四层与两层竖井实际跳转、代表层正常镜头滚动、两名守卫与奥丁后继、奖励详情／使用、返回和原生保存加载。概率分支的穷举归核心专项，不在 UI 反复刷概率。截图用于检查地形、门格、物品和菜单，正常游戏允许地图超出视窗。

长距离路线沿用 Z6 的生产 Rust 命令分段与门口原生按键；不每格等待一次 WebDriver。选定存档加载只校验本次槽位，不把全列表刷新混入会话创建或加载。若清场仅为路线准备，按实际活动实体识别并记录；不得清掉正在验收的维达后继后仍宣称通过该战斗。

本阶段完成标准：核心用例、桌面场景、准备接口限制和预期断言就绪，未运行状态明确。AS7 工作结束后的统一验收才产生桌面报告／截图、关键保存状态和无前端异常证据，并验证普通可玩 EXE 拒绝专用准备接口。

### AS7：来源、状态与交付收口

先完成现有来源记录、NOTICE、[状态页](../docs/status.md)及本计划的实现／来源收口，列清入口、层链、奖励消费者、准备的检查和保留适配；需要编译才能生成的 Schema／绑定／lock 留在统一验证环节，不能提前标为已同步。**AS7 上述工作完成后**，统一生成必要产物、编译并执行 AS2–AS6 的相关测试、active 契约、Tauri standalone 构建和桌面验收。修复实际失败后只复跑受影响范围；最终回填实际结果，确认全部完成标准后再报告整项验收完成。

交付源码提交、普通 Tauri standalone 产物及可复现的核心／桌面命令；不以神器数量、编译成功或测试准备后的胜利替代行为说明。

## 4. 验证与工作方式

- AS1 只核对文档、来源事实与本地链接，不生成正式内容、不开放入口。本计划按 AS1 → AS2 → AS3 → AS4 → AS5 → AS6 → AS7 推进；按用户要求中途不编译、不运行测试，AS7 实现／来源收口结束后统一验证。阶段不是额外审批点。
- 内容变化更新正式包与 lock；类型变化才生成对应 Schema／绑定。没有实际格式变化不预升协议、save 或 State Hash Schema；不维护旧开发存档兼容。
- 测试围绕真实调用者：神系／召唤／唯一额度、神器生成／装备／投掷／射击、死亡掉落／宝箱、持续行动、连接与保存。复用既有覆盖，只补缺失的行为，不按每层或每神器复制静态矩阵。
- 新增六件可普通生成神器、底材或地牢初始化可能影响全局生成和哈希，在最后统一验证时按[验证指南](../docs/testing.md)运行相应 active 契约并解释行为变化。公共连接改动覆盖既有一层楼梯、两层竖井和金字塔土丘；不把阿斯加德专项通过当作所有调用者都安全。
- 按[内容开发](../docs/content-development.md)和[并行协作](../docs/parallel-development.md)维护稳定 ID 与来源归属；只有其他方向实际正在修改同一物品／机制才协调，不提前要求通用底座。
- 照常运行 Cargo／Tauri 命令，沿用已配置的共享 main 编译缓存与各工作树 `rustc-workspace-wrapper` 隔离。EXE、前端与 E2E 产物留在自身工作树；缓存锁等待属于正常并行行为，不擅自清理缓存或别树输出。

主要代码入口为 `game/world/generation.rs`、`game/floor.rs`、`game/death.rs`、`game/loot.rs`、`game/loot/allocation.rs`、`game/item_use.rs`、现有物品效果／属性／投掷及持续行动模块。新增必要测试可集中于 `game/tests/asgard.rs`，已有消费者的回归留在原测试职责中，不向 `game/mod.rs` 堆规则。
