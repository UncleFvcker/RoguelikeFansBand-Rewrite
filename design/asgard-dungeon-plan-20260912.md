## 1. 目标与完成边界

接入阿斯加德的真实地表入口、北欧神系资格、64–88 层完整深度定义、洞穴／洞窟与竖井、入口／末层守卫，以及当地物品、神祇死亡分支和专属神器的实际消费者。最终用核心流程及聚焦 Windows 桌面流程验证入口、战斗结算、奖励使用、返回和保存继续。

沿用现有神系、地牢、物品和怪物机制。新增内容进入既有职责模块，不建立另一套地牢生成器、神器系统或通用事件脚本框架。自然练级通关、所有北欧怪物 AI 的全面重审、其他地牢、职业／种族及 Android 不自动包含在本计划中。

十二件神器、钓鱼和弗丽嘉宝箱均属于本计划的实质范围；不能只定义物品或掉落后，把缺失的使用行为藏进“完整导入”结论。若后续明确裁剪其中某项，必须同步调整完成声明。

### 2.1 竖井不能照搬现有金字塔土丘配置

`src/floors.c` 1021–1027：普通竖井基础跨两层；阿斯加德／金字塔土丘向下出发深度 **<78** 时再加两层，向上出发深度 **<82** 时再减两层。正常路线为：

`地表 → 64 → 68 → 72 → 76 → 80 → 82 → 84 → 86 → 88`

这是 25 个定义中的 **9 个常规访问深度**，不能写成“走遍 25 层”，也不能删除其余深度。源 `bldg.c` 1911–1917 的可达层判断同样采用 80 以下相对起始深度模 4、其后模 2。地表进入仍落在根层 64，向上越过最浅层则回地表。

当前金字塔土丘正式 connections 全部按两层配对；[内容校验](../crates/rfb-content/src/validation/worlds.rs)也只允许 Shaft 的深度差为 2，并要求静态目标成对互指。这是已观察到的表达缺口，不能把 JSON 改成四层后粗暴放宽所有连接校验。AS4 在现有连接模型内补齐这一源规则，保留同地牢、方向、目标存在、回程和保存完整性约束。

源 `floors.c` 先寻找已有保存连接；实际回程不能每次仅按深度公式重算。重点验证 76↔80、80↔82、从非通常路径抵达 77／78／79／81 等层后的往返，以及最浅／最深边界。金字塔土丘使用同一已确认的源条件，AS4 同步纠正其受影响连接及直接相关回归、当前交付说明，不扩展到该地牢的其他规则。

### 2.3 超出物品静态旗标的行为

- **雷神之锤与手套：** `py_throw.c` 将雷神之锤设为回旋投掷并给回返判定 +20，不是必中回手；`obj_kind.c` 排除其双手持握；`xtra1.c` 在同时装备 ART_MAGNI 时给该武器额外 100 百分之一攻击并解除 heavy_wield。保留源的回返／接住失败落点和物品唯一实例，联动不误加给另一把武器。
- **乌勒尔戒指：** `equip.c` 使其命中／伤害只进入射击，不进入近战；`object3.c` 有相应戒指伤害估值分支。复用已有弓术 Ego／射击加成消费者，不能把 +21／+36 作为全局近战收益。
- **号角：** `devices.c::EFFECT_RETURN_PETS` 召回现有宠物，跳过当前坐骑，逐个使用宠物传送规则。复用主人、占位、传送和宠物顺序；不生成替代宠物。使用位置／装备槽位依源调用核对，不为了套用现有接口随意改成武器。
- **维达靴：** `EFFECT_STUNNING_KICK` 使用源 power×2 的相邻目标 GF_STUN；不是普通近战伤害。保留 NO_MELEE、目标取消、抗性和实际状态判定，沿用现有状态／投射消费者。
- **钓鱼竿：** `EFFECT_FISHING` 选择相邻无怪水格后进入 ACTION_FISH。`dungeon.c` 持续消耗行动，每次 1/1000 判定有事发生，再用 AQUATIC、非 UNIQUE、源字形 `Jjlw` 筛选并作 1/2 成功抽选，实际生成怪物或提示鱼饵丢失，随后停止；玩家输入可中断。进入既有持续行动和生态路径，不实现一个界面倒计时或一次性赠鱼替代。目标取消、错误地形、阻挡各自的耗能／冷却按源分支核对。

### 2.4 死亡事件与当地药水

**奥丁→维达。** `xtra2.c` 1320–1348：奥丁死亡后，维达仍可用时在死亡位置附近半径 20 内最多尝试 100 次，找到合法位置再实际召来；奥丁为宠物时保留宠物归属。此分支不以 `drop_chosen_item` 为门槛，不得套入“宠物不掉神器”的过滤。使用已有唯一额度／跨楼层保存规则，维达已存在、已死或没有落点时不复制／复生；不借此把维达改成第二个地牢最终守卫。

**弗丽嘉宝箱。** `xtra2.c` 1403–1419：额外创建 7:5 / kind 641 大木箱，使用当前 object_level 和 `AM_NO_FIXED_ART`，之后仍有独立神器抽选与普通掉落；该 case 没有 `drop_chosen_item` 判断。当前包及物品交互没有该宝箱消费者，须实现源箱锁／陷阱／打开／内容生成及空箱状态的必要链条，保存后不能重复开箱取物。只接当前这类宝箱及其实际需要的共同操作，其他宝箱种类不批量导入。AS1 进一步核对 `object2.c` 和 `cmd2.c` 的生成、开箱、陷阱、无嵌套箱及奖励来源细节，确定最小持久字段。

**诗歌蜜酒。** 已有 `demo.item.muse-tonic`、`demo.effect.poetic-inspiration`、`resolve_item_poetic_inspiration` 和公共分配入口的 `(75,14) → legacy dungeon 39` 限制；不要重复实现。源 kind 466 为等级 80、`A:75/6`、重量 4、价值 10000、营养 100、固定亮橙色外观。`devices.c` 的实际使用时长是经药水加成处理的 `100+1d100` 源回合，继续饮用累加，`set_tim_poet` 上限 10000 源回合；WIS／CHR 各 +5。检查当前能力式时长调用是否正确换算 tick、应用药水加成和上限，验证到期／驱散／保存及真实属性消费者。源 info 显示采用另一组数值，不能据此覆盖实际 cast 分支。当前中文“诗歌蜜酒药水”需按源表校正为“诗歌蜜酒”，保持稳定 ID。

当前正式 actor 中有 21 个带 NORSE／NORSE2 的成员，身份及既有召唤优先复用。AS1 对这批实际候选的源 index／符号再查 `xtra2.c`、`quest.c` 具名与数字分支，记录遗漏；不把“已有 actor JSON”当作专属死亡行为已实现。源内部竞技场／战斗、克隆及曾为宠物等未表达状态须逐项注明适配边界，不能把独立的竞技场地牢等同于源 `inside_arena`。

## 3. 分批实施

### AS1：来源与依赖收口

完成上述来源表、21 个成员的特殊分支核对、十二神器的 source index／底材／效果映射，以及宝箱、钓鱼、号角和竖井边界的最小调用链。复查已合入物品，更新现有来源／覆盖清单中的本批条目；不新建另一份全仓审计账本。

完成标准：每个必要行为有现有消费者或明确后续批次，中文未解决项显式列出，正式地牢入口仍关闭。来源变化记录本批实际 master 提交，不隐式沿用历史固定契约的 ref。

### AS2：神器定义与实际使用

导入十二神器及缺少的钓鱼竿／大号角底材，接通普通神器资格、被动、激活、冷却、雷神之锤回返与手套联动、乌勒尔射击和估值。钓鱼在本批完成持续行动／生态／取消／保存；英勇、加速、闪电球优先复用现有效果。按号角、践踏、钓鱼、装备／投掷四条调用链分小提交，不预造可配置神器联动引擎。

完成标准：通过生产物品工厂生成并实际装备／激活／投掷／钓鱼，属性和事件来自 Rust；已生成神器保存后排重，命伤归属和冷却拒绝正确。没有消费者的物品不能记为完成。检查实际影响的物品生成、投掷／射击及相关已有神器测试。

### AS3：神祇死亡、选择掉落与大木箱

在 [loot.rs](../crates/rfb-core/src/game/loot.rs) 的现有 `specialArtifactDrop` 中做支持芙蕾雅先选分支的最小扩展，单神器调用保持现有语义。接十二件死亡绑定；在 [death.rs](../crates/rfb-core/src/game/death.rs) 接奥丁召来维达，沿用实际死亡、召唤、唯一登记和事务顺序。补大木箱的生成／开箱与弗丽嘉额外掉落。

完成标准：普通死亡掉落、神祇神器、弗丽嘉宝箱及地牢征服奖励相互独立；芙蕾雅抽选和 Bad Luck 顺序可复演；奥丁死亡只结算一次，维达现存／已死／无空格分支正确。宝箱打开、陷阱和内容生成有真实行为证据，保存恢复不重复发物。持久字段或内容类型真实变化时才升级／生成相应格式。

### AS4：地图与源竖井连接

复用 [world/generation.rs](../crates/rfb-core/src/game/world/generation.rs) 的 CAVE 房间、源深度触发 CAVERN、混合墙、矿脉、普通门和地面分配。先用 64／76／80／88 代表深度确认地图可通行与预算；初始采用已有 96×33 表示，房间／怪物预算按实际面积核验并记录为项目适配，不冒称源最小怪物数 50 或原图尺寸。

在既有 FloorConnection 及校验／保存路径中支持本地牢的四层／两层竖井和真实回程；同步纠正金字塔土丘的同源连接。保留普通两层竖井及一层楼梯的原约束。CAVERN 与石英矿脉必须有实际生成证据；不添加源未声明的水河、无门或地牢全图必须装入视窗等条件。

完成标准：25 个深度配置完整；正常九深度路线、阈值两侧、非通常路径和最浅／最深层的进出／保存继续成立。非法跨地牢、错误方向、悬空目标或不合法跨度仍被拒绝。旧两层竖井和金字塔土丘直接相关测试通过。

### AS5：神系生态、正式入口与当地物品

注册世界 (94,11)、`pantheon: 3`、`legacyIndex: 39`、完整层链和源守卫；入口最后开放。复用 [world/mod.rs](../crates/rfb-core/src/game/world/mod.rs) 默认四选二、主次神系过滤、[wilderness.rs](../crates/rfb-core/src/game/wilderness.rs) 入口／守卫抑制和现有北欧召唤。保留 MONSTER_DIV_2 的源偏好，复用分配权重入口，不将数字 2 当怪物数量。

接默认征服卷轴，检验地牢内提前召唤奥丁并击杀也能征服、域外死亡不误征服、已死唯一守卫不复生、重复进入不重复发奖。入口海姆达尔的唯一身份沿用全局额度，域外先死时的入口行为按现有来源规则验证。激活诗歌蜜酒的现成所在地分配消费者，校正上述使用／显示偏差，并覆盖地面物、怪物掉落、相关获取方式及域外不分配。

完成标准：从新角色进入真实地表，北欧激活与未激活两分支均正确；正常路线可以完成守卫、拾取并使用源奖励、回地表、召回及保存继续。对全局普通神器生成、地牢初始化状态和 RNG 的实际影响运行 active 契约，先解释差异再决定刷新，不因纯 contentHash 变化刷新状态哈希。

### AS6：聚焦核心与桌面验收

复用 AS2–AS5 已通过的有效专项，补正式入口到征服再返回的完整核心流程。用近战角色完成路线／战斗；测试等级、装备、HP、RNG、位置或清场准备逐项记录。源守卫实际属性及攻击命令不被“直接标记征服”替代，测试准备和自然战斗证据分开。

使用 Tauri standalone 及专用 WebDriver，覆盖地表彩虹桥／入口、四层与两层竖井实际跳转、代表层正常镜头滚动、两名守卫与奥丁后继、奖励详情／使用、返回和原生保存加载。概率分支的穷举归核心专项，不在 UI 反复刷概率。截图用于检查地形、门格、物品和菜单，正常游戏允许地图超出视窗。

长距离路线沿用 Z6 的生产 Rust 命令分段与门口原生按键；不每格等待一次 WebDriver。选定存档加载只校验本次槽位，不把全列表刷新混入会话创建或加载。若清场仅为路线准备，按实际活动实体识别并记录；不得清掉正在验收的维达后继后仍宣称通过该战斗。

完成标准：桌面报告／截图、关键保存状态和无前端异常证据齐全，普通可玩 EXE 拒绝专用准备接口。实际检查范围明确；没有新失败或修改，不为了最后收口再跑一遍同范围全量检查。

## 4. 验证与工作方式

- 纯规划阶段只检查文档、来源事实与本地链接，不编译、不生成正式内容、不开放入口。本计划按 AS1 → AS2 → AS3 → AS4 → AS5 → AS6 → AS7 推进；阶段不是额外审批点。
- 内容变化更新正式包与 lock；类型变化才生成对应 Schema／绑定。没有实际格式变化不预升协议、save 或 State Hash Schema；不维护旧开发存档兼容。
- 测试围绕真实调用者：神系／召唤／唯一额度、神器生成／装备／投掷／射击、死亡掉落／宝箱、持续行动、连接与保存。复用既有覆盖，只补缺失的行为，不按每层或每神器复制静态矩阵。
- 新增三件可普通生成神器、底材或地牢初始化可能影响全局生成和哈希，按[验证指南](../docs/testing.md)运行相应 active 契约并解释行为变化。公共连接改动覆盖既有一层楼梯、两层竖井和金字塔土丘；不把阿斯加德专项通过当作所有调用者都安全。
- 按[内容开发](../docs/content-development.md)和[并行协作](../docs/parallel-development.md)维护稳定 ID 与来源归属；只有其他方向实际正在修改同一物品／机制才协调，不提前要求通用底座。
- 照常运行 Cargo／Tauri 命令，沿用已配置的共享 main 编译缓存与各工作树 `rustc-workspace-wrapper` 隔离。EXE、前端与 E2E 产物留在自身工作树；缓存锁等待属于正常并行行为，不擅自清理缓存或别树输出。

主要代码入口为 `game/world/generation.rs`、`game/floor.rs`、`game/death.rs`、`game/loot.rs`、`game/loot/allocation.rs`、`game/item_use.rs`、现有物品效果／属性／投掷及持续行动模块。新增必要测试可集中于 `game/tests/asgard.rs`，已有消费者的回归留在原测试职责中，不向 `game/mod.rs` 堆规则。
