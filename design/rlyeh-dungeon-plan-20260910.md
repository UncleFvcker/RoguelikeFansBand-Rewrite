## 3. 实施分批

### R1：校正本批实际使用的水上投射

**已完成（内容包 1.401.4）**：深水新增 `allowsProjectilePassage=true`，StarBall 选点复用 `projectile_can_cross`，保留距玩家不超过 4 且排除自身的约束。1000 次尝试耗尽时跳过该球，避免使用最后一次无效坐标；这项边界处理比源循环耗尽后继续投射更严格。没有新增能力字段、几何系统或改变水域通行、负重伤害与物品落地算法。保留 `projectable` 标签供现有隔空取物使用。

67 项核心相关测试通过：实际玩家/怪物伤害投射跨浅水和深水；StarBall 全深水邻域正常选点、封闭邻域不向墙或自己发球；玻璃墙/永久墙阻挡、黑坑通行/投射和落地保存回归通过。复用投射、怪物 AI/移动及隔空取物检查。26 条 active 契约无需刷新即通过，Clippy、格式与内容锁验证通过；未改 Schema/协议/存档/State Hash Schema，未制作 standalone。

实施前已观察到的差异（规划基线 `32f828dfc`）：

- 源 `f_info.txt` 的 DEEP_WATER 83、SHALLOW_WATER 84 均有 PROJECT。
- 当前 `surface-water-deep.json` 为 `walkable=false`，仅在 tags 声明 `projectable`；`projectile_can_cross` 读取 `walkable || allows_projectile_passage`，尚未消费该标签。
- `item_use.rs` 的 StarBall 随机目标筛选仍调用 `is_walkable`；隔空取物另有已支持深水的 `fetch_projectable`。现状会使水上投射的不同消费者不一致。

沿用 O1 已加入的投射能力字段与现有几何函数，修正深水声明及 StarBall 的实际选点调用。核对本批用到的浅水、黑坑、玻璃墙和永久墙；仅改投射语义，保留现有水域通行、负重伤害和物品落地规则。不机械替换所有 `is_walkable`，不新增地牢专用投射系统。

**完成标准：**玩家及怪物投射能跨过源允许投射的水面；StarBall 能选择合法深水目标，仍排除自身和阻挡格；墙仍阻挡，黑坑既有行为不回退，掉落物不会落在禁止承物的格子造成非法存档。复用已有投射/StarBall/黑坑测试，只补本次缺失的水域边界。

**完成标准：**奖励物品可真实生成、装备、激活和读档；自然生成与守卫奖励共享唯一性状态。仅有 JSON 定义但激活不可用时，不进入最终地牢开放步骤。

实际来源仍为 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`：`a_info.txt:129`、`init1.c` 的固定神器四元素保护、`devices.c EFFECT_STAR_BALL`。基础身份为万色龙鳞甲 `38/6`，等级 90、稀有度 1/9、重量 500、基础价值 400000、防御 65、近战命中 -4；光照、看破隐形、自由行动、激怒、雷电免疫和六种抗性按源属性接入。激活难度 30，独立效果程序复用现有 StarBall；装置估值 7500。中文神器名继续 unresolved，显示源名 `'Razorback'`。

### R3：接入完整地点、17 层与征服闭环

**已完成（内容包 1.401.6）**：使用 `demo.dungeon.rlyeh`、`demo.floor.rlyeh-depth-80` 至 `-96`、`demo.terrain.rlyeh-entrance`、`demo.encounter-table.rlyeh`，引用 R2 的唯一奖励定义。

1. 在 `legacy-wilderness-selection.json` 登记原版索引 13、位置、完整 dungeonPlan、守卫和奖励；来源审计输出到临时副本，避免重写其他地点。
2. `worlds/middle-earth.json` 添加正式地点、楼层链、根层入口与最终守卫配置。完整闭环和 R1/R2 到位后再开放入口，不交付能进去却没有结局的中间态。
3. 复用城堡的房间/普通楼梯能力与努曼诺尔/亚特兰蒂斯的河湖分布能力，按拉莱耶来源组合。源未声明 ALL_SHAFTS、NO_DOORS、BIG 或 SUBSTITUTE，不从参考地牢顺手复制。
4. 使用全局怪物分配的 `preferredTags=[demon, eldritch-horror]`、`specialDiv=16`，保留深度、稀有度、唯一怪、地牢归属及守卫排除。现有恐怖触发与免疫规则继续运行，不另造“克苏鲁理智系统”。
5. 入口守卫位置使用现有实际荒野入口定位逻辑，不抄其他地牢在旧出生图上的静态坐标。末层固定守卫死亡后走既有征服、奖励、返回及召回路径；水面死亡奖励落在合法承物格。

**完成标准：**从 (40,3) 的真实局部入口进入 80 层，可下行至 96 层并返回原出发位置；入口/最终守卫不重复，征服和奖励仅结算一次，读档/重访不恢复已结算奖励。现有城镇、Outpost 与其他地牢状态不被覆盖。

实际来源仍为 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`。来源审计在临时 world 副本通过 22 个地点；正式 world 只追加拉莱耶，原有地点和楼层数据逐项不变。入口守卫以局部视图中心偏移 `(0,-1)` 定位，实际在入口北侧一格；不使用其他地点的旧静态坐标。普通分配排除最终守卫，恶魔/恐怖标签按既有 `specialDiv=16` 权重缩放，仍允许非偏好怪物；没有新增等级 45 门槛或恐怖规则。

生成适配：使用 66×22 地图、普通房间与楼梯，不生成矿脉。源 50/30/20 混合以房间面积上限 800、房间水格预算 400 和浅/深水权重 3:2 表达；走廊、预留格、河湖会改变最终比例。河流沿用 1/7 概率及面积预算 160；85 层采用既有 ARENA 开阔布局，90 层采用湖泊布局（面积预算 360，其中深水 120）。这些代表层沿用当前地牢生成适配，并非原版每层随机挑选 ARENA/湖泊的逐次复刻。

开放水面击杀测试复现了神器在普通落点半径外消失的问题。共享掉落函数现对神器继续寻找全图承物格，并更新实际落点投影；死亡、投掷、弹药和背包掉落均传入真实神器身份，普通物品仍受原有近邻限制。`object2.c drop_near` 的随机游走/全图抽签在这里适配为最近合法格，不消耗额外 RNG。重复神器奖励仍用既有守卫替代流程生成高品质万色龙鳞甲，并在奖励生成处保留替代神器的水面落地保护；普通怪物掉落不因此获得保护。此适配不宣称等价于原版 `create_replacement_art`。

R3 验证：223 项核心回归通过，覆盖完整 17 层往返、水中守卫死亡、固定/替代奖励落地、奖励去重、保存恢复、召回与 Outpost/其他地牢保留，也覆盖普通物品与混合背包批量掉落的原有限制。3 项内容测试、2 项本地化测试、core Clippy、来源审计与内容锁检查通过。26 条 active 契约只更新新增地牢状态引起的哈希，事件/错误类型/坐标及其他断言不变，刷新后全部通过；没有协议、存档格式或 State Hash Schema 变更。

### R4：聚焦验收与交付

- **来源与内容：**索引/坐标/深度/层链/生态/奖励绑定、合法入口和落点、source/lock；实际类型变更才生成 Schema 或协议绑定。
- **生成：**先抽查根层、中层、末层和代表性河湖种子，检查普通上下楼梯、守卫/玩家落点及预期水域特征；失败揭示更广影响时再扩展。无需为 17 层各复制一套测试。
- **行为：**复用 `game::tests::world` 的水域地牢、守卫及返回测试，`monster_ecology` 的分配/恐怖测试，以及物品激活、投射和保存测试；新增场景使用 `rlyeh_` 前缀。
- **奖励：**未生成时取得神器 129、已生成时走既有替代奖励、重访不重复结算；水面死亡、装备激活及保存恢复各选最小有效场景。
- **契约：**先观察实际影响。新增地点可能改变初始化的 dungeon state、守卫排除或公共物品分配；若影响公共状态/RNG，执行 active `verify-all` 并解释差异后刷新。不能仅因 contentHash 变化刷新或升级 State Hash Schema。
- **交付：**更新当时正式包版本/lock 和 `docs/status.md`，记录来源提交、实现/开放/验收边界；本计划不预留版本号。不默认执行全量前端、Android、桌面 E2E 或路径可达性专项；若要求可玩 EXE，再单独做 Tauri standalone。

## 4. 主要改动位置与边界

内容进入现有 `packs/rfb-demo-original/{worlds,terrain,encounterTables,items}/`、来源 selection 和两套 locale；必要的规则改动放在 `game/projectile_geometry.rs`、`game/item_use.rs` 及既有 world/loot 职责内。参考 [内容开发](../docs/content-development.md)、[验证与契约](../docs/testing.md)和[并行协作](../docs/parallel-development.md)。
