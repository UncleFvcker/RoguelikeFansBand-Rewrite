# Phase 19: Legacy Item Integration

The fixed-source importer remains the authority for original RFB item identity,
weight, base value, equipment slot, combat dice, and defense. Formal gameplay
content is selected explicitly rather than copying the complete generated pack.

## Reproducible Selection

`packs/rfb-demo-original/legacy-item-selection.json` pins every selected item by
both fixed-source index and normalized id. Regenerate the selected item files
with:

```powershell
$env:RFB_LEGACY_SOURCE='D:/codex/Frogcomposband/master'
cargo run -p rfb-legacy-import -- sync-demo-items packs/rfb-demo-original/legacy-item-selection.json packs/rfb-demo-original/items
```

The command reads the pinned legacy commit, rejects index/name drift, duplicate
selection entries, and items with active behavior or unmapped functional flags.
It emits formal `demo.item.*` definitions and preserves original base values.
Town membership is expressed by the formal shop definitions, so the legacy
`TOWN` generation flag is allowed but not copied.

## Coverage Audit

`legacy-item-adaptations.json` records formal items that implement an RFB source
item without being generated by `sync-demo-items`. Each row pins the source
index, authoritative source name/id, formal item id, coverage status, blocker
when applicable, and the contract that introduced the adaptation.

Run the deduplicated audit with:

```powershell
$env:RFB_LEGACY_SOURCE='D:/codex/Frogcomposband/master'
cargo run -p rfb-legacy-import -- audit-demo-items packs/rfb-demo-original/legacy-item-selection.json packs/rfb-demo-original/legacy-item-adaptations.json packs/rfb-demo-original/legacy-item-p3-plan.json packs/rfb-demo-original/items
```

The JSON report counts unique active source items even when one source template
has several formal adaptations. It also lists source items whose mechanics are
ready, blocked source items with their blockers, and formal items with no RFB
source mapping.

`legacy-item-p3-plan.json` freezes the P2 totals and assigns every P3 source
identity to one rule family and one implementation batch. The audit validates
the pinned source index/name/id, reports each batch's `blockedToActive`,
`blockedToMechanicsReady`, newly mapped RFB formal item ids, and remaining
secondary blockers. A planned source cannot report as active until its plan row
records completion of behavior, authoritative Chinese name, source identity,
flavor, and acquisition requirements.

The P3.0 baseline contains 85 planned source identities: 16 scrolls, 23
potions, 25 foods, and 21 launcher/ammunition rows. All remain blocked at the
baseline, so every formal-item delta and transition count is zero. The ranged
batch deliberately exposes the blockers that will remain after damage-model
work: five unpaired launchers, five instant-artifact rows, two charisma flags,
and two no-enchant flags. Those rows must not become active merely because the
launcher multiplier or ammunition dice blocker is removed.

## P3.1 Food and Basic Status Effects

P3.1 moves all 23 planned identities to `active`: eighteen mushrooms, Hard
Biscuit, Strip of Venison, Slime Mold, Satisfy Hunger, and Sleep. Food effects
run in original order: the special effect resolves first, then nutrition is
added from the source `pval`. Damage foods retain their original dice and
attribute drain; restorative foods remove or restore the named state before
adding nutrition. Sleep applies paralysis rather than inventing a separate
sleep behavior, and Satisfy Hunger sets nutrition to the engine maximum minus
one.

The item effect vocabulary adds `satisfy-hunger`, generic `apply-status`,
`self-damage`, and `drain-resource-full`. Item `sequence` accepts these narrow
self effects without allowing nested, projected, or world-changing steps.
Confusion and hallucination use their matching resistance types; paralysis
uses the existing status-immunity boundary. Hallucination is persisted as an
ordinary status. The Web renderer derives occupant substitutions from cell
index and authoritative `worldTick`, so presentation changes are deterministic
and never consume core RNG.

All source names, Chinese names, flavors, weights, values, and nutrition values
come from RFB `master`. `TOWN` foods enter the General Store. Priced non-town
restorative or harmful foods enter the Black Market. Zero-value harmful foods
remain zero-value and use deep regular-kobold theme drops instead of violating
the shop positive-value rule. The remaining shallow items use Warrens drops.

The four deferred special foods remain blocked exactly as planned: Fast
Recovery, Fine Ale, Fine Wine, and Elvish Waybread still report both
`consumable-effect` and `food-nutrition`; no reduced substitute is emitted.
The audit now reports 179 active, 106 mechanics-ready, and 259 blocked source
items, with 180 mapped formal items, 24 original formal items, and 204 formal
items total. P3.1 reports 23 `blockedToActive`, no remaining item, and no
secondary blocker.

The demo pack is version 1.195.0 with content hash

## P3.5 Item Generation and Mutation

P3.5 moves five of its six planned identities from `blocked` to `active`:
Mundanity, Acquirement, *Acquirement*, Rumour, and Crafting. Acquirement reuses
the current floor's validated loot table, forces exceptional quality, and
creates one item at the player's position; the starred scroll uses the same
path for two or three items. Generated instances use the existing monotonic
item serial allocator. The count roll and the existing entry, quality, and
affix rolls are the only core RNG draws.

Mundanity and Crafting use the existing item target selection. Invalid targets

artifact identity is part of the content kind rather than an instance field.
Crafting accepts ordinary weapons, armour, launchers, and ammunition, chooses
from explicit validated affix candidates, and fully identifies the resulting
ego item.

Rumour emits a content-owned localization key and deliberately consumes no
core RNG. The ledger records this fixed-rumour adaptation. Artifact Creation
remains blocked under `random-artifact-identity`; a high-quality ego is not
treated as a random artifact substitute.

## P3.7 Character Growth Potions

P3.7 moves three of its five planned identities from `blocked` to `active`:

Neo-Tsuyoshi clears hallucination and extends a normal persisted status. The

## P3.7-M1 Mutation Definitions and Authoritative State

Content pack 1.212.0 adds one `MutationDefinition` for each of the 152 M0
ledger identities. Definitions retain the stable `rfb.mutation.*` id, exact
