## 2. 建议实施顺序

### S1：巫术之塔与盗贼公会的现有服务接入

已实现两处入口、批量鉴定会员报价和公会住宿；Rogue Owner 身份仍待正式职业交付，当前盗贼公会使用其他身份价。完整最终计价仍属于 S5。

这是推荐的第一批：新增两处可用建筑入口，不依赖赌场、声望或新物品生成器。

1. 复用 `town_facility_membership`，让批量鉴定的权威报价支持 Owner / 其他身份。投影和实际扣款使用同一计算，不再由前端判断会员价。
2. 将现有住宿规则提取为一个共用内部操作：旅店仍从 Shop 取价格和入口，盗贼公会从 Facility 取价格和入口。不要伪造一家有库存的旅店商店来承载公会住宿。
3. 新增 `demo.town-facility.morivant-sorcery-tower`、`demo.town-facility.morivant-thieves-guild`，补地图两格、设施引用、来源记录和中文。ID 在实现时检查唯一性。
4. Sorcery 身份使用现有领域 ID。当前包没有 Rogue，不造占位职业；先向现有构筑开放其他身份价格，Rogue Owner 价在该正式职业交付时接入。来源表保留 Rogue 原始条目。
5. 暂沿用现有建筑价格算法，明确这是“基础价和身份接入完成”；完整最终报价在 S5 完成。

验收：批量鉴定只作用于携带/装备物品，会员报价与扣款一致；公会住宿复用中毒/流血拒绝、时间与资源恢复、召回取消规则；金币不足和非法入口不修改状态。复用已有鉴定、住宿测试，各补真实缺口，不串联多个设施走路线。

### S2：餐饮、传闻与怪物研究

1. 在旅店增加独立的“购买食物和饮料”：原版 `inn_comm(BACT_FOOD)` 设置饱食到 `PY_FOOD_MAX - 1`，不是发放一份背包食物。核对当前种族/拟态提示和对应 RNG 分支，复用饥饿模块。
2. “打听传闻”从该 ref 的 `lib/file/rumors.txt` 核对可用中文及授权，再导入有来源的消息条目；复用消息显示。不能拿现有单条传闻卷轴文本冒充原版传闻池。没有可交付来源时，该项继续隐藏并记录缺口。
3. 开放驯兽师 (144,13)。以怪物种类 ID 为输入，支持现有正式内容的符号、名称、唯一/非唯一筛选；复用探查知识和保存结构。研究对象不要求在玩家视野中，不能复用战斗“选择可见目标”的限制。
4. 原版 `research_mon` 在确认查看种类资料时记为见过并执行 `lore_do_probe`；取消浏览不收费。实现时保留该成功边界，明确当前知识投影已覆盖和尚未覆盖的字段。

验收：餐饮不生成物品；取消、资料不存在、金币不足不扣费、不消耗业务 RNG；研究后的知识可保存恢复。传闻使用 Rust 权威 RNG，结果通过事件投影给前端。

### S3：博物馆入口与共享存储

分两次交付，避免把同存档存取表述为跨角色博物馆已经完成。

**S3a：本存档内的跨城博物馆。** 复用萨洛斯博物馆和 `home_states`；新增莫里凡特入口，引用同一博物馆存储 ID，与玩家 Home 分开。核对普通物品存取、真正神器拒收、刻铭清除及原版 Sacrifice 美德影响。继续允许取出；不增加原版不允许的馆藏销毁命令。萨洛斯现有单城适配与共享规则一并收敛。

**S3b：原版跨角色共享语义。** 单独实现本地用户资料中的博物馆库存，目标是新角色也能读取同一馆藏，而不是读取别人的整份游戏存档。先确定现有桌面/其他客户端可用的持久化边界，再写最小存取事务：馆藏与角色背包只能有一份物品所有权，处理进程中断、重复命令及同时打开两个存档，禁止通过回滚角色存档复制馆藏。复用已存在的物品序列化、ID 和保存基础；不照搬旧原版原始结构体兼容格式。

S3b 涉及应用持久化和跨存档事务，不能只改内容 JSON；未完成时保留“同一存档内共享”的明确适配说明，不声称完整复刻。

验收：S3a 直接验证两城引用同一库存和 Home 独立性；S3b 验证跨角色取放、崩溃恢复和并发冲突，不能以两次顺序保存代替事务证据。

### S4：王牌之塔指定层传送

1. 对照 `bldg.c::BACT_TELEPORT_LEVEL` 与 `spells3.c::choose_dungeon`：目标必须是已访问、未 suppressed、非随机且有有效深度的地牢。
2. 原版可选目标深度不只是已走过的最深层；输入按地牢最小/最大深度约束，并受原版特殊任务深度上限约束。不能误做成“只回到已经到过的楼层”，也不能开放本包尚无正式定义的楼层。
3. 核对并补齐每个地牢的访问/召回深度记录；当前单个 `RecallStateDto` 不足以枚举全部已访问地牢。该持久状态影响保存和哈希时，按实际范围更新契约。
4. 前端从 Rust 投影读取可选地牢、有效楼层和价格，提交设施 ID、地牢 ID、深度。Rust 再验证一次，收费后更新召回目标并使用既有延迟召回和地表返回逻辑。

验收：未访问/被抑制/无正式目标层不能提交；取消不收费；选层后保存恢复、倒计时触发、原地表返回正确。保持普通召回的原有语义。

### S5：声望、建筑最终报价与强化完整规则

这是完整经济规则批次，影响所有复用设施，不能只给莫里凡特另写一套价格。

1. 核对原版 `fame` 初始值及已实现行为的增减点，包括任务、悬赏和守卫等真实来源。它不是金币、征服数、任务数量或美德的别名。补 Rust 权威字段、保存与投影；只接入已有行为，不借此新增任务内容。
2. 复用已有种族交易修正和魅力数据，按 `shop.c::town_service_price`、`_price_factor_aux` 接入种族、魅力和声望影响，保留舍入顺序及免费服务语义。检查共享商店价格路径是否存在相同适配差异，列明实际影响。
3. 旅店开放“询问你的声望”，使用 `BACT_REPUTATION` 原版区间和中文；收费后输出真实声望对应结果。
4. 按 `bldg.c::enchant_item` 实现可选强化档位、装备估价增量、会员上限/折扣、数量及付款条件，替换固定 750/1500 和每次固定 +1 的适配。复用物品估价和强化操作，不新增第二套物品成长系统。
5. 原版列出的 Samurai、Berserker、Blood-Knight、Mauler、Ranger 等 Owner 身份，随正式职业接入；无对应 ID 时继续记为未覆盖，不自行翻译或用相似职业代替。

验收：代表性身份、魅力、声望和强化档位的来源数值；报价与实际扣费一致；失败不丢物品/金币；受影响的原有设施调用者都检查。新增持久声望触及时执行对应全局保存/状态哈希契约，不能批量刷新掩盖差异。

### S6：赌场与赌博商店，按独立机制拆批

**S6a 普通赌局。** 按 `gamble_comm` 接入夹牌、掷骰子、轮盘、骰子老虎机、扑克和规则说明。逐个迁移押注限制、下注/选择、赔率、结算及 Chance 美德影响。使用 Rust RNG 和金币结算；只有确实需要跨玩家操作的赌局才保存未结算状态，避免退出或重发命令重投结果。

**S6b 赌博商店。** 按 `_gamble_shop_potions`、`_gamble_shop_scrolls`、`_gamble_shop_device`、`_gamble_shop_object` 分三组接入七种商品。药水/卷轴使用来源权重，设备使用来源等级/激活分布，装备使用来源深度和品质生成。输出完整鉴定的物品，复用生成草稿、正式实例 ID、自动拾取处置与神器唯一性。先列出来源候选中缺少的正式物品/机制；不能删掉缺项后重新归一化概率并声称原版分布已完成。随机神器按钮保持关闭。

**S6c 怪物竞技场。** 独立于普通赌桌：核对 `battle_monsters` 及押注入口、候选生成、赔率、玩家旁观、胜负/平局/退出结算和返回城镇。复用现有怪物战斗，只在需要处加入赌局状态；不借用玩家竞技场闯关记录或任务成功状态。

验收：每种赌局的有效输入和结算；固定种子下中奖结果可复现；金钱与物品只结算一次；多步赌局和怪物竞技场能保存恢复。未完成的子服务不显示空按钮。正式价格收口依赖 S5。

### S7：战士公会神器重铸

依赖 S5 的真实声望与估价，还需要物品方向提供与原版一致的随机神器重铸能力。

1. 对照 `_reforge_artifact`、`_get_reforge_src/_dest`、`_calculate_reforge_cost`、`get_reforge_powers` 和 `reforge_artifact`，核对源神器、目标物品、槽位权重、声望功率范围、限制和费用。
2. 先完成物品规则底座，再接建筑 UI 的源/目标选择和权威报价。不能把“重铸神器”降为加几个普通词缀、生成一件无关奖励或复制源神器。
3. 在同一权威操作中处理扣款、源物品消耗、目标更新、唯一性记录和 RNG。取消或不合法选择不改变物品、金币及 RNG；可预判的拒绝在实际消耗前完成。

验收：合法重铸结果、目标限制、功率/费用边界、源物品唯一消耗和保存恢复。没有正式机制交付前继续隐藏服务，不用占位按钮提前开门。

## 3. 代码与内容落点

- 内容：现有 `packs/rfb-demo-original/townFacilities/`、`shops/morivant-inn.json`、`towns/morivant.json`、`worlds/middle-earth.json`、terrain、locale 和 `legacy-wilderness-selection.json` 的来源记录。
- 设施规则：优先在 `crates/rfb-core/src/game/town.rs` 的现有服务入口复用。住宿、公会鉴定做最小共用改动；赌局或重铸变大时放到现有职责邻近模块，不堆回 `game/mod.rs`，也不建通用建筑脚本引擎。
- 地牢与保存：`game/floor.rs`、现有 `DungeonState`、`game/persistence.rs`、`game/validation.rs`。只有 S3b 才进入应用级跨角色存储。
- 物品与知识：`game/loot.rs`、现有估价/强化函数、`game/abilities/terrain.rs` 的探查知识；沿用已有物品和怪物 ID。
- 类型与界面：`rfb-content/src/definitions/towns.rs`、`rfb-protocol/src/lib.rs`、`web/src/task-service-panel.ts` 及实际住宿/存储调用界面。修改类型后生成 Schema/协议绑定，不手改 `web/src/protocol.ts`。

共享机制修改前检查实际调用者及当前并行分支交付状态。只在真实重叠或依赖出现时协调，不为了这个计划预先造平台或启动其他工作。

## 4. 交付纪律与完成定义

每批做到服务可用、显示真实报价、成功与拒绝均正确、必要状态可保存恢复，再提交。内容变化更新正式包版本和 lock；纯文档计划不改包或生成物。

复用现有鉴定、住宿、Home、召回、探查、物品生成和交易测试，只补缺失的行为检查。设施测试直接设位置；通用购买选首个投影库存。按既定要求，不新增/运行城镇可达性专项或完整步行—交互—存档—回城路线；不默认跑桌面 E2E、Android 或全量 workspace。

服务目录完整、会员身份完整、原版最终价格完整、跨角色博物馆完整、桌面试玩通过分别报告。S1–S4 完成可称“常用服务补齐到当前正式内容范围”；只有 S5–S7、S3b 及正式职业依赖也交付后，才能称非任务建筑服务完整复刻。原版尚未导入的物品、怪物、职业仍需明确列出限制。
