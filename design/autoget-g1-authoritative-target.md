# G1：权威自动拾取目标

状态：已实现。协议 `1.155`，state hash Schema `v76`，contract 基线 `v218`；save 容器保持 v1，旧开发存档不兼容。

## 目标判定

- `off` 不产生目标；`ammo` 只考虑带 `=g` 铭文的已发现地面物品；`wanted` 还考虑已发现金币和墨家名器首条命中的地面物品。
- `wanted` 接受拾取动作；排除留下、询问，以及受神器、任务、内容标签或保护铭文阻止的销毁动作。开启 `leaveDestroyedItems` 时不考虑销毁目标。
- `wanted` 要求玩家到目标的既有 line-of-effect；`ammo` 保留原版规则，非投射目标只有在 RFB 距离不超过 18 时才可入选。
- 所有候选必须通过 O3 已探索格本地旅行检查。最终按 RFB 距离取最近目标，距离相同按稳定实例 ID 排序。
- Core 只投影最终坐标 `autoGetTarget`；前端不编译规则、不判断资格。

## 金币发现

- 金堆新增权威 `discovered`，由当前视野或金币探测写入。
- 未发现金币不进入 `goldPiles`、`CellDto.itemId` 或自动拾取目标。
- 发现状态随楼层和存档保持并进入 state hash；目标坐标始终派生，不保存。

G1 不实现 Ctrl+G 输入、连续旅行、到达后的拾取或重新选取；这些执行行为留给后续阶段。
