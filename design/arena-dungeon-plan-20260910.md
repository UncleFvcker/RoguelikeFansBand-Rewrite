### 生成与规则的实际边界

- **专用圆形房间：**`src/rooms.c::room_build` 对 `DUNGEON_ARENA` 调用 `build_type16(TRUE)`。半径 `3 + randint0(5)`，取 3–7；用原版 `distance` 判断圆形内部，地板范围为距离 ≤ 半径−1，外围经 `place_extra_bold` 与 `add_outer_wall` 处理。不是普通 `DF1_ARENA` 开阔布局，也不是城镇竞技场设施。
- **通道仍存在：**`src/generate.c` 仍打乱房间顺序并连接房间；按 `randint1(depth) > tunnel_percent` 选择洞穴式或普通通道。`src/grid.c` 的生成通道依赖生成网格类别，不能直接套用游戏内“永久墙不可挖掘”来推断房间断连。旧计划中的“隔离房间”不作为本批实现依据。
- **房间照明：**未受 DARKNESS 限制时，`randint1(depth) <= 15` 决定房间亮起；本地牢未设 DARKNESS。不能把全部房间固定为亮或暗。
- **中心单怪：**每个成功建成的房间在中心调用 `get_mon_num(depth)`，并以 `PM_ALLOW_SLEEP` 放置一个候选。不附带普通房间群体；候选为空或放置失败的源行为需保留明确处理。
- **分配下限：**`src/monster2.c::get_mon_num` 在普通、非召唤分配上下文要求怪物等级 ≥ `MIN(50, depth-5)`，故 50 层为 45，55 层起为 50。沿用既有稀有度、唯一种和分配资格，不能误写为 `MAX`，也不能把下限施加到全部召唤。
- **普通生成预算：**`src/generate.c::_cave_gen_monsters` 跳过额外普通怪物生成；`_cave_gen_objects` 跳过普通地面物品、金币及补给等流程。房间中心怪物、最终守卫、怪物死亡掉落与最终奖励仍分别处理。
- **不能顺带禁用：**源码未在 `_cave_gen_traps` 整体排除竞技场，也未给本地牢 `NO_DOORS`。`alloc_monster` 仍存在运行期分配路径，但竞技场排除群体／horde 分支；“不额外生成初始怪物”不等于“关闭环境刷怪”。
- **移动规则：**`src/melee2.c` 的竞技场特判涉及穿墙／毁墙怪物的寻路流，不能据此全局删除其移动能力。永久墙行为及怪物寻路按实际消费者核对。

## 3. 当前缺口

现有 `legacy-wilderness-selection.json` 只有竞技场计划登记，尚未开放真实世界入口。生成房型只有 Rectangle／Cross／Cavern，没有本批圆形房间与中心单怪流程；现有全局预算不能直接表达原版的房间分配行为。

`random_artifact.rs` 已有随机神器生成及卷轴相关参数，实例化与名称持久化也已合入；但尚未找到「创造神器」正式物品及选中已有装备后使用的完整入口。`legacy-item-p3-plan.json` 中仍登记其旧阻塞 `random-artifact-identity`，实施时应更新为实际完成状态，不能把工厂存在视为卷轴可用。

## 4. 实施顺序

### AR1：圆形房间、墙与通道

- 在现有 procedural 内容类型和生成模块中加入表达上述几何所需的最少能力，复用房间中心、占用格与连接流程。只为实际差异增加字段或枚举，不建立通用可编程生成管线。
- 对照 `place_extra_bold`、`add_outer_wall`、`build_tunnel`／`build_tunnel2`，落实地牢填充墙、房间边界和通道开口。生成阶段的开路与游戏内挖掘权限分别遵守各自约束。
- 落实 BIG、NO_VAULT、无 streamer、普通门与房间照明；不混入 CAVERN、河湖、废墟、普通 ARENA 开阔布局。地图尺寸沿本项目既有大地图适配，记录实际尺寸，不宣称像素或 RNG 序列逐格复刻原版。
- **完成证据：**固定种子复现圆形地板、半径边界、永久墙与通道；不同种子有有效变化；楼梯、玩家和守卫预留位置可达且无重叠。生成结束后的永久墙仍不可被普通挖掘破坏，保留已有普通地牢生成覆盖。

### AR2：房间中心分配与运行期生态

- 按成功生成房间的中心分配单怪，复用当前全局候选与唯一种登记；处理占位冲突和最终守卫预留，不能先放中心怪再无声覆盖。房间大小、数量与布局成为初始普通怪物数量的来源。
- 实现 `MIN(50, depth-5)` 的非召唤分配下限，以及本地牢禁用队伍伴随／horde 的源差异。保留运行期分配，避免为了取消额外初始怪物而移除整张 encounter table。
- 取消额外初始普通怪物及普通落地物品／金币预算，保留陷阱、怪物掉落和奖励消费者。复用既有预算校验；若零预算不合法，只在对应内容边界补足真实语义。
- 核实并复用穿墙／毁墙与寻路约束；最终守卫已有 actor 定义，但须检查其高防御、低生命、抗性和移动能力是否有真实消费者，不以“有 actor”代替可战斗验收。
- **完成证据：**50／55／80 层下限边界、单怪无伴随、无第二批初始怪物、无普通地面战利品；一次真实环境分配与召唤检查其不同资格；死亡仍能掉落。复用现有 `monster_ecology` 测试，不给每层复制矩阵。

### AR3：「创造神器」卷轴使用闭环

- 导入 kind 364 的正式物品与中文显示名，沿用 P3 来源身份；调用现有随机神器工厂，补齐“选择已有合法物品 → 生成 → 更新该实例 → 消耗卷轴”的使用路径。
- 对照 `src/spells3.c::artifact_scroll`、`src/devices.c` 和 `src/cmd6.c`，确定可选物品位置、无名武器／防具过滤、神器／Ego／特殊定制／不可移除限制，以及取消、失败和成功的消耗／回合语义；在实现前记录决定，不凭其他卷轴的默认行为套用。
- 明确原版对多件堆叠目标只保留一件的处理、Snotling 蘑菇分支及 Android 经验重算等实际相关消费者。选中物品不通过生成另一件无关联装备来替代；沿用现有实例、背包／装备槽、重量及事务边界。
- 生成属性、名称和来源须持久化；非法目标在真正输入边界拒绝，不能先改库存再因校验失败留下半完成状态。正常生成失败与非法指令分开处理，其 RNG／消耗遵从所核实规则。
- **完成证据：**从正式物品使用入口成功改造合法装备，保存恢复后属性与名称不变；覆盖取消、拒绝已有神器／Ego、堆叠目标及实际存在的种族消费者。优先复用已有神器工厂与物品使用测试，不另写一套神器算法测试。

### AR4：31 层、守卫、奖励与真实入口

- **依赖 AR1–AR3 完成后开放入口。**在正式内容中接入 50–80 层、(67,7) 地表入口与返回、龙魔像入口守卫，以及 80 层唯一种散失金属史莱姆。
- 补全已有来源登记的墙参数与实现说明，沿用地牢稳定 ID 和来源记录。无替代组，不引入新的世界选择开关。
- 最终奖励使用已完成 AR3 的 `70/52` 物品，复用最终守卫奖励发放流程；与普通死亡掉落分开确认，保存／重入／重复处理死亡均不得再发一份。
- 末层无向下楼梯；保存恢复、楼层往返、召回和地表返回沿现有流程。中文名逐字采用本次 source ref；实施时更新正式包版本与 lock，不预留版本号。
- **完成证据：**由真实地表入口进入首层，代表中层转移、末层战斗与奖励、卷轴实际使用、返回地表和保存恢复闭环均通过；不是只靠直接构造末层状态证明入口已接通。

### AR5：聚焦验收与交付

- **内容：**核对索引 25、坐标、31 层链、两名守卫、`70/52` 奖励、无替代关系、L/A 参数、source、中文名与 lock。覆盖代表层，不为 31 个定义各复制固定场景。
- **生成与规则：**按 AR1–AR3 的真实改动运行 generation、monster_ecology、world、item use／artifact 等相关测试；场景名沿 `arena_dungeon_` 区分城镇竞技场。保留正常门／陷阱、永久墙、怪物掉落与普通地牢的直接回归证据。
- **类型与契约：**内容类型改变才生成相应 Schema；DTO 改变才生成协议绑定，不手改生成物。若状态哈希输入、公共初始化或 RNG 改变，按真实影响执行 active `verify-all`，先解释行为差异再刷新。contentHash 不触发 State Hash Schema 升级或全量刷新。
- **交付：**更新 `docs/status.md`，记录完成阶段、地图尺寸／通道适配和实际验收范围。明确区分规则、内容定义、入口和可玩构建；可玩 EXE 若另行要求，使用 Tauri standalone。普通交付不默认扩大到全量前端、Android、桌面 E2E 或人工试玩。

## 5. 范围与完成标准

本批不接入城镇竞技场赛程、随机任务系统、奥林匹斯山或安格班，不重做随机神器工厂，不维护旧开发存档兼容。测试从新存档开始。共享物品使用路径若与其他工作树出现实际并发重叠，再协调文件与提交；已有共享机制不另造副本。

完成需同时具备：**圆形房间及有效通道、专用初始与运行期生态、可使用的创造神器卷轴、真实地表入口与 31 层链、最终守卫奖励不重复，以及按影响范围通过的自动检查**。只增加地牢 JSON 或获得一次构建成功均不算完成。
