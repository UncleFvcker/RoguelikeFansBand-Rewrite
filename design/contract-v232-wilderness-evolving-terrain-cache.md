# Contract v232：荒野分代地形与临时缓存

状态：第二步已实现。协议 `1.159`，内容包 `1.226.0`，State Hash Schema `v79`，
active baseline `contract-v232`；save 容器保持 v1。

## 行为边界

- `wildernessPosition × 3 + wildernessViewOffset` 得到当前绝对中心区块；96×33
  视口由中心周围 3×3 个 32×11 区块拼成。
- 每个区块只依赖当前 `wildernessSeed` 与绝对坐标。同一代相邻视口的重叠区域
  完全一致；道路、生物群系和正式地点继续由权威世界图决定。
- 草地、荒地、树林、雪地等微地形以及低层特殊房间随当前代 seed 变化。特殊
  房间不再依赖玩家从哪一侧进入。
- 运行时以 `BTreeMap<Position, Vec<String>>` 缓存派生地形，生成视口前删除距
  中心任一轴超过两个区块的条目，因此最多保留 5×5 个区块。
- 成功进入世界地图时清空缓存，并以固定奇数步长 wrapping 推进
  `wildernessSeed`。下一次进入同一荒野位置会生成新一代微地形。

## 确定性与持久化

缓存不是权威状态：不保存、不进入 State Hash，读档后为空。同一 seed 下冷缓存、
热缓存和淘汰后重建完全一致；seed 本身继续由既有 save 字段和 State Hash v79
覆盖。推进使用模 2^64 加法，完整周期为 2^64 次世界图入口。

本阶段不实现移动触发卷动、实体/物品/探索状态平移，也不改变怪物分配范围；这些
继续属于后续步骤。

## 验证

- 单元测试锁定相邻视口横向重叠、冷/热缓存一致、缓存不改变 state hash、5×5
  上限和远距淘汰。
- 测试锁定 seed 推进后地形变化、缓存清空和 wrapping 语义。
- 世界图、动态荒野生成、存档往返与特殊房间测试覆盖现有入口路径。
