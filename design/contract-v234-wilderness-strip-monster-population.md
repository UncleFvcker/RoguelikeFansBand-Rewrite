# Contract v234：荒野暴露条带怪物生成

状态：第四步已实现。协议 `1.160`，内容包 `1.226.0`，State Hash Schema `v79`，
active baseline `contract-v234`；save 容器保持 v1。

## 分配范围与轮数

- 初次进入普通荒野仍按道路 4 轮、非道路 10 轮生成怪物。
- 横向或纵向卷动暴露 3/9 个区块，只允许在对应的 32×33 或 96×11 条带生成；
  对角卷动暴露两个条带的并集，共 5/9 个区块。
- 卷动轮数按 `初始轮数 × 暴露区块数 / 9` 折算。不能整除时，以当前代
  `wildernessSeed` 和绝对暴露区块集合进行确定性舍入；不增加持久小数余数。
- 怪物首领与 pack 成员都必须位于新暴露条带。重叠区域内的既有怪物保持原样，
  不因卷动重新生成。

## 确定性与实体生命周期

- 条带生成使用由当前荒野代、绝对区块集合与固定 salt 派生的局部 RNG；不会消耗
  主模拟 RNG，也不会改写已有的怪物分配余数。
- 重新进入曾暴露过但已离开缓存范围的条带可以再次生成怪物；实体 ID 使用既有
  冲突规避序列，避免与视口中仍存活的实体重号。
- 自然补怪继续沿用既有机制，本契约不扩展其触发条件或频率。

## 伏击边界

- 伏击判定与激活只允许在世界地图发生。普通局部荒野不会掷伏击，也不能直接
  激活伏击。
- 世界地图判定成功后，仍进入既有局部伏击战斗地图，并使用独立 salt 与完整
  20 轮怪物生成；普通卷动的面积折算不影响伏击强度。

## 协议与持久化

本阶段不增加 DTO、存档字段或 State Hash 输入。暴露集合、折算结果和局部 RNG
均可由已保存的 position、offset 与 seed 重新派生，因此协议保持 1.160，save
容器保持 v1，State Hash Schema 保持 v79。

## 验证

- 单元测试锁定横纵 1/3、对角 5/9 的暴露面积和绝对区块确定性舍入。
- 世界流程测试锁定卷动怪物只落在新条带、不会使用伏击 salt 或 20 轮规则，并且
  不改变主 RNG 与已有分配余数。
- 世界流程测试锁定局部荒野不能判定或激活伏击；世界地图伏击流程保持既有行为。
