# Outpost 原版城镇地图改造计划

状态：已完成来源与当前调用链核对，待实施。本文规划地图改造，本批不修改正式地图或开放新任务。

## 1. 目标与基线

将当前 96×32 的简化 Outpost 改为 RFB 正常荒野中的完整 **198×65** 城镇模板，恢复城墙、河流、街区、城外任务地点和两个地牢入口。保留已有城镇、商店、设施、任务及地牢的稳定 ID；出生城镇仍是前哨站，世界坐标仍为 **(28,52)**。

- 当前工作树：`codex/dungeons-towns`，核对提交 `1b4910bcf`，正式包 `1.401.0`。
- RFB 来源：`D:/codex/Frogcomposband/master` 的 `master` Git ref，实际提交 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`。
- 正确地图为 `lib/edit/t_outp.txt`，公共符号来自 `t_pref.txt`。`t_info.txt` 在 Town 1、正常荒野、SPEED≤1 时选择该图；`t_lite.txt` 属于无荒野模式，`t_ulite.txt` 属于另一速度模式，本次不混用。
- 原图含 **65 行，每行 198 格；4383 格显式符号、8487 格空白**。保持 `NO_ROTATE`，不裁掉城外区域，不缩放、不转置。
- 中文城镇名沿用正式包及源表的“前哨站”。新增地形/设施文案按源字符串或中文表；没有权威名就记录 unresolved。

## 2. 当前实现与改造边界

当前前哨站使用世界根定义中的 `demo.floor.surface`：96×32，荒野 `mapOrigin=(51,17)`，玩家局部出生点 (44,16)。九类普通商店、白马旅店、伯爵、赏金事务所、Home 和两条任务链均已有正式定义；地图还放置了两件开发期起始物品。原图的博物馆尚未注册在前哨站。

改造继续使用 `demo.town.outpost` / `demo.floor.surface`，将模板尺寸改为 198×65、`mapOrigin` 改为 **(0,0)**。连续荒野视图仍为 198×66；第 66 行是模板之外的自然荒野，不伪造为原图的一行，也不把 65 行拉伸为 66 行。

初始层与其他城镇存在真实实现差异：`initialization.rs` 和 `wilderness.rs::town_template_terrain` 的出生城分支分别使用 fill/border 生成整块地表；Angwil 的 `inheritWildernessTerrain` 目前只适用于 procedural inline town。实施应让出生层复用同一按坐标/种子生成底图的逻辑，再覆盖显式格子，并将结果交给既有城镇存取流程。不能只改首次画面，也不能把 8487 格空白全部铺成固定草地。

本次迁移已有服务和入口，不同时重写任务地下图、奖励、职业种族、商店定价或怪物生态。博物馆复用已交付存储能力。没有本批证据的额外机制不预造。

## 3. 原图地形与入口映射

坐标均为原图左上角起算的零基 `(x,y)`；实施后与前哨站局部坐标一致。

| 源符号 | 来源含义 | 实施要求 |
| --- | --- | --- |
| 空格 | 不覆盖底图 | 继承当前世界地点的种子化荒野；保留滚动、地形变化和探索后的状态 |
| `#` | PERMANENT，855 格 | 使用永久墙；不能继续用可穿越/可挖掘的近似城墙 |
| `.` / `-` / `,` | FLOOR / GRASS / DIRT | 分别映射既有地板、草地、泥土，保持街道与土路区别 |
| `W` / `V` | DEEP_WATER / SHALLOW_WATER，589/47 格 | 保留河流与护城水域深浅，沿用实际水域通行及负重伤害规则 |
| `T` / `^` / `;` | TREE / MOUNTAIN / RUBBLE，177/78/24 格 | 复用既有树、山、碎石能力；不要为视觉一致而改成普通墙或地板 |
| `C` | DARK_PIT，7 格，f87 中文“黑坑” | 当前没有对应正式地形；原文 LOS、PROJECT、CAN_FLY，普通步行不能穿越。用现有移动模式表达飞行通行，并核实投射路径；不能用山、岩浆或黑色地板替代 |
| `&` | 本图明确覆写为 FLOOR | (98,29) 是调试符号对应的普通地板，不是出生点或隐藏任务入口 |

黑坑的投射不是只改颜色：当前 `projectile_geometry.rs::has_line_of_effect` 会检查 `is_walkable`，仅设置 `walkable=false` 会阻断本应通过黑坑的投射。实施需检查实际投射调用者，在现有几何/地形职责内表达该区别并覆盖回归，不另建一套投射系统。本图没有冰川，不借此追加冰川滑落系统。

## 4. 实施步骤

### O1：完整模板与出生城底图

1. 从固定来源提交解析 `t_outp.txt` / `t_pref.txt`，保留 198×65 全图与空格。先建立逐符号坐标核对，替换现有简化城墙、房屋、河流和装饰，不叠加两套地图。
2. 保留初始 floor/town ID，将世界根尺寸与地图原点同步改动。让初始地形构造和后续城镇叠加共用种子化底图入口；复用已有 chunk 生成，不新增 RNG 流、持久缓存或地图管理器。仅为真实需要增加内容字段并生成对应 Schema。
3. 加入准确的黑坑地形及所需通行/投射表达；其他地形先复用现有定义。保持城外树、水域、山与碎石的实际行为。
4. 建议出生局部坐标 **(99,33)**：源图为普通地板，位于城内街道，且与原点为零的现有荒野中心一致。源文件没有把此点声明为出生标记，应记录为本项目落点选择。
5. 当前地面短剑和两瓶轻伤治疗药水不是原图内容；本次保留它们的稳定实例 ID、数量和现有用途，移至邻近的 (100,33)/(101,33) 地板，避免移图时被墙覆盖或无说明删掉。角色背包中的出生物不改。

### O2：所有现有设施及地牢入口同步迁移

按上表更新 `shops/`、`townFacilities/` 与实际地形落点，伯爵复用多入口机制，增加共享博物馆入口。迁移 Warrens 与 Hideout 实际入口，并核实选中 Man cave 时仍走同一入口且不能进入未选中的地牢。

商店库存、店主、费用、Home、博物馆存储和跨城传送资格继续由现有状态维护。同步更新 `legacy-wilderness-selection.json` 的 Outpost `townPlans`，使用 `lib/edit/t_outp.txt`；当前 selection 只有城镇身份，尚无该城模板声明。按材料适用声明补充 `NOTICE`/来源记录，不套用 Angwil 地图作者的许可说明。

### O3：任务入口、存取与既有调用者

迁移九个已有独立任务入口，保留城外 `R` 的未开放底材。覆盖出生、跨区滚动、离城再入、读档、城镇传送、任务/地牢返回；显式地形、继承区域中的修改、探索及地面物品都必须通过同一城镇存取路径恢复。

检查出生地图尺寸扩大对地表怪物分配的真实影响。当前 `surfaceActorAllocation={rolls:12, level:9}` 不在本批随意调参；城镇矩形扩大后排除区域与可采样范围会变化，按现有规则解释结果，不能为了旧快照而硬塞旧怪物坐标。检查旧坐标引用的调用者，不机械替换全仓所有相同数字。

**O1–O3 是一个完整地图版本的实施步骤。地形、设施元数据与入口未对齐的中间态不作为可玩交付。** 不需要等待其他城市任务链或未交付装备；只有本次地图确实使用的共享能力进入实施范围。

### O4：验证与交付

- 内容：来源尺寸/符号/入口一致、三个伯爵门归属一个设施、未交付入口底材、世界地点原点、初始落点与地面物合法；正式包 version/lock 及相关来源检查。
- 行为：复用城镇、世界、荒野及对应任务测试；补充初始城透明底图保存、黑坑移动/投射、伯爵三门、共享博物馆的缺失覆盖。普通交易选投影首项库存；非移动场景直接设设施位置，不安排跨整张图的步行脚本。
- 返回：现有 Warrens/Hideout-Man cave 分支、两条任务链的入口交互与返回位置；清场/奖励逻辑未改时复用现有验证，不重造全部任务战斗测试。
- 契约：本次改变公共出生地图及持久 terrain/position，实际影响超出 town 类；完成实现后执行公共初始化范围的全局契约验证，逐项解释并刷新受影响 fixture。不是因为 contentHash 改变而刷新，也不因此自动升级 State Hash Schema。
- 本次不维护旧开发存档；验收从新存档开始。测试中旧坐标导致的失败应修正真实场景，不删除关键断言或保留一套旧地图兼容路径。
- 不默认跑完整前端、Android 或桌面 E2E，不增加专项路径可达性验收。若用户要可玩产物，另执行 Tauri standalone 构建；布局试玩反馈后再调整。

实现完成后更新 `docs/status.md` 的实际开放范围，并说明完整模板、已有功能迁移、新增博物馆、仍未交付的两组任务替代和已执行检查。当前这份计划仅经过文档与源数据核对，未进行地图游戏验收。
