## 为什么下一职业选游侠

| 候选 | 合并后可复用基础 | 本轮主要新增工作 | 顺序判断 |
| --- | --- | --- | --- |
| **游侠（Ranger）** | 自然等领域、法师双领域/改换/保存、圣骑士随机学习、射击与怪物探查 | 随机学习与双领域交叉、3 级施法起点、职业参数、箭射速和树林通行、两件奖励弓 | **优先**。已有基础足够，形成弓箭与自然法术结合的新玩法，范围可限定为四个 Build |
| 牧师（Priest） | 双领域、随机学习、善恶领域与现有法术效果 | 主副领域善恶过滤、主领域特殊效果、武器祝福/厌恶、两类职业能力及奖励 | 后续候选。组合与领域例外更多，宜在双领域随机学习闭环完成后接入 |
| 食魔者（Magic-Eater） | 新装置生成、使用、充能和实例保存 | 体内装置槽位、吸收/替换、再生充能、专门的状态与 UI | 后续独立职业批次；已有法师“吞噬魔法”不等于此职业机制 |

游侠整体工作量中等：法术效果和双领域状态已经存在，但不能把法师 Class 改成 WIS，再挂一个射击加成就开放。最需要补齐的是随机学习对共享支出、遗忘和改换副领域的消费，以及射击结算顺序。

## 本轮交付范围

交付现有领域范围内的可玩游侠：**固定自然主领域，第二领域四选一**，普通创角可选当前受源规则允许的种族；包含 1—50 级职业成长、书本学习/施法、15 级职业能力、射击/树林规则、当前可达生成/奖励/公会及保存。高等级规则由测试和显式经验准备验收，不承诺自然练到 50 级或完整通关。

| 自然 `nature` | 咒术 `sorcery` | `demo.build.ranger-nature-sorcery` |
| 自然 `nature` | 死亡 `death` | `demo.build.ranger-nature-death` |

原版第二领域共六项，另有混沌 `chaos`、王牌 `trump`，尚未具备同等正式接入，留给领域批次。新合入的工艺 `craft` 不在 Ranger 候选表中，不能因为已有书本就开放；生命、圣战、毁灭等也不属于本轮游侠第二领域。四个组合不是全部原版游侠组合。

范围包含通过真实书本在上述四个副领域间改换，并由当前领域驱动学习、书本分配、自动拾取与设施等消费者。自然主领域不能改换；不能选择重复、源不允许或尚未支持的领域。领域效果若查出 Ranger 实际可达缺口，须修复或明确缩小开放范围，不能以“书已导入”替代行为验收。Android 和其他职业的新领域入口不在本轮范围内。

## 来源与已确认差异

唯一 RFB 来源为 `D:/codex/Frogcomposband/master` 的 `master` Git 对象，本次实际提交为 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`，使用 `git show` / `git grep` 读取。第一步已完成[逐项来源审计](ranger-source-audit.md)；本节保留规划依据与主要结论，具体消费者和实施差异见审计。

- **职业与出生：** `src/ranger.c` 的中文名为“游侠”；STR +2、INT 0、WIS +2、DEX +1、CON +1、CHR 0；生命 106、基础 HP 8、经验 140、宠物维持除数 35。出生为匕首、软皮甲、短弓、随机 20—40 支箭及所选领域书，叠加现有种族/公共出生流程。第一步已追踪基础与成长技能、近战、武器熟练度、装备感知、美德及种族交叉的公共表，数值及适配边界见审计。
- **施法：** 同文件使用 WIS，3 级起点，最低失败率 5，负重参数 450/33/1000，有手套负重；没有 Mage 的减耗及法力再生选项。`lib/edit/m_info.txt` 的 `N:4` 提供 Ranger 表，五个本轮涉及领域的 160 项等级/费用/失败率/首用经验参数已核对，包括无法学会的高阶法术；不复制 Mage/High-Mage 参数。
- **学习容量：** `m_info` 的 `I:LIFE:WIS:0x06:0:3:450` 决定随机书本学习；这里的 LIFE 是学习方式标志，不代表允许生命领域。`src/xtra1.c` 的 `calc_spells` 使用 `max(level − 3 + 1, 0)`，双领域 Ranger 的基础上限为 80、该学习方式额外 bonus 为 0；不采用 Mage 的 96＋bonus，也不沿用单领域折半算法。额外学习机会、遗忘返还与已付支出按审计中的共享公式处理。
- **随机学习与改换：** `src/cmd5.c` 按当前书的源顺序用 reservoir sampling 抽取合格法术，`item_tester_learn_spell` 使用职业第二领域候选表，因此 Ranger 也可请求改换。第一步已确认 `spell_okay(..., study_pray=TRUE, ...)` 排除已学/遗忘项，游侠不能重复研习；改换仍不退还旧副领域的学习支出。当前随机学习仅按已知数量判满，须接共享支出、主副熟练度、遗忘恢复与保存。确认改换后即使新书无候选也保留改换，未成功学习不耗学习回合；详见审计。
- **射击：** `src/ranger.c` 装备任意 `TV_BOW` 发射器时增加射击技能 `20 + level`；这里不只指射箭的弓。`src/xtra1.c` 先按射击技能与重弓/重甲条件计算公共基础射速，随后 Ranger 回调把非 `TV_ARROW` 的基础射速设为 100。要在现有投射物解析链处理，不另造射击公式；保留装备额外射速、骑乘、弹药破损及特殊发射器的源结算顺序。
- **树林与能力：** `src/cmd1.c` 对 Ranger 免除普通树地形的双倍移动能量；当前树地形公共适配为非步行/可飞行，本轮接 Ranger 通行并保留普通移动能量，不重写所有职业慢速穿树。15 级能力实际 SPELL_NAME 为“探测怪物”，WIS / 20 / 90、最低失败率 0；优先支付 MP，不足部分支付 HP。复用已有探查效果，空目标也成功支付；不能照搬 Sniper 的 INT/80/固定 HP 配置。
- **生成与奖励：** `src/obj_kind.c` 的武器偏好指向弓类；`src/artifact.c` 的 Ranger bias 及 Warrior 概率分支须沿现有自然/主题/卷轴生成入口核对。`lib/edit/q_old_castle.txt` 的 Ranger 奖励按 `$RANDOM27 MOD 5` 分为 `belthronding`（1/5）与 `yoichi`（4/5）；对应 `a_info` 124、148 当前未找到正式物品定义，列入必要导入，不能用 Archer 的奖励替代。普通盗贼任务、固定神器重复替代与其他职业条件另外审计。
- **公会：** 源城镇表包含 Ranger 的弓手公会 Owner，以及 Thalos/Angwil 第 8 号塔 Member 条目；依当前六个正式城镇映射逐项核对服务资格、领域条件与定价，不扩入未开放城镇。

所有中文显示名逐字采用源中文表或源字符串。第一步已找到两把奖励弓的源中文后缀 `『贝尔斯隆丁』`、`与一的`，完整属性和中文表定位见审计。来源、许可证及 NOTICE 随实际导入维护，不把旧批次的授权判断当作新材料的自动授权。

## 最小实现方案

1. 新增一个 `demo.class.ranger` 和四个薄 Build，共用领域书、法术效果及来源记录。玩家 actor 复用现有基础参数，以独立 `demo.actor.ranger-player` 保留正确职业显示名；直接复用 Mage actor 会显示“法师”。出生装备引用现有物品，箭数量走权威出生 RNG。
2. 在现有职业施法配置、`player_abilities.rs` 和 `spell_realms.rs` 补足实际缺口：3 级起点、Ranger 学习公式与职业参数、双领域随机学习、当前副领域与合法候选。复用已有共享学习支出/历史/待确认状态；只有现有字段确实无法表达时才新增字段，不建 Ranger 专用存档或第二套学习系统。
3. 在现有 `player_stats.rs` 射击解析及移动规则中处理职业差异；探查能力复用 `demo.ability-program.sniper-probe-monsters` 的实际效果。只有真正共用的行为才提取函数，不给所有职业加无调用者的配置框架。
4. 职业关联随本批完成：生成偏好、两个固定神器、现有任务/设施消费者和四个 Build 的五类生成审计。复用公共物品/奖励机制及共同证据，保持每个物品唯一稳定身份。

## 验证与协作边界

每步只运行实际受影响检查，优先复用现有覆盖。行为重点为 1/2/3/15 级、学习容量上限及遗忘、四个第二领域的参数/资格差异、弓与非箭射速、改换后的消费者和保存；不复制四套完整战役测试。相关检查通过后交付该步，不因普通提交或 merge 机械运行全量桌面构建。

公共初始化/RNG、状态哈希输入或共享协议投影发生变化时，按实际影响运行全局契约检查；失败先解释行为差异，不能直接刷新 fixture。`contentHash` 不在状态哈希输入中，纯内容变化不因此升级 State Hash Schema。保存类型变化按现行格式规则处理，只维护新开发存档。最终桌面必须使用 Tauri standalone，不能用普通 Cargo build 替代；命令见[验证与契约](testing.md)。

四个 Build 的生成记录遵循[内容开发](content-development.md#职业与领域-build-的生成接入)，五个范围为基础分配/Tailored、Ego/负向生成、随机神器、固定神器/奖励、使用/保存。记录同时包含源规则、当前消费者和可复现行为证据；不可用物品不能仅因此被移出普通生成池。

种族职业方向在当前 `main` 负责游侠接入和交付；法术道具继续负责缺失领域与公共物品效果，地牢城镇继续负责地点。两把必要奖励弓等交叉内容实施前核对是否已由对方导入，复用同一 ID；只有实际重叠写入或共同机制依赖才协调，不预设等待两缺失领域。集成写入交接遵循[并行协作](parallel-development.md)。
