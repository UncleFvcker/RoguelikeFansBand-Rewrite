# 跨角色馆藏

莫里凡特 `(98,17)` 与萨洛斯博物馆共用馆藏，Home 独立。来源为 RFB `master` 提交 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c` 的 `src/home.c`：普通物品与随机神器可存取，固定神器拒收，捐赠清刻铭并增加 Sacrifice；检视不自动鉴定。原版通过用户目录的 `museum.txt` 跨角色保存，本项目复用自己的物品 DTO 与存档校验。

## 玩家入口

- 使用同一本地 Tauri 应用资料的新角色可读取同一馆藏。首次生成有博物馆的城镇时载入；已有会话可在博物馆点击“刷新馆藏”。
- 其他窗口改变馆藏后，旧视图不能直接转移，刷新后重新选择。若另一个窗口已经为同一角色转移，必须重新读档。
- 每次成功转移自动保留该角色的最新转移后检查点。读档界面显示“馆藏转移检查点：角色名”，可读取后另存，不能手动覆盖或删除。未曾手动保存的角色也可从这里恢复。
- 载入早于一次馆藏转移的角色存档时，自动恢复最新转移后检查点并明确提示；这会替代旧存档中的角色进度。普通文件、原生槽与原生备份都遵守此边界。

## 持久化边界

Tauri 的 `app_local_data_dir()/profile/museum.json` 是一次转移的唯一提交文件，同时包含馆藏、资料身份、角色转移序号及对应检查点。检查点内部仍用 `.rfbsave` 编码。独立的 `museum.lock` 使用操作系统文件锁，进程退出即释放；多个窗口/进程不能并发提交。

转移在克隆的 Rust 游戏状态上执行，验证成功后，把馆藏和转移后的角色检查点一同写到 `museum.pending`，同步文件后原子替换正式资料。替换成功才发布内存状态。提交前中断保留原所有权；提交后中断由新检查点恢复。残留 pending 文件不是恢复候选，不会把旧馆藏回滚回来。损坏资料直接报错，不自动重建或退回旧副本。

每个角色有资料内分配的稳定身份和单调增加的转移序号。序号落后的存档不能重新贡献旧背包；同角色的过期窗口不能保存或转移。不同角色使用馆藏版本检查阻止对旧物品选择执行命令。重复命令沿用核心的序列/版本拒绝，不重复转移。

跨角色导入由 `Game` 分配新实例 ID，保留物品 DTO 的数量、设备状态、属性与捕获对象，并合并相关已知信息；未鉴定物不会因检视被鉴定。导入复用完整存档校验，避免与接收角色的实例 ID 冲突。城镇尚未生成时延迟导入，不新增第二套核心馆藏状态。接收外部馆藏后，回放从新的权威初始状态开始一段；不宣称外部资料变化可以由先前的纯命令回放重现。

## 范围与验证

当前协议、保存与状态哈希版本见[状态快照](status.md)。资料绑定不进入规则状态哈希；核心命令工具仍可独立运行。Tauri 是当前接入该本地持久化的客户端。

核心测试覆盖两城同库存、Home 独立、捐赠细节、检视，以及导入后的设备状态、捕获对象、知识与 ID 完整性。桌面原生层测试覆盖跨角色取放、旧存档恢复、重复命令、过期会话、资料拒绝、真实子进程在提交前后退出和跨进程竞争取出。此批未进行桌面 UI E2E、整段步行专项测试或 standalone 产物重建。

开发从新角色开始，不兼容旧开发存档。迁移角色需要保留原本地资料，不能只复制一个角色文件。防回滚范围是应用读取旧角色存档，不包含用户手改文件或整体回滚馆藏资料。中断验证针对进程退出，不把它表述为断电/磁盘硬件故障测试。当前逐次原子重写资料文件，尚未针对大量角色检查点做性能验收。

当前存入入口只接受背包；原版装备、箭袋和袋内直接捐赠以及 ORIGIN_BLOOD 来源标记尚未扩展。
