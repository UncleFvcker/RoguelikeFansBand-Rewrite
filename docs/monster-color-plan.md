# 怪物配色与 unique 流动渐变计划

状态：第 1–3 步已实现，前端／原生偏好回归与普通 EXE 的 unique 渲染 profile 通过。实际视觉可读性、后台／减少动态效果及多 unique 长时间性能仍保留人工验收；见[发布验证](release-0.0.1-validation.md)。

已确认：unique 使用**缓慢流动的彩虹渐变**，保留原来的怪物字符形状。普通怪物复用地形的稳定 ID 配色匹配方式，并非取所在地格的颜色。

## 已落地的修改与待验收范围

- 三个内置 tileset 已为 1,396 种怪物提供明确前景色：1,386 种通过现有 allocation 索引或导入选择表对应 RFB；10 种原创遭遇在同步脚本中单列项目配色。保留图片、字形和背景映射。可用 `python scripts/sync-monster-colors.py D:/codex/Frogcomposband/master` 更新来源色；脚本读取 Git 对象并输出实际来源提交。本次读取 `r_info.txt`、`init1.c::color_char_to_attr` 和 `variable.c` 的 32 色表；基础 16 色继续参与现有用户调色板替换，扩展色保留原 RGB。
- 地图消费 `monsterRecall.unique` 与已投影的实体种类，不新增协议或存档字段。补齐身份／unique 知识变化及实体移除时的局部显示更新，完整快照清除旧格缓存；模糊感知、幻觉、记忆格和玩家字符不启用效果。
- 现有字符 Sprite 复用地图共享的渐变 Filter，以原字符透明度着色并加细黑边；提供 WebGL / WebGPU 程序。约 8 秒流动一轮，只更新相位参数，不逐帧生成图集或重建地形。无可见渐变字符、后台或减少动态效果时移除动画回调；释放地图和复用分块时清除效果。
- 视觉编辑器已有流动／静态／普通配色选项及字形预览，保留显式前景覆盖优先级。前端和 Tauri 同步偏好校验；既有版本 5 偏好仅在缺少新增字段时补默认值，保留其余设置，非法值仍报错。PRF 不输出应用专用动画设置。
- 实际运行边界：真实图片保持原像素，渐变用于 ASCII 和图片缺失时的字符回退。Pixi 的软件 Canvas 回退不能执行自定义 GPU Filter，因此沿用普通怪物配色；不将字符错误染白。流动渐变的验收目标为 WebGL / WebGPU。
- 已有配色、偏好优先级／读写、身份隐藏与移除、快照替换测试通过，普通 EXE 渲染 profile 已包含 unique 字符并通过。渲染冒烟不等于完成全部视觉和性能验收。

以下保留实施与验收清单，完成验证前不标记为全部完成。

## 当前实现与缺口

- 地形与怪物已经共用 tileset 的稳定 ID 映射、16 色调色板和用户覆盖设置。现有视觉编辑器已有怪物分类，应扩展现有入口，不另建编辑器。
- 怪物视觉目录通过 `allocation.legacy_index` 关联原版 `R:{index}`。原版 `lib/edit/r_info.txt` 的 `G:` 行提供字符与颜色；需要核对现有映射的覆盖范围，不能按字符或名称猜颜色，同字符的不同怪物可能颜色不同。
- 当前 `GlyphAtlas` 生成白色字符纹理，`TilesetRuntime` / `PixiRendererBackend` 通过单色 tint 染色。单纯切换 tint 只能让整个字符变色，无法实现字符内部同时存在多种颜色的流动渐变。
- `ResearchMonsterDto.unique` 已有权威唯一性信息，玩家投影中已有怪物回忆目录。优先复用其知识门槛；`EntityDto` 与视觉目录目前没有直接的 unique 字段，不先增加存档状态或维护前端 unique 名单。

本批实际查阅的 RFB 来源：`D:/codex/Frogcomposband/master` 的 `master@a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`，通过 Git 对象读取。普通配色参考该来源；所有 unique 的流动彩虹是用户指定的显示效果，不宣称原版采用同样规则。

## 实施顺序

### 1. 普通怪物按稳定 ID 匹配颜色

- 审核三个内置 tileset（`ascii-default`、`image-demo`、`rfb-pixel-28`）的怪物映射以及现有资源生成入口，补齐缺失或错误的来源颜色。复用现有资源流程，避免建立第二份运行时配色表。
- 以原版怪物索引关联 `G:` 颜色，再接入已有 16 色调色板替换；核实原版颜色字符的解析。多色等特殊显示旗标与 unique 身份分别处理，不能相互替代。
- 保留明确的用户颜色覆盖。未知身份继续使用现有模糊显示，不通过实际怪物的配色提前揭示身份。
- 图片 tileset 的真实贴图继续按现有图片规则显示；其字符回退与 ASCII 模式使用相同颜色解析。本批流动渐变的目标是字符，不给整张图片套彩虹滤镜。

主要落点：既有 tileset 映射及资源生成入口、`visual-preferences.ts`、`tileset-runtime.ts`。若实际需要修改正式内容定义，同步正式包版本与 lock；仅视觉资源变化不无故修改游戏状态契约。

### 2. 给已识别的 unique 字符增加流动彩虹

- 从核心投影获取 unique 身份，先确认 `player.monsterRecall` 足以覆盖可显示身份的地图实体；若存在真实缺口，只在相同身份公开边界补最小投影字段，并按项目命令生成绑定。
- 保持字符形状、字号和位置不变，在字符内部呈现连续彩虹带，沿固定斜向缓慢流动。初始视觉参数采用约 8 秒一轮，无闪烁、缩放或快速明暗跳变；最终桌面验收时调整可读性。
- 优先复用现有字符纹理的透明度作为遮罩，用局部渐变 shader/material 着色；资源和参数定义共享，避免每个怪物复制完整图集。实现前核实当前 Pixi 渲染后端与接口，选覆盖实际运行后端的最小方案，不预造多套渲染路径。
- 渐变不能再经过普通单色 tint 或被 `ensureContrast` 整体改成黑白。检查亮地形、暗地形和光照叠加下的轮廓，必要时仅给字符加细描边。
- 宠物背景标记、目标/路径标记与 unique 前景效果分别保留；玩家角色沿用现有玩家显示规则。

颜色优先级：**用户对该怪物显式指定的前景色 → 已开启的 unique 渐变 → 怪物基础色及调色板替换 → 现有缺失映射回退**。只覆盖字符形状不关闭渐变；清除显式前景色后恢复渐变。

主要落点：`render-world.ts`、`tileset-runtime.ts`、`pixi-renderer-backend.ts`；仅按需要扩展字符材质与运行时视觉类型。

### 3. 接入现有设置并限制动画开销

- 在现有视觉设置中增加一个 unique 显示选项：流动彩虹（默认）、静态彩虹、普通配色。静态选项用于减少动态效果；不增加任意渐变编辑器或一组速度滑块。
- 怪物编辑预览使用同一解析规则，能看见显式前景色覆盖的结果；恢复默认和持久化沿现有流程。同步前端与 Tauri 的偏好类型、默认值和严格校验。
- PRF 继续遵守原有单色格式，流动效果由应用偏好保存，不伪造 PRF 指令。已有 PRF 单色覆盖遵守上述优先级。
- 接入现有绘制周期，按实际经过时间更新可见 unique 的相位，不调用游戏命令、不消耗游戏 RNG、不依赖回合推进。
- 没有可见的渐变字符、页面进入后台或地图销毁时停止相关动画更新；尊重系统减少动态效果偏好，显示静态彩虹。返回前台不补播积压帧。
- 每帧只更新动画所需参数；不重新生成字符图集、不重新解析偏好、不触发地形分块重建。切换字体、tileset、偏好和地图时正确释放旧材质及动画订阅。
- 模糊感知、幻觉和隐藏实体不携带真实 unique 效果；怪物离开视野、死亡或换层后清除原格残留效果。渐变保留现有可见性与光照遮罩的层次。

### 4. 修改完成后统一验证

- 配色：同字符的不同怪物按各自 ID 取色；原版索引与色值对应正确；调色板、单怪覆盖、重置以及图片模式的字符回退生效。
- 身份：普通怪物、已识别 unique、unique 宠物、模糊感知、幻觉、离开视野、死亡与换层，均遵守身份和可见性边界。
- 显示：字符内部同时出现多种颜色并缓慢移动，等待时也持续；深浅地形和光照下可辨认；前景覆盖优先、宠物背景仍在、减少动态效果时静止。
- 生命周期与性能：比较关闭渐变、单个和多个可见 unique 的帧耗时及移动响应；确认动画不重建地形/图集、资源不会随地图切换持续增长，后台没有相关更新。
- 复用 `visual-preferences`、`tileset-manifest`、`render-world` 的相关测试；按实际修改补偏好持久化和身份投影覆盖。字符渐变与动画必须在真实桌面渲染中验收，不能用纯数据断言代替效果验证。
- 本轮不执行上述检查。最终需要可玩产物时使用 Tauri standalone；不创建 NSIS。

完成标准：普通怪物颜色可追溯且服从用户覆盖；已识别 unique 字符显示缓慢流动彩虹；不泄露隐藏身份，不导致地图或输入卡顿。
