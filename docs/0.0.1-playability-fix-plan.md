### F1：恢复长按移动

实现待验收：普通移动记录本次物理按键及解析方向，后续只消费该键的系统重复事件；忙碌时丢弃重复事件，松键、失焦、点击、阻塞界面和会话重置清除按键状态。自定义方向键复用首次解析结果，避免重复展开宏或菜单。已补 `input-controller.test.ts` 用例，但尚未执行。

- 在输入解析中只允许普通方向移动处理系统重复按键事件，继续限制施法、交易、菜单、计数前缀和宏等一次性命令的重复触发。
- 复用当前按键预设、方向映射和命令分发；优先使用系统按键重复，不先增加定时器、输入队列或另一套连续行动状态。
- 分发忙碌时不积压移动；松键后不能继续消耗排队命令。处理失焦、弹窗、输入框、命令阻塞和游戏结束。
- 明确与跑步、自动探索、重复上一命令的交互，避免重复移动事件中断或重启已有自动行动。

落点：`web/src/input-controller.ts`、对应测试；仅在现有分发确有缺陷时跟进调用方。

验收：原始/roguelike 预设及自定义方向键，单击只走一步、按住持续移动、松开停止；慢 IPC 无积压；失焦/弹窗不继续移动；菜单和交易长按不重复执行。真实桌面验证键盘长按，不能只用逐次 dispatch 代替。

### F2：自动开门、规则拾取、记忆物品

实现待验收：共享局部寻路允许 `easy_open` 下的已知可开启门，travel/auto-get 转换出的移动复用现有开门动作；探索和前端连续行走将开门成功视为进展。每步重新选择规则物品，起步与途中均走 `AutoGet`，不再借普通拾取绕过规则；探索关闭拾取时也不调用移动后的普通拾取。全新偏好默认启用 Mogaminator、选择 `Wanted`，已有显式关闭偏好照常注入，不覆盖。确认规则仅在脚下触发，满包或无进展停止。

记忆显示消费现有 `discovered` 投影与记忆色，不新增世界记忆副本。对照上述来源提交的 `src/cave.c::map_info` / `wiz_dark`、`src/melee2.c` 拾取分支：显示已标记物品，遗忘或怪物拿走时清除地图发现标记，保留实例鉴定。存档校验同步允许地面/怪物携带物品保留“已鉴定但地图位置未知”的状态，其他鉴定与引用校验保留。

边界：锁门仍走原有一次开锁检定；失败按本项目无进展规则停止，不自动无限重试。RFB `src/cmd1.c` 的 `door_hack` 会在 travel 的步数预算内允许重试，此处保留项目的失败停止行为。卡死门和未发现的暗门不新增可行路径；有穿墙等能力的角色保留原有通行规则。

## 火把堆叠与新货燃料（代码已修改，待统一验收）

来源为同一 `master@a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`：`obj.h::OBJ_STACK_MAX` 为 99，`obj.c` 合堆要求相同灯具燃料；`py_birth.c` 的出生火把为 3–7 根、每根 1500–3500 燃料；`shop.c::_create` 将商店新生成的火把／提灯补到燃料上限。出生赠品和随机掉落不必满燃料，不改成统一满值。

木制火把原 `maxStack=1` 与出生逐根创建导致无法堆叠，现改为最多 99 根且出生同燃料合成一堆。装备保留选中物品 ID，拆出一根点燃，剩余堆叠分配新 ID 并复制知识；卸下／换装按既有属性、燃料、铭文及知识条件合堆，容量预检计入实际合并结果。装备仍只允许一根，补充燃料只消耗一根；不同燃料、不同属性／知识不能混合。火把改为可堆叠后，保留其词缀生成及各存储位置的品质校验。新生成商店火把／提灯补满，玩家售出的旧灯具保持原燃料。

已调整出生用例，新增拆装、单根燃烧／补充、丢弃拾取合堆、满背包卸下、保存恢复、商店重复购买／补货用例，并保留旧火把卖出买回的燃料断言；尚未执行。包版本改为 1.485.0，内容编译与 lock 更新遵照用户安排推迟到统一验证，现有 lock 仍记录上一版，不能据此认定内容同步完成。出生和商店实例减少会改变后续实例 ID／初始状态哈希，统一验收需解释后刷新实际受影响的保存／回放／契约预期，不因此升级哈希结构版本。

## 验证与交付

- 每批先复现并补缺失的最小有效回归，再修复。F1/F4/F5 运行对应前端测试和 typecheck；F2/F3/F6 运行实际受影响核心模块及调用者测试。
- 例如前端在 `web` 执行 `node --test src/input-controller.test.ts` 或对应的 `render-world`、`inventory-panel`、`shop-panel`、`status-panel` 测试文件，再执行 `npm run typecheck`。
- 核心在根目录使用明确模块过滤，如 `cargo test -p rfb-core --lib game::tests::auto_explore::`、`cargo test -p rfb-core --lib game::tests::berserker::`；鉴定按审计找到的真实调用者选择，不能只用 `inventory` 过滤便声称全部覆盖。
- 公共默认值、共享投影、认知持久化或 RNG 改变时，执行相应保存恢复、回放和受影响全局契约。先解释行为差异，再更新 fixture。
- 内容修改更新正式包版本与 lock；类型变更才生成相应 Schema/协议绑定。纯显示改动不升级状态哈希 Schema。
- 集成后从新存档做聚焦普通 Tauri standalone 验收，使用 `npm run build:standalone:debug`；需要优化版验收时用 `npm run build -- --no-bundle`。不生成 NSIS，不因本计划自动发布新 release。
- 完成证据覆盖：真实长按键 → 自动开门探索 → 规则拾取 → 记忆物品 → 鉴定前后名称/详情 → 商店买卖 → 狂战士归还。只有执行过的流程可以写为通过。
- 不默认跑 Android 或无关全量测试；完成后按七项用户反馈逐项报告修复、验证和剩余限制。
