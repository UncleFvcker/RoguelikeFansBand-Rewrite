## 全阶段共用的数据约定

- 原生应用数据目录的独立 `preferences.json` 是唯一全局持久来源。标题页与游戏内设置、视觉编辑、导入和 Mogaminator 使用同一版本结构、校验与提交路径，不另建 PRF 运行文件或自动拾取配置副本。
- 文件缺失使用明确默认；文件损坏报错并保留原文。保存复用现有原子写入模式及修订校验，写入失败不应用新运行配置；陈旧编辑保留草案并报告冲突。Game 不自行读磁盘。
- 角色保存保留实际角色／世界事实。全局偏好变更不覆盖创角规则，不删除地图知识，不重写物品铭刻、悬赏对象或宠物指令，不触发拾取、销毁、使用物品或 RNG。
- 纯显示设置在应用后立即刷新，不进入规则状态哈希。改变操作行为的配置在当前命令结束、连续行动停止后注入 Core；尚在编辑的草案不影响游戏规则。
- 回放独立记录影响行为的初始配置及后续变更；验证使用回放自己的输入，不读取或修改观看者的本机偏好。存档解耦不意味着从确定性验证中删掉行为上下文。
- 已有合法 localStorage 值只迁入一次；已有全局文件不被旧键覆盖。迁入成功后停止旧读写；笔记、成绩、馆藏和会话寄存器不纳入偏好迁移。开发存档不增加旧格式兼容层。

## O2 — 全局存储与统一设置入口

实现状态：已编写，等待 O8 后验收。原生 `web/src-tauri/src/preferences.rs` 保存 `{ revision, preferences }`（O3 扩为格式 2），位置为 Tauri `app_local_data_dir()/preferences.json`；JSON 交换文件只包含 `preferences` 正文，不携带本机修订。独立锁文件、临时写入替换和预期修订避免并发覆盖；损坏文件保留并报错。前端 `PreferencesClient` 统一读取；只在原生文件缺失时迁入六个旧 localStorage 键，成功保存后才清理合法旧值，失败可重试。

标题与游戏设置共用 `SettingsPanel`：现有五项选择、自定义键位导航、搜索／默认说明、草案差异、显式保存与默认预览；JSON 导入先预览再保存。自定义键位编辑器改用同一修订提交，无角色时可编辑；失败保留草案，运行映射只取已保存快照。Mogaminator 仅在有角色时提供现有编辑器导航；O3 已将旅行选项和 Mogaminator 编辑迁入同一全局提交路径。

待验收用例：原生非法值／文件损坏／锁冲突／陈旧修订／写入失败；前端迁移及中断重试、JSON 校验、设置草案取消／保存／导入／默认、无角色键位编辑。相关 E2E 已改为操作统一设置页面并等待持久保存，不再写旧设置键；O8 执行时须隔离原生应用数据，或在无其他游戏实例写入的条件下备份并恢复偏好，不能仅隔离 WebView localStorage。O2 未改 Core 类型，无本批 Schema／协议生成项；没有运行这些用例或任何编译。

目标：先让已有界面偏好跨角色、跨重启使用同一份设置。

1. 增加原生偏好加载／保存及版本、修订、边界校验，复用现有存储设施。只定义本批有消费者或后续已明确需要的配置，不搭建通用配置框架。
2. 迁入语言、键位方案、自定义映射、镜头、缩放和图块。保留当前默认：zh-CN、numpad、居中镜头、缩放 1、ASCII；合法旧值优先。
3. 标题页“设置”与游戏内 `=` 共用设置页面、分组、搜索、说明、保存和恢复默认。键位与图块各有一个选择控件。
4. 建立高级导入与备份区域，JSON 负责已接入全局偏好的完整导出／恢复，后续字段随同一格式纳入。导入先预览，再共用保存流程。
5. 自动拾取只提供进入 Mogaminator 的导航；字形、配色和 PRF 功能随对应阶段接入，不提前放无效果页面。会话宏中含实体／物品 ID 的数据不持久化。

交付：原生存储、前端单一配置读取路径、统一设置入口、JSON 备份恢复与迁移代码。O2 不提前宣称角色保存已解耦，那是 O3 的交付。

后续验收：无角色可设置；换角色／重启值一致；非法输入、文件损坏、写入失败、陈旧编辑和迁移中断不覆盖原有效配置。

## O3 — 角色存档解耦与确定性回放

实现状态：已编写，等待 O8 后生成与验收。`SavePayloadV1` 移除旅行、语言和整块 Mogaminator 数据，仅保留角色悬赏 ID；物品铭刻、知识、宠物与连续行动事实保持角色所有。Core 新建／加载接受显式行为配置，原生入口读取已保存的全局文件；既有测试／工具便利构造仍使用固定默认值。默认双语规则由 Core 提供给原生和前端，前端不复制规则正文。

配置提交先保存全局修订，再通过零时间 `ConfigurePreferences` 应用到当前会话；原生拒绝绕过该入口的旧配置命令，以及与已保存全局值不一致的配置。应用清除待确认匹配和拒绝缓存，不重新处理物品、不推进时间或 RNG。加载保留连续行动事实，但前端不自动续发钓鱼等行动。Mogaminator 编辑保存期间锁定草案，失败保留文本和错误信息。

回放格式 2 记录初始行为配置及瞬时查询缓存，后续配置变更仍进入既有命令序列。验证先恢复回放自己的上下文，不访问本机偏好文件。角色保存的载荷校验和不含偏好；执行状态哈希及回放检查点仍含语言、旅行和 Mogaminator 上下文。该哈希输入结构未变，State Hash Schema 保持 145；配置切换导致执行哈希变化属于预期行为。原生槽位摘要的执行哈希使用明确默认上下文进行只读验证，不代表加载后使用当前全局配置的执行哈希。

待生成：Protocol 1.289、Save Payload Schema 41（Header 14 不变）的 Schema 与 TypeScript 绑定；Replay / Preferences 格式均为 2。生成文件仍是之前版本，O8 后统一生成，不兼容旧开发存档或尚未发布的 O2 偏好格式。待验收：Core 保存字段与配置注入、配置无物品副作用、查询缓存清理；回放在不同观看者配置下重现；原生跨新建／保存／加载读取全局值；前端阻塞选择期间更新配置、加载后连续行动不续发。直接调用加载 API 的既有用例和旅行设置 E2E 已随接口调整，均未执行。

依赖 O2 的持久化边界。目标：全局偏好不再跟随角色槽位保存。

1. 从角色保存拆出旅行四项、界面语言、Mogaminator 启用／策略与两语言规则正文。统一 Game 新建／加载的显式行为配置输入，更新原生、工具及回放调用者。

3. 载入后不自动续发保存中的连续命令；重新开始前按当前配置与实际危险条件检查。
4. 回放记录初始行为上下文和命令之间的配置变更，包括影响 Mogaminator 规则选择的语言；纯视觉项不进入行为记录。明确角色保存哈希、执行状态哈希和回放检查点的边界。

后续验收：存档无偏好正文；同一角色加载当前全局配置；改变本机设置不影响历史回放；重载不改变物品、悬赏、时间或 RNG；回放不污染本机配置。

自动探测／绘图的步前检查已由跑步、探索、旅行和自动取物共用，沿用设备／卷轴消耗；可见敌情先停止，不先消耗资源。探测独立于离开覆盖停止开关。便捷行走调用原有门／陷阱动作，显式综合交互保持独立；特殊行走临时翻转拾取和便捷拆陷阱意图。重试开关只控制省略次数的明显命令，次数前缀和重复上一命令仍按原语义执行。
