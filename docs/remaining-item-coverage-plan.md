## 目标与完成口径

逐批补齐当前游戏能实际获取、鉴定、使用或装备，并能保存恢复的原版物品。保留已完成的共享生成系统，按缺少的内容、规则、入口和证据拆分工作。
每批区分“定义存在、规则完成、入口可达、实际验收”；只有 JSON 或来源身份不能记作可玩覆盖。无自然分配、占位或特殊用途的源记录也要有明确归类，不能为了数量把它们全部放进掉落池。

本计划覆盖基础物品、固定神器、装置效果、特殊对象及书本依赖。新职业/种族、完整领域施法、任务与设施各自仍由原方向负责；物品侧交付共享定义和效果，实际交叉依赖按[并行协作](parallel-development.md)交接。
未开放身份或系统保留依赖；本轮可玩物品扩充完成不自动把 `runtimeParityComplete` 改为 `true`。

## 分批执行

### I0：校准覆盖清单

- 对照 `master` 的 `k_info.txt`、`a_info.txt`、`devices.c` 三类效果表，以及正式物品和真实获取调用者。将基础记录、神器身份和装置效果分别统计，名称逐字采用权威中文表/源字符串；无权威名记 unresolved。
- 校准现有选择/改编记录和底材报告，确认六个漏记 ID 的实际归属。复用 [base_allocation.rs](../crates/rfb-legacy-import/src/content/base_allocation.rs) 的同步路径；先看其输出影响，不把全包重导作为清单刷新步骤。
- 剩余项注明稳定 ID 或源 ID、当前缺口、获取方式、所需消费者和所属批次；分类为可用现有机制接入、缺少具体机制、等待身份/领域/地点、非独立可玩内容。复用现有记录；固定神器和装置仅补现有记录无法表达的对表信息，不新建一套通用审计框架。
- 旧 `audit-demo-items` 的 mechanics-ready 来自 importer 的 flags/行为支持判断，不等于自然入口或完整运行时验收；旧 P3 计划只作来源索引，不复活已完成待办。

完成标准：没有未归类的剩余源记录，已有物品没有被重复列为待导入；得到 I1 的明确首组 ID 和缺口。清单变化只做文档/记录检查；实际同步若改动正式内容则按内容变更验证。

### I1：补普通装备底材

- 优先处理现有数值、槽位、抗性和攻击表达已足够的底材：从 65 个装备候选中筛选普通护甲、头盔、盾牌、挖掘工具和普通武器。按机制族小批提交，具体数量由 I0 核实，不承诺一次补齐 65 件。
- 复用装备定义、估值、销毁、Ego、随机神器及基础分配路径。保留源等级、分配行、零概率和主题谓词，不能均匀撒入所有商店或掉落表。
- 龙鳞甲另作小批：复用已有底材生成，逐项核对抗性与激活，确认 Ego/随机神器生成后仍保留应有底材能力。毒针、死神镰刀等专属战斗分支留给 I4。

完成标准：实际生产分配路径生成目标机制族，鉴定/装备后属性、攻击或防御消费者正确；新实例保存恢复一致。候选池扩大引起的 RNG/契约变化有可解释差异，完成受影响契约检查。

### I2：装置效果与普通消耗品

- 先核对三类源装置效果表、当前别名物品、已有 effect program 和实际生成入口。已有激活或法术效果复用同一执行路径，但重新核对装置自身的难度、费用、强度、等级/模式筛选和充能恢复。
- 按实际缺失效果族接入自然装置生成；不为每个效果复制一种近似底材，也不把随机神器的 195 项激活池当成三类装置的完整原版效果表。
- source kind 368、465 分别追踪真实使用分支和现有能力；若缺机制，在本批补最小完整实现或明确转交对应依赖。source kind 364 留给 I3，不随普通卷轴直接开放。

完成标准：真实获取、未知/已知状态、选择目标、成功/失败/取消、费用和恢复，以及保存后继续使用都符合规则。狂战士等实际使用限制沿用职业审计；不能用“职业不能用”删除普通生成候选。

### I3：固定神器与神器创造入口

- 从 I0 的 `a_info.txt` 对表清单按“现有底材及消费者可用 → 当前可玩身份敏感 → 等待专属系统”排序，每个机制族单独交付。已实现的 14 件先复核身份，不重建同名物品。
- 补完整基础属性、flags/pval、诅咒、激活、普通/instant 生成、唯一性登记和获取限制。复用 [loot.rs](../crates/rfb-core/src/game/loot.rs)、现有神器物化及激活消费者，不另建神器工厂。
- 身份敏感神器和固定神器竖琴先查原版普通分支；当前职业有适用分支就同时实现，未开放身份保留依赖。同步审计输入及 `audit-egos.mjs` 中现有固定神器断言，不能只删除失败断言使新增内容过关。
- 神器创造卷轴（364）作为独立小批：追踪物品选择/拒绝、取消与消费、成品生成、命名登记、职业 bias、德行和保存。复用已有随机神器工厂；未完成真实入口前保持卷轴 gap。Inspired Smithing 重铸依赖对应设施/系统，单独交接，不混作卷轴完成。

完成标准：至少一个符合源规则的实际入口；唯一性、身份差异、激活/诅咒等真实消费者及恢复后的登记/RNG均有证据。测试明确标注受控前置，不把强制物化当自然获取证明。

### I4：特殊底材与交互对象

- 按源调用链分成小批：毒针/死神镰刀等战斗规则；箱子生成、陷阱和开箱；魔法雕像及目标怪物身份；骨骸、尸体、部位、雕像/照片；哨、号角、工具、铁钉等交互物。无当前消费者的专属对象保留具体依赖。
- 每组先确认当前模型是否足够；若确实需要新实例字段，先完成该字段的初始化、保存、哈希和消费者再开放物品，不给所有物品预造额外状态。
- 宝箱、任务或设施内容由实际入口方向使用同一物品 ID。金币先核对当前货币生命周期与原版生成，不强制物品化；占位和只用于特殊构造的底材不进入普通池。

完成标准：物品本身能完成对应交互，含必要失败/拒绝边界及生命周期；有来源限制的获取遵守来源限制。不能用无效果占位物关闭覆盖缺口。

### I5：书本与领域/职业依赖

- 逐一核对 43 个书本候选的实际消费者。Craft 的四册/32 法术属于完整领域接入工作，已有 Craft Ego 制作不代表该领域已完成。
- Chaos、Trump 及其他领域/职业书按真实能力、职业参数和入口分批接入。已有八领域、七个未开放领域的工作沿用当前[状态](status.md)，不重新导入已有 32 本书。
- 物品侧同时维护源书身份、获取、发现计数、等级/质量筛选、学习/销毁消费者；新领域 Build 按[生成接入闭环](content-development.md#职业与领域-build-的生成接入)补审计。未经领域/职业规则验证，不单靠摆出书本宣称可用。

完成标准：有完整领域/职业依赖的书本具备获取、发现、学习/使用及保存证据；尚未开放的依赖明确列出。已有领域的菜单开放和未导入领域的完整接入分别计数。

### I6：对象表示差异

- 复核 [B1/B5](../design/base-allocation-acquirement-plan.md) 保留的书本单实例、普通物品生成堆数，以及 `obj_can_combine` 的来源、铭文、折扣等差异。先列真实消费者和可观察差异，再决定最小状态变化。
- I1–I5 某组物品确实依赖这些语义时，将必要部分提前随该组实现；其他差异独立推进，不能作为所有内容接入的前置重构。
- 改动数量/合并语义时覆盖生成、落地、拾取、拆分/合并、交易、储存、销毁和发现计数中实际受影响路径，以及保存后的后续行动。不能靠存档默认值或刷新哈希掩盖丢失。

完成标准：逐项关闭有行为证据的表示差异；仍采用改编表示的项目写清边界，全原版完成标记据实保留。

### I7：本轮可玩范围验收

- 汇总本轮实际增加的源身份、效果、入口及未关闭依赖，核对正式报告和 Build 审计一致；没有新增影响的旧验证沿用已注明范围的证据。
- 对本轮新增的交互和机制族安排 Windows Tauri standalone：新角色 → 真实获取 → 鉴定 → 装备/使用 → 原生保存恢复 → 继续行动。稀有或高等级前置可受控准备，但必须明示，不能冒充自然练级。
- 单纯增加同机制数值内容不要求每件各跑桌面测试；新界面、目标选择、特殊实例等真实风险补对应检查。Android 与全仓构建不自动附带。

完成标准：可玩范围与证据对应，未完成项仍可追踪；不以文件数、构建成功或审计绿灯代替行为结论。

## 执行顺序与验证

建议先执行 **I0 → I1 → I2 → I3**，尽快增加当前角色能实际获得并使用的内容。I4 按机制族推进；I5 跟随领域/职业接入；I6 按实际依赖提前或单独收口；I7 在本轮选定的可玩范围完成后执行。大批按上述小组提交，不等所有原版系统开放才交付已完成部分。

每次先复查本工作树及主线已新增的物品 ID，防止与职业奖励或地点神器重复。只在同一状态/文件确实交叉写入时协调，不新增共享文件审批。
内容变化更新正式包版本及 lock，类型变化才生成对应 Schema/协议；按[内容开发](content-development.md)使用现有命令。普通候选池扩充仍可能改变全局 RNG 消费，按实际影响执行[验证与契约](testing.md)，说明差异再刷新必要 fixture。
新增物品触及职业/主题/神器条件时同步来源审计、生成矩阵和只读 CI 检查；通用物品不机械复制八职业全套测试，仅补实际差异与缺失证据。

本次规划仅核对 Git 对象、正式 JSON、审计输入与相关代码，检查文档链接、事实统计和 diff；没有运行游戏测试、生成审计、内容同步或桌面构建。下一步是 I0，尚未开始实施。
