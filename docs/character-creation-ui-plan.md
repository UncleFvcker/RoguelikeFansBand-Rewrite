# 创建角色 UI 改造计划

状态：第一、二步已实施并通过聚焦桌面验收；第三、四步尚未实施。

基准：Rewrite `main` 的 `1b4910bcf`。RFB 参考仓库为 `D:/codex/Frogcomposband/master`，通过 `git show master:src/py_birth.c` 读取；本次实际来源提交为 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`。实施前重新确认工作树与入口，保留他人修改。

## 1. 目标与边界

把目前纵向堆叠的职业卡片、种族下拉框和输入表单，改为与游戏内角色信息、物品栏一致的固定大面板。通过多级菜单浏览种族与职业，详情随当前查看项变化，姓名、已选组合和开始操作容易找到。

- 桌面外框采用物品栏现有的 `84vw × 84dvh`，面积约占视口的 **70.6%**。本计划把“占据屏幕 70%”解释为面积，直接对齐物品栏；尺寸以应用内容视口计算，排除系统标题栏。
- 使用现有深色背景、金色强调、直角边框、标签页和字体缩放规则，避免保留创角页独有的蓝色大卡片风格。
- 只重新组织已经开放的创角选项。基准代码是六个职业构筑、46 个种族叶子选项，其中包含九个龙人亚种。
- 保留姓名、完整 `u64` 种子、随机种子、返回标题和创建失败重试流程。
- 本批不开放新种族、职业、领域、性格、性别、怪物模式、属性分配或随机角色功能；不修改出生规则、RNG、保存格式或游戏状态协议。
- 角色信息面板是布局参考。创角前展示已有名称、说明和已确认选择；不调用正式初始化来生成预览，不在前端重算属性、生命值、法力或装备。

## 4. 面板结构

```text
┌────────────────────── 创建角色 ──────────────────────┐
│  概览           种族           职业          返回标题 │
├─────────────────────────────────────────────────────┤
│ 当前路径：种族 > 其他 > 龙人分支          返回上一级  │
├──────────────┬─────────────────┬────────────────────┤
│ 分类         │ 当前层选项      │ 正在查看的说明     │
│              │                 │                    │
│ 人类         │ 红色            │ 名称与所属层级     │
│ 精灵         │ 白色            │ 现有种族/职业说明  │
│ ……           │ 蓝色            │ 已实现的专项说明   │
│ 其他         │ ……              │                    │
│              │                 │                    │
├──────────────┴─────────────────┴────────────────────┤
│ 已选：姓名 / 种族与亚种 / 职业与领域                 │
│ 状态或错误                         概览   开始游戏  │
└─────────────────────────────────────────────────────┘
```

这是一张结构示意图，示意标签从现有本地化和原版分类取用，最终名称按实际 Fluent 键显示。

- **顶部**：主标签页“概览 / 种族 / 职业”和返回标题按钮。可以任意切换，不强制按步骤重复填写。
- **概览页**：沿用角色信息的名称—数值排版，显示姓名输入、种族/亚种、职业/领域以及对应修改入口。种子与随机按钮放在同页的独立设置区域。初始值沿用现有行为。
- **种族与职业页**：桌面采用分类、当前层选项、详情三栏，初始宽度比例约 `20% / 30% / 50%`，实际以字号和长名称可读性调整。选项是紧凑菜单行，长说明只出现在详情区。
- **路径栏**：显示当前分类和父项，支持返回上一级；不叠加第二、第三个模态弹窗。
- **页脚**：始终显示已确认的角色摘要和开始按钮。状态、错误预留位置，长文换行不把操作挤出外框。
- **滚动**：外框不滚动、不被内容撑高；分类、候选列表和详情必要时内部滚动，使用 `min-height: 0`。标题、路径和页脚常驻。

### 尺寸与窄屏

- 普通桌面外框固定为 `84vw × 84dvh`，保留现有最大宽高边距约束，分页或展开说明不改变尺寸。
- 在 1280×720、截图相近的 1280×820 内容视口、1920×1080 和 2560×1440 下检查，不使用全局 CSS zoom 或缩小整页文字来塞内容。
- 视口宽度不超过 900 CSS px 时，分类改为可切换的横向导航，保留候选与详情两栏。
- 不超过 640 CSS px 或高缩放使可用宽度不足时，候选与详情改为同一面板内的“选择 / 说明”切换；外框可扩大至距视口边缘约 `0.5rem`，以可读和操作可达优先。选择器有自己的局部滚动，不恢复成长表单。
- 窄屏规则用明确媒体查询实现，不引入布局状态管理器；边界值在实际桌面验收时校准。

### 职业

| 原版分类 | 当前职业 | 后续层与最终构筑 |
| --- | --- | --- |
| 近战 | 战士 | 直接选择 `demo.build.warrior` |
| 箭术 | 弓箭手、狙击手 | 分别选择 `demo.build.archer`、`demo.build.sniper` |
| 魔法 | 高阶法师 | 进入领域层，目前只有死亡；选择 `demo.build.high-mage-death` |
| 混合 | 圣骑士 | 进入领域层，目前只有死亡；选择 `demo.build.paladin-death` |
| 骑乘 | 骑兵 | 直接选择 `demo.build.cavalry` |

只有一个领域也明确呈现领域层和“当前可选领域：死亡”，让领域从职业卡片名称中分离。内容包已经定义的其他领域不自动开放，不显示不可用选项墙。当前无子职业叶子，不添加空的子职业页面。

### 查看、确认与返回

1. 焦点移动或查看候选项时更新右侧说明；“正在查看”与页脚“已选”分开标记。仅浏览不改最终请求。
2. 激活分类或父节点进入对应菜单；激活最终叶子提交该项到创角草稿，更新勾选和摘要，不立即创建游戏。
3. 亚种/领域未选完时禁用开始按钮，并提示完成该分支或返回。取消未完成分支保留此前已确认的组合。
4. 返回上一级恢复父项焦点。切换主标签页取消未确认分支，保留已确认姓名、种子、种族和构筑。
5. 切换到普通种族后不残留旧龙人亚种；切换到战士后不残留旧死亡领域。摘要从最终 `raceId`、`buildId` 派生，不独立存一份领域或亚种状态。
6. 从概要修改已有项时定位到已选叶子及其分类。返回标题再进入创角沿用当前会话草稿；现有显式随机种子的入口继续按调用参数生效。
7. 开始时沿用姓名与种子校验。发生错误则定位对应页面和字段；请求失败保留草稿、恢复可操作状态；忙碌期间导航、修改、返回和重复提交一并禁用。

### 键盘与可访问性

- 主标签页沿用 `tablist / tab / tabpanel`，方向键切换标签，选中状态与焦点状态分别可见。
- 分类、父节点和叶子使用原生 `button type="button"`，叶子以 `aria-pressed` 标识已确认项；不把“移动焦点仅查看”的行为套在方向键本来就会更改值的原生 radio 上，也不自建 ARIA 树组件。
- Tab 在区域和操作间移动，当前列表保留一个顺序 Tab 焦点入口，方向键移动查看项，Enter/Space 确认当前叶子或进入子层。切层时恢复对应焦点，按钮焦点框与已确认标记分开显示。
- Escape 逐级返回，顶层返回标题；正文输入框内编辑、中文输入法合成期间不触发菜单快捷操作。只有显式激活开始按钮或概要提交才创建游戏，子菜单 Enter 不误提交整个表单。
- 错误、选择变更和忙碌状态有适当 live region；说明有可关联标题；焦点不会落到隐藏页，也不会穿透到不可见游戏区域。

- 菜单测试覆盖叶子集合与分组、不完整分支、确认/取消和最终请求；保留现有姓名与完整 `u64` 种子的边界测试。不要为每个叶子复制一份游戏开局测试。
- 在现有 Tauri E2E 中增加聚焦创角验收入口（如 `--character-creation`，实施后才视为可执行命令），通过可见菜单操作验证主要分支和截图。迁移并运行直接受创角选择器变化影响的既有场景，按实际调用范围选取。
- 最终提供 `npm run build:standalone:debug` 产生的试玩程序；桌面自动化可使用 `npm run e2e:build` 的 WebDriver standalone。分别注明构建通过与实际执行过的验收，不把二者混为一谈。
- 纯 UI 改造不默认运行整个 Rust workspace、全量契约、Android 构建，也不刷新状态哈希 fixture。若出现真实核心调用变化，再按[验证与契约](testing.md)扩大范围。

最初规划交付只检查文档链接、代码及来源依据与 `git diff --check`。实施后在提交说明记录实际证据；当前指南只更新持续有用的范围，不追加版本流水账。

### 当前实现与实际验收范围

`node e2e/tauri.e2e.mjs --character-creation` 已成为可执行的聚焦桌面检查。Tauri WebDriver standalone 在1280×720内容视口下确认外框约1075×605、姓名和开始按钮可见、三个页面切换、Tab标签方向键与返回、姓名/种子错误从其他页定位回概览，以及返回标题后保留选择；中英文概要截图已检查。最终创建红色龙人死亡高阶法师，核对游戏内姓名、种族、构筑和种子。报告及截图输出到本机 `test-results/character-creation-acceptance.json` 与 `test-results/creation-*.png`。

种族、职业目录和两页共用的局部菜单集中在 [character-creation.ts](../web/src/character-creation.ts)。八个种族分类的中文、顺序及归组来自上述原版提交的 `b_race_groups`，不包含没有开放入口的“变形者”；九个龙人亚种归入“其他”的龙人父节点。五个职业分类来自同文件的 `_class_groups`，死亡名称对应同提交的 `src/tables.c`。叶子导出创角白名单；种族名称、说明键与正式Race数据一致，四种专项提示沿用已有Fluent文本，龙人亚种沿用正式数据指定的共同种族说明。

原种族select、四个独立说明DOM及六张职业radio卡片已移除。菜单把正在查看项与已确认项分开：方向键/焦点及悬停只更新详情，激活叶子才确认；进入未确认的亚种或领域分支禁用开始，返回父层或切换主页面取消分支并保留已确认组合。返回父层恢复父项焦点，从概要修改时定位已选叶子。高阶法师和圣骑士都明确进入领域层，目前各自只有死亡；普通职业直接选择，转回战士不会残留死亡领域摘要。职业父项使用现有Class名称和说明，领域叶子沿用现有Build说明；没有改变正式内容、初始化请求或Rust规则。

聚焦桌面脚本逐一选择46个种族和6个构筑，检查说明、四种专项提示、两个领域分支的取消、主页面取消、父项焦点、普通种族与职业清除子层摘要，并实际创建红色龙人死亡高阶法师。脚本在原生创建请求边界模拟一次延迟及失败，验证全部控件禁用、重复提交受阻、错误可见、草稿保留，以及重试请求的姓名、种子、种族和构筑完全一致。报告输出到 `test-results/character-creation-acceptance.json`；中英文职业/领域与失败恢复截图和已有种族截图均位于 `test-results/creation-*.png`。现有会话、种族专项和生命力脚本已通过辅助函数操作可见菜单；供给与Ego脚本没有依赖旧选择控件，无需改写。

### 响应式与键盘验收

宽度不超过900 CSS px时，分类横向排列并支持左右方向键；不超过640 CSS px时提供“选择 / 说明”切换。说明页的返回或Escape先回到选择，恢复候选项焦点；跨越窄屏断点时恢复到可见控件。菜单重绘时静止指针不会覆盖键盘预览，鼠标移动仍可查看候选项而不改变确认结果。低高度窗口紧凑排列路径栏，错误区限制高度并支持Tab和End滚动；外框使用不可滚动的裁切边界，滚动说明或错误不会移动标题与开始按钮。普通桌面窗口启用Tauri原生缩放快捷键，原有最小窗口尺寸保持不变。

`node e2e/tauri.e2e.mjs --character-creation` 同时运行入口/提交检查和 [布局及键盘检查](../web/e2e/character-creation-layout.e2e.mjs)；单独调试后者可用 `--creation-layout`。中英文均验证1280×720、1280×820、1920×1080、2560×1440、900×620及390×844视口；另在原生200%缩放下验证640×360和450×310 CSS视口。390像素测试通过专用E2E权限临时解除窗口最小尺寸，普通试玩程序没有这些权限。报告记录尺寸、缩放后的像素比例、操作边界及详情可滚动范围，长姓名与长错误另有检查。

键盘检查经WebView2 CDP发送真实浏览器按键，覆盖Tab/Shift+Tab、方向键、Home/End、Enter/Space确认、逐级Escape、姓名/种子编辑、随机种子、返回标题保留草稿和开始游戏。实际从新存档创建人类战士、红色龙人死亡高阶法师、骷髅死亡圣骑士，核对姓名、种族、构筑与种子，并各执行一个有效回合动作。结果页路由使用一次仅供UI测试的退休终局投影；其“新建角色”随后创建真实Rust会话，验证保留选择、重新随机种子并再次行动。该路由测试不代表完成了整个战役退休流程。

布局与开局报告为本机 `test-results/character-creation-layout-acceptance.json`；尺寸、窄屏选择/说明、键盘确认及长错误截图为 `test-results/creation-*.png`。常规 `npm run build:standalone:debug` 生成试玩程序；上述实际自动化使用 `npm run e2e:build` 生成的WebDriver standalone，其调试端口和视口权限仅在专用构建中启用。当前完成Windows/WebView2自动化和截图检查；IME覆盖合成状态防误触，未进行系统中文输入法、屏幕阅读器或Android的人工验收。
