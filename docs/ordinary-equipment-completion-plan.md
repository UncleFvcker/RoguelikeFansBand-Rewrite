- 不把全固定神器、未开放身份、全部原版生成行为或 `runtimeParityComplete` 的关闭捆入本轮。已有186件沿用各自已记录证据；本轮池变化触及的既有行为仍须回归。

## 每批检查与最终收口

1. **定向导入。**复用 `sync-demo-items`，只选择本批 source kind；同步现有 selection／adaptations、分配报告及逐项清单，不全包重导。名称、W/A/P、销毁及品质资格逐项核源。内容变动更新正式包版本和lock；命令见[内容开发](content-development.md)。
2. **按实际影响验证。**优先复用 `game::tests::items` 的 B组、`loot::allocation`、装备／挖掘、Ego／随机神器、源C估值、本地化与来源检查；新增有效行为缺口才补测试。新底材改变普通池后，检查直接依赖完整候选池的既有测试；概率样本变化必须解释，不提升概率使之通过。
3. **生成责任审计。**复用 `generation-build-applicability.json`／`audit-egos.mjs`，记录当前已开放Build的差异或无差异依据；矮人主题、骑乘、法师护具和死神镰刀的决斗者分支按真实消费者验证。共享规则用代表性行为覆盖，不逐Build复制同一矩阵，也不另造一份全量底材审计框架。
4. **状态和契约。**纯内容变化不因 `contentHash` 刷 fixture 或升级 State Hash Schema。若镰刀实现改变公共状态、RNG调用链或协议投影，则按实际范围执行 active 契约；类型变化才生成 Schema／绑定，不手改生成物。检查范围与命令见[验证与契约](testing.md)。
5. **阶段实际验收。**五批完成后，用新角色在 Tauri standalone 做聚焦装备流程：代表武器／挖掘、重甲／固定附魔、泳装激怒、镰刀普通攻击／反噬与保存恢复。高深度／稀有内容允许显式准备，但准备与自然生成证据分开说明；核心已验证的概率边界不在桌面重复堆矩阵。不自动扩成全职业、全地牢、全前端或Android验收。
