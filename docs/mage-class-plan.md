## 选择：下一职业做法师

| 候选 | 当前可复用基础 | 主要新增工作 | 判断 |
| --- | --- | --- | --- |
| **法师（Mage）** | 八领域、32 本书、选择学习、MP/负重、法术进度、吞噬魔法、装置及生成规则 | 双领域学习预算、主副熟练度、重复研习、改换第二领域及全部消费者 | **优先**。补齐书本施法的一项实际缺口，玩法也与刚完成的两个近战职业不同 |
| 游侠（Ranger） | Nature、射击、随机学习和探查效果 | 固定自然＋第二领域、职业法术表、弓射加成与随机学习交叉 | 排在法师之后；同样需要双领域，先由法师完成这一调用链更清楚 |
| 食魔者（Magic-Eater） | 本轮合入的真实装置与充能/使用路径 | 每种装置 10 个体内槽位、吸收/替换、再生充能、独立保存和 UI | 后续候选。原版保留体内装置实例，不能把它做成法师的“吞噬魔法” |

这是按当前调用链和交付价值排序，不按职业源文件长短排序。法师的职业文件较短，但双领域状态会影响学习、掉落、自动拾取、公会及保存；整体工作量中等偏大。

## 本轮范围

交付**现有八领域范围内的可玩法师**：普通创角选择两个不同的领域，按原版法师参数学习、施法、成长至 50 级，并能通过学习其他受支持领域的书改换第二领域。当前开放种族按源允许组合接入，不只允许人类。

| 本轮支持的源领域名 | 现有稳定 realm ID |
| --- | --- |
| 生命、咒术、自然、死亡 | `life`、`sorcery`、`nature`、`death` |
| 奥秘、恶魔、圣战、毁灭 | `arcane`、`daemon`、`crusade`、`armageddon` |

原版法师的第一、第二领域候选均有 12 项，另含混沌、王牌、工匠、律法（`chaos`、`trump`、`craft`、`law`）。这四个领域目前没有同等完整的正式书本/法术接入，留给后续领域批次，不用近似技能填充；本轮不宣称原版全 12 领域完成。诅咒等非 Mage 候选不得因内容存在而开放。法师没有牧师的善恶领域互斥，不能误禁生命＋死亡等源允许组合。

八领域共 **8×7＝56 个有序组合**，主副顺序影响熟练度，不能折叠成 28 组。本轮全部组合应能创建和通过内容/生成审计；行为测试按实际差异覆盖，不复制 56 套完整游戏流程。若某现有领域查出影响法师的可达缺口，须完成修复或在计划中明确缩小开放范围，不能自动按“已导入”放行。

本轮包含职业有关的已可达任务奖励、公会、基础/Tailored/Acquirement 分配、Ego、随机/固定神器、神器创造卷轴、装置与保存消费者。它们已经进入合并基线，不能沿用旧文档的“系统尚未实现”结论。其他职业的新领域入口、四个缺失领域、Android、自然练到 50 级和完整通关不包含在本轮承诺内。

## 最小实现方案

1. **复用正式 Build。** 拟新增 `demo.class.mage`，组合 ID 为 `demo.build.mage-<first>-<second>`。56 个组合是只描述领域与出生书的薄内容定义，共用 Class、玩家 actor、技能集和能力，沿现有内容工具维护；不复制八套法术效果，不引入临时 Build 注册机制。写入前检查 ID 占用。UI 将组合分成“第一领域 → 第二领域”两步展示，不平铺 56 个按钮。
2. **出生配置与当前领域分清职责。** Build 保留出生组合身份；第一领域不允许改换，当前第二领域及必要的历史进入 Rust 玩家状态。初始化从 Build 取值，此后各消费者读取当前权威选择；保存时不靠出生 Build 推测已改换的领域。优先扩展现有角色状态与查询方法，不新建领域管理器或每次失败时回退旧 Build。
3. **学习与进度复用。** 在 `player_abilities.rs` 及现有能力执行职责中接双领域预算、重复研习、主副上限、遗忘/恢复与源熟练度成长。沿用 `ability_learning_order`、`learned_abilities`、`AbilityProgress`；仅为不能从现有状态派生的“已花学习机会”等信息增加持久字段，不为每种施法者复制一个系统。
4. **迁移真实消费者。** `active_casting_realm_profiles` 目前取 Build 的两个字段；`mogaminator.rs`、`player_stats.rs`、`town.rs`、`virtues.rs`、`loot.rs` 等也直接读取。逐调用者区分出生信息和当前选择，核对改换后的书本需求、归类、被动、奖励与公会资格；不是全局文本替换所有 `first_realm_id`/`second_realm_id`。
5. **沿现有保存与 UI。** 新状态进入初始化、校验、保存、哈希和投影。书本学习/改换提示由 Rust 给出资格、代价和后果，前端提交用户选择；创角、能力面板和角色详情复用当前页面。共享协议或状态哈希改变时才升级对应版本并生成绑定。
