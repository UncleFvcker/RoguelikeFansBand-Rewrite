装备错误按源优先级判定：护甲总重量 `>120+3L` → 任一盾牌或捕获球 → 武器数大于 1 → 毒针 → 玩家反魔。重量为原版十分之一磅，计算所有 `object_is_armour` 对应的实际装备，不是背包重量，也不是仅身体甲。恰好等于阈值有效；拿一把双手武器不等于持两把武器。盾牌等仍可装备，只是天赋失效。

基础 AC 始终 −50；有效时再加 `floor(x/2)+floor(x*L/50)`，`x=INT属性索引+3`。每把武器有效时加伤 `DEX属性索引+3−10+floor(L/2)−floor(武器重量/10)`，允许负值。基础攻次参数 max/wgt/mult 为 `100/70/40`；最终正向额外攻次超过 100 才封顶，不把零/负攻次抬到一次。双手持用不享受 `xtra1.c` 的普通双手命中/加伤及 `combat.c` 的双手暴击概率加成，但仍走原武器基础攻次/重量计算。

干扰原因从当前装备与状态派生；出现失效立即清除挑战，恢复后不复活旧目标。原版用静态消息指针跟踪提示变化，本项目无需保存同样的重复标志。反魔洞、恐惧、混乱或临时禁咒不等于装备错误，不因此任意清掉有效挑战。

## 3. 挑战、自动挑战与中途选择

### 手动挑战和生命周期

手动成功会替换唯一挑战实体、唤醒并敌对化，基础费用 0 HP、默认 100 行动能量。可见性采用实际知识；被感知但隔墙的可见怪物可以标记，不把普通射线可达作为前提。默认候选不含宠物；源坐标确认仍可选可见友方/宠物。实现应保留明确选定对象后敌对化的行为，与现有友方操作确认一致，不能把宠物默认挑进自动重选列表。

| 操作 | 原版 | 本项目锁定语义 |
| --- | --- | --- |
| 成功新标记 | 施技包装器掷失败 RNG（即使 0%）→选择→标记；付 0 HP、正常施技能量 | 合法提交后执行相同规则，保留实际失败掷骰；不把所有手动标记改成免费动作 |
| 重复同一目标 | 返回 false，无 HP/能量；包装器此前已掷 RNG | 作为无效重复请求在边界拒绝，无 HP/能量/RNG，符合现有拒绝契约；明确记为适配 |
| Esc/取消 | 有旧目标时清掉它，但返回 false，无 HP/能量；可能已消费包装器 RNG | Esc 纯取消：状态、HP、能量、RNG 都不变 |
| 明确解除挑战 | 源通过上面的取消表达 | 独立“解除挑战”操作，只清挑战，0 HP、0 能量、0 RNG；无目标时不改变状态。属于交互适配文案，不伪称源技能名 |

Rust 保存可选实体实例 ID。同一实例正常移动、同层传送、暂时不可见时保留；不按种类或坐标重绑定。源没有“变友方立即清标记”的消费者，因此阵营改变本身不清理；玩家再次明确挑战才执行敌对化。删除/死亡清理、离层清理、装备失效清理和改变为非决斗者时的清理进入真实状态边界；同职业变形重新计算装备和种族约束。野外滚动必须在重新加载城镇怪物后检查目标是否真正离开活动区域，不能在临时缓存阶段清理；第四步的实际击杀重选流程发现并修复了此问题，保存恢复回归覆盖相同选择继续。

原版保存挑战字段并在 `save_player_aux`、`rd_savefile` 中暂存恢复跟踪索引；`wipe_m_list` 里的历史注释不代表当前保存会丢挑战。新存档需保存挑战和未完成的职业交互，状态哈希覆盖它们；加载时拒绝错误/错层/已删除实体引用，不仿照原版自动清掉坏索引掩盖存档错误。正常运行的删除先清引用。显示名称、标记与不可用原因来自 Rust；不可见时不得泄露实时位置。

### 普通攻击的自动挑战

两条源入口不能合并成同一阈值，也不能把发出挑战和受益攻击合并为一次动作：

| 入口 | 新对手触发条件（此外要求天赋有效） | 结果 |
| --- | --- | --- |
| 武器攻击 `cmd1.c:2124,2300` | 对象不是当前目标；`!retaliation || 没有当前挑战`；怪物等级 `>=floor(4L/5)` 或最大 HP `>=9L`，或玩家 `<35` 且对象为 `MON_OCHRE_JELLY` | 在攻击循环先唤醒、敌对化并设置挑战，退出本轮，不造成该次攻击伤害 |
| 天然攻击 `cmd1.c:1455` | 对象不同；同一反击条件；最大 HP `>100`，且等级 `>=floor(4L/5)` 或最大 HP `>1000` | 设置挑战、唤醒、敌对化，返回而不执行本次天然攻击 |

已经挑战该对象的武器攻击才获得专用命中和成长打击。天然攻击入口的自动挑战不代表所有种族爪咬都继承武器专用伤害；保留两类消费者的边界。非挑战者、反击时已有其他挑战、普通弱怪、零攻次、恐惧拒绝和友方确认都要沿真实调用顺序测试。

### 30/35 级交互也是核心规则

- **30 级阻止传送：** 挑战者对玩家使用 `ESCAPE_TELE_OTHER` 时先询问是否阻止。拒绝直接继续原传送抗性/传送流程；接受掷 `one_in_(3)`，1/3 失败继续、2/3 成功中断该法术效果。阻止本身不追加 HP 或玩家行动费用。源事件用“无尽追击(Unending Pursuit)”。
- **30 级跟随：** `teleport_away_followable` 先移动怪物；旧位置可见、旧距离不超 MAX_SIGHT、对旧位置有 LOS、不是怪物时间停止/斗技场战斗时，挑战身份授予跟随选择。接受后 1/3 随机被动传送距离 200，2/3 传到目标附近；随后追加一次 `PY_ENERGY_NEED()`，即使传送受阻也不免这次费用。拒绝不掷跟随 RNG、不追加行动。源成功消息另用“无尽追猎”；保留两处源文字，不自造统一中文被动名。已有主动传送突变（MUT_TELEPORT）或非诅咒传送装备的跟随资格仍走公共判断。
- **35 级免费重选：** `cmd1.c:3040` 的被挑战者武器近战死亡分支先清目标；若 `duelist_can_challenge` 找到可见、非宠物、距离不超 MAX_RANGE 的存活对象，立即提供新的挑战选择。直接调用 `duelist_issue_challenge`，不再掷施技失败、不另付 HP/能量。取消保留空挑战；其他死亡/删除路径仅清理，不擅自赠送此选择。

`pending_duelist` 仅为决斗者启用（包括其主动传送突变/装备授予的跟随）；记录超距确认、传送阻止/跟随、免费挑战选择，以及实际调用栈所需的近战收尾、职业 HP 付款、怪物动作、世界 tick 和任务死亡事件。该状态参与保存、哈希和引用/顺序验证；普通命令在待选择期间被拒绝。恢复从中断位置继续，不重复选法术、攻击、RNG 或付款。35 级击杀后可免费重选或取消，任务奖励和混沌升级事件按原动作顺序结算。第四步已通过 Rust 投影和 `ResolveDuelistChoice` 接入四种选择界面，取消/拒绝显式提交对应响应，选择期间停止自动移动并阻止重复提交。

## 4. 对手相关攻防与成长打击

被挑战者武器攻击增加命中 `+L`；正常命中分支之前有 1/2“完美打击”直接命中，仍保留前面的特殊攻击判定。`perfect_strike` 用于命中与消息，不附带额外暴击倍率。普通命中成功后，在源 `mon_damage_mod` 之后取当时伤害 `d=k`，按下面的**执行顺序**处理：

| 顺序 / 等级 | 规则 |
| --- | --- |
| 1 / 10 | `k += d` |
| 2 / 15 | 非 unique 且 DEX 怪物豁免失败，slow 累加 50 |
| 3 / 25 | 没有 `NO_STUN` 且 DEX 豁免失败，调用 `mon_stun(mon_stun_amount(d))` |
| 4 / 20 | DEX 豁免失败，`k += min(当前HP/5, randint1(3)*d)`；把吸血结算用的 `drain_result` 改成当前 k |
| 5 / 40 | 再独立做 DEX 豁免，失败则 `k += min(当前HP*2/5, rand_range(2,6)*d)`；再次更新 `drain_result` |

此后才进入源种族/职业近战倍率等后续伤害流程。`d` 不随之前加伤扩大；两处百分比读取伤害尚未扣除的目标当前 HP，不用最大 HP，也不在 20 级判定后先扣一次怪物 HP。唯一怪不直接免创伤/重创；只在割筋处被排除，其他豁免按其等级修正。各项未达到等级、免疫或已经短路时不消费那一项 RNG。

DEX 豁免见 `monster1.c:60–84`：玩家 power 为 `max(1,L+adj_stat_save[DEX索引])`，怪物等级对 unique 加 `floor(level/5)` 后至少为 1；依次掷玩家/怪物骰，玩家骰 `<=` 怪物骰则抵抗。震慑量按 `mon.c:126` 的 `(1,1),(10,10),(100,25),(500,50)` 插值；已有震慑时增量除以 `1+当前震慑/20`，至少 1。复用现有怪物状态和豁免函数，确有差异才补这个调用所需参数。

防御必须带实际攻击者 ID：

- 被挑战者近战：源先把本次 AC 加 100，用于命中与后续对应护甲伤害计算；每项效果的原始伤害再做 `dam -= floor(dam/3)`，随后进入该效果的抗性/伤害结算。
- 被挑战者投射攻击：`spells1.c:2098` 在调用玩家 GF 前同样做 `dam -= floor(dam/3)`。不能在共用扣血处再减一次；装备接触光环、地形伤害、自付 HP 不因“当前有挑战”自动减伤。
- 需要玩家豁免的 GF 和诅咒：`duelist_skill_sav` 只对正数且等于挑战对象的来源加 `15+L`，传入原消费者的公式。不能直接全局修改角色面板基础 sav。
- **5 级**只是恐惧时对挑战者尝试近战，使用 `fear_save_p(afraid)`，其他对象仍用 `fear_save_p(3*afraid)`。不是免恐惧，也不是所有来源恐惧攻击的统一减伤。
- 聪明怪物封魔选择权重 10 接现有 `monster_ai.rs` / `monster_abilities.rs` 的候选权重；当前候选通常仍保留 base weight，不能以“已有封魔效果”声称该职业 AI 分支已实现。

当前 `player_combat.rs`、`monster_combat.rs`、`monster_abilities.rs` 及 GF/状态消费者均可复用，但没有任何挑战身份分支。UI 的常规攻击预览需标明条件或提供目标上下文，不能照搬源面板“假定决斗中”的显示到所有攻击。

### 费用和状态包装器

`spells.c::_add_extra_costs` 对 HP 职业也调用 `calculate_cost`：有效 `DEC_MANA` 且基础费用大于 0 时，最终为 `max(1,floor(cost*3/4))`。装备层 `equip.c:1734` 可设置它；不是只适用于 MP。因此八项的减耗费用依次为 `0/7/6/18/22/45/45/60`。当前 Class HP 字段直接取 `hit_point_cost`，需接统一的有效 HP 费用并同步投影/预算/付款，不能只改 UI；普通种族 power 的费用公式保持其自身规则。

零基础失败在 `calculate_fail_rate_aux` 提前返回 0，不受普通最小失败或震慑加成；仍有合法施技的失败掷骰。源先做恐惧施法许可，再筛混乱/恐惧可用标记；这些八项没有例外标记。`dungeon.c` 的临时禁咒、反魔洞、玩家反魔和普通狂暴会阻止，不能继承狂战士的豁免。盲目不是无书能力的全局禁令，但会影响需要可见对象的动作。

提交前检验当前 HP 足够，恰好等费可用；效果成功后才扣 HP，效果中吸血/接触伤害在前。扣到 0 不死亡，负 HP 才死亡，复用现有付款及美德边界；效果中已经死亡则不再扣第二遍。效果取消不付 HP/能量。源在目标选择前可能消费失败/恐惧 RNG，本项目沿已确立的无状态取消契约，在正式确认前不推进权威 RNG；费用/拒绝差异必须用明确事件和测试表达。

侧步、脱离和灵动决斗的后半段忽略源传送 bool，传送受阻不自动退回整项费用。源动作耗时使用默认 100；只有单独的 `strafing_spell` 为星界向导返回 30。装置 `EFFECT_STRAFING` 则是 `energy_use /= 3`，不能把装置的 33 与职业的 30 混为一个常量。

### 冲锋和隔离的易错边界

1. 路径分别用 `STOP|KILL`、`THRU|KILL`、`DISI|THRU`。没有挑战、不可见、普通/杂技无 LOS、拒绝超距确认或无路径，返回 cancelled；出现非空路径后即为 failed，哪怕第一处障碍挡住也收费。超距必须有明确继续操作，不能静默截断或自动接受。
2. 源不是逐格普通行走：先累计最近可达位置，接触怪物前才 `move_player_effect`；只有未进入过接触/交换分支（`!moved`）时，遍历结束才补最后落点。杂技交换后若只剩空白尾段且没有再次接触，源不会再把玩家补移到路径末端；保留这一实际行为。普通冲锋还要求 `cave_empty_bold`，杂技/相位检查则是无怪物并通过各自 `player_can_enter`。每个实际落点执行移动/陷阱/区域副作用；中途普通路径格不凭空多触发一次踩踏、搜索、自动拾取或行动费用。`MPE_DONT_PICKUP` 明确禁止拾取。
3. 相位仅临时给 `player_can_enter` 的检查设置 pass_wall；不摧毁墙，也不授予持续穿墙。该函数优先处理坐骑/特殊形态，正常分支要求 `CAN_PASS` 等真实地形标记；不能用“所有墙都可走”代替。真实落点仍允许源许可的墙内位置，使用现有合法占位/危险地形模型，不另加“最终必须普通地板”限制。
4. 杂技交换让拦路怪物落到玩家先前实际位置，不删除、不推到任意空格。原代码若落点副作用导致死亡/离层仍可能继续引用旧路径；Rust 在真实死亡/区域更换边界中止续攻击和侧步，作为状态完整性适配，不复制失效索引行为。野外路径执行期间保持坐标有效，结束再接现有野外区域转换。
5. **源成功判定与注释不一致：** `duelist.c:264` 比较的是冲锋开始时的目标 ID 与当前挑战 ID，随后才攻击眼前怪物，没有比较眼前怪物 ID。因此拦截者也可能令返回值为 succeeded；若攻击没有自动换挑战且原目标仍在，灵动决斗仍会侧步。本批保留这个实际判定，并覆盖“攻击拦路弱怪仍侧步”和“自动挑战换目标后不侧步”；不能按注释悄悄改成必须击中原对手。
6. `GF_ISOLATION` 先按 ID 排除挑战者。其余对象只有带 `RES_TELE` 才进入抗性分支：再带 `RES_ALL` 或 unique 时必抗，否则做 DEX 豁免；没有 `RES_TELE` 的 unique 不在此处分支免疫。不要沿用普通 Away All 对 guardian 的额外免疫或 `level > randint1(100)`。

侧步、灵动决斗和已有 `BlinkSelf` LOS 激活共用 `abilities/travel.rs` 的传送执行；保留原版距离环及至少一半候选的筛选方式。落点排除陷阱、vault 和实体占位，主动传送检查移动能力与深水/熔岩，被动追随失败允许危险地形；反传送仍生效。跟随者按旧位置判定，并处理已导入 Monkey Clone 的强制跟随例外，脱离仍排除指定对手。孤立使用独立 DEX 豁免，再复用怪物位移。地形可达性和怪物近处落点仍采用本项目公共模型，不承诺逐个原版随机数或最终落点一致。

第一步仅检查文档、来源引用和计划一致性。第二步沿同一 RFB 提交落下 Class/Build、技能/熟练度、强感知、装备限制、基础攻防和手动挑战；专项及相关核心回归通过。挑战保存为当前层实例 ID，反魔装备使其清除，临时禁咒/恐惧/混乱仅阻止施技；投影保留 ID 而不补出隐蔽位置。明确挑战宠物会解除控制和旧骑乘羁绊，保留召唤来源与剩余寿命，避免把临时召唤变成永久生物。

当前骑乘模型只接受受控坐骑，因此必须先下骑才能挑战当前坐骑；原版 `xtra2.c:4998` 的坐标确认没有这个限制。核心在目标确认前拒绝，0 行动能量、0 RNG，避免敌对化后产生玩家与非坐骑实体重叠的非法存档。普通可见宠物不受此限制；这是第二步保留的骑乘适配差异，并非原版禁令。

护甲/出生仍使用公共数值模型，不能将职业 −50 AC 直接当成装备后的面板总值；本步保留负 AC 的投影并由现有战斗边界处理。恐惧施技沿当前 Class 能力的直接拒绝及无 RNG 约定，尚未实现原版的恐惧施法许可骰。协议、save payload 和 State Hash Schema 因新字段分别升版；完整 active 契约的预期只允许相应状态哈希变化，不改变既有行为断言。第三步已实现中途选择、减耗 HP、对手攻防及生成/任务神器。旧城堡以 wilderness seed 和任务 ID 派生固定 1:4 选择，不受命令 RNG、查看或失败领取影响；已生成的同名神器按 `artifact.c::create_replacement_art` 生成估值接近的具名替代品，保留原奖励重量，名称账目与保存继续一致。37 项职业相关测试及相关共享回归、完整 active 契约验证通过。
