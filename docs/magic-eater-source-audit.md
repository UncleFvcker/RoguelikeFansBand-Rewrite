## 3. 整件吸收、确认与保存决策

`obj.c::obj_can_combine`明确禁止三类装置堆叠；`obj_kind.c::object_is_device`只接受tval55/65/66。`gain_magic`允许背包或脚下装置，不要求预先鉴定或剩余SP，也不排除已经失去激活的装置。原版复制整个对象再完整鉴定、清原位置；覆盖确认后可继承旧铭刻。

本批采用[ItemInstance/ItemLocation](../crates/rfb-core/src/state.rs)的单实例模型：增加`Absorbed { category, slot }`，类别三种、槽号0—9。30个槽由位置投影得到，空槽不造虚拟物品。吸收保留源实例ID、整个动态激活、当前/最大SP、恢复小数、Ego/实例属性、名称及铭刻；不重新生成装置、不补满SP。体内数量必须为1、知识为完整鉴定；失去激活的合法装置可占槽但不可使用。

覆盖确认沿既有待选择事务模式，保存源实例ID、类别/槽号、当时目标实例ID及铭刻继承选择。提交时重验职业、源仍在背包/脚下、目标身份未变、槽号与类型合法、当前允许操作。取消或失效拒绝不删物品、不鉴定、不耗时/RNG；有效提交一次性移动源实例、删除旧体内实例并清理其局部知识引用，保持已发现内容和唯一性账本。不能仅凭旧槽号覆盖后来换入的另一件装置。同类换位改变位置，保持实例ID；铭刻标签由当前槽位和铭刻派生。

## 4. 使用、周期恢复与休息

源`magic_eater_cast/_use_object`顺序为：禁魔区域、禁止施法、反魔法、狂暴、混乱等入口检查；通用菜单还有`fear_allow_magic`，其成功在当前源回合缓存；确定装置后先设行动能量100并应用SPEED，再作装置恐惧及自然失败检定，之后检查SP，再执行效果，最后按实际使用次数付SP。成功检定后缺SP或效果取消返还行动时间，已经消耗的RNG保留；自然失败可能在空SP时仍耗行动。快捷分类入口和通用菜单的恐惧路径不同，不能把UI点选取消变成额外恐惧惩罚。

[item_use.rs](../crates/rfb-core/src/game/item_use.rs)已有共同效果、目标、威力和支付管线，但普通入口在检定前检查SP，且依赖背包位置；应抽取实际共同原语，由体内入口表达上述顺序，不复制效果分发器、不临时搬回背包。鉴定按实际鉴定数量付费。现有EasySpell装置Ego在生成时已经降低难度，不能使用时再降一次；DevicePower沿当前实例威力处理；Quickness的行动成本目前依赖`UseItem`动作匹配，体内使用也要覆盖。

第四步已由`UseAbsorbedDevice { item_id, targets }`接通分类选中装置后的使用路径；`targets`为空表示自用或目标取消，普通鉴定接受有序目标列表，完整鉴定及其他效果最多一个目标。重复的已鉴定对象不扣费，SP不足停止后续鉴定；空结果探测仍视为使用成功。禁用及失效实例在命令前置边界拒绝；已开始的恐惧/装置检定保留RNG，取消后的通用世界收尾和冷却递减跳过。没有另设通用菜单的缓存恐惧检定，前端选槽也不发送使用命令；当前命令对应源分类入口选定装置后的`_use_object`。已复用共享恐惧豁免（包含Human INT修正）和装置Impotence修正；当前引擎没有独立`tim_no_spells`状态，不虚构额外状态或caster。

恢复接入现有世界tick的装置恢复阶段，位于周期突变选择续接点之后，沿用同一SP/小数写入原语，体内部分按源三类/槽位顺序结算。装备REGEN逐件计入源玩家regen，体内REGEN只影响自身；每10 tick触发，不依赖HP恢复条件。保存字段沿第三步实例模型，无另一个恢复时钟。八项新增行为用例与一项失败率算例已编写，按用户安排尚未运行。

**公共检定适配明确保留。** 源`devices.c::device_calc_fail_rate/device_try`按千分制概率，含技能/难度变换、诅咒、震慑、Impotence及特殊形态；当前[check.rs](../crates/rfb-core/src/check.rs)使用共享`UseDevice`检定，包含d100的5%自动成功/失败和后续技能/难度抽样。本批复用该共享机制及已表达的实例/玩家修正，展示其实际失败率；不另建仅食魔者使用的千分制引擎，也不宣称与源失败分布相同。源未表达的共同恐惧/形态细节仍是共同差异，不能将已实现的禁用状态、Impotence等消费者归入豁免。

周期恢复遵循源`magic_eater_regen_amt/_do_regen`及`devices.c::device_regen_sp_aux`：

1. 基础速率为`3 + max(0, floor((playerRegen−100)/100))`‰，魔棒乘5；装置REGEN在此基础增加`pval×base/5`。玩家regen低于100也保留基础3‰。
2. 源世界处理每10个时间单位调用一次，与行动次数及是否主动休息无关；`pct`参数未使用，不能叠HP/MP的饥饿/休息倍率。接入现有世界周期，在同一周期只恢复一次。
3. 以百分之一SP精度计算`maxSP×100×rate/1000`，不足部分按1000范围随机舍入；未满装置即使余数为0也保留源抽样顺序，满池跳过。当前千分之一SP字段承载10的倍数；满SP截断并清小数。
4. 固定按魔杖0—9、法杖0—9、魔棒0—9结算并消费RNG，保存/加载后相同周期必须一致。普通背包恢复不再处理体内装置；普通装置REGEN是`pval×base`，不能误用在体内。

当前`player_regeneration_rate_percent`未包含穿戴REGEN，而源装备每件REGEN先加100，之后才应用姿态/SlowRegen等修正。本批在共同派生入口补实际穿戴贡献及顺序，复用种族/突变/状态约束；避免在最终已经除以5的结果上再加100，也避免现有HP恢复单独统计装备时双计。体内自己的REGEN只影响该装置。

`magic_eater_can_regen`进入[休息需求](../crates/rfb-core/src/game/player_abilities.rs)：HP满而体内未满仍能休息，全部恢复后结束，保持见敌/受伤/死亡/待选择中断。`bldg.c::_recharge_player_items`在普通旅店休息和重铸调用`restore_all`；当前[town.rs](../crates/rfb-core/src/game/town.rs)旅店只充背包，本批补体内充满及小数清零，保留费用/需要治疗等失败事务。当前没有正式重铸服务，不新造服务。`magic_eater_restore`的350/700‰函数全源仅声明/定义无调用；普通恢复法力药水、法术及`RechargeCarriedDevices`不连体内充能。调试骗死不构成正式复活范围。

工程已存在[TravelLocal](../crates/rfb-core/src/game/travel.rs)和[前端连续行走](../web/src/input-controller.ts)。前端每步发送`travel-local`，核心在动作预处理时改写成`Move`；因此要在改写前保留本次行走意图，在移动消费者内判断自动功能。现有敌人、失明、混乱、已知地形及陷阱停止条件继续有效，不新增另一套前端寻路或持续后台循环，也不把普通`Move`/自动拾取自动视作源running。

当前`explored`/已知地形不等于源`CAVE_IN_DETECT/CAVE_IN_MAP`。本批在现有楼层探测/地图状态中表达实际覆盖范围和自动设置，由手动及自动效果更新；随楼层保存、区域平移及状态哈希处理，不能用“看见过”替代“已探测”。开关必须有Rust权威及UI入口。首先由实际探测建立范围，再在自动行走离开该范围时续用；站立或每次普通步行不能无条件免费探测。

## 6. 生成、奖励、设施及五类责任

源`object2.c`将食魔者列为device class；在Tailored分类选择中先作食魔者专用1/5装置选择，未选中且未被其他实际条件选定时，才进入共有device-class的1/7候选。保留源中间种族/突变分支与顺序，不合成一个无条件概率，不推广到所有生成模式；不属于needs-book。`artifact.c:2233`卷轴倾向为Mage/20，沿现有随机神器消费者。

任务按源最终适用分支处理：
