目标是正式新建决斗者，完成 1–50 级成长、八项能力、完整挑战与攻防规则、当前可达的职业关联、保存恢复及 Tauri standalone 验收。按已开放种族提供原版允许组合；原版明确禁止冬贝利出生为决斗者，核心与 UI 都应排除。后天冬贝利形态、龙人天赋和其他当前可达交叉仍须完成，不用仅允许人类来回避问题。

职业基础修正为 STR +2、INT +1、WIS −2、DEX +2、CON −3、CHR +2；生命系数 100、基础 HP 4、经验系数 150、宠物维持除数 35。无普通书本/MP 施法，职业能力使用 HP。技能、熟练度、物品感知及出生美德按完整消费者审计落实，不从近似职业复制。

`MAX_DUELIST_SPELLS` 为 9，但最后一项是哨兵，实际能力是八项。上表是基础值；`DEC_MANA` 对正数 HP 费用也按 `max(1,floor(cost*3/4))` 减耗，必须同步实际付款与投影。装备失效、状态限制、扣费时序、失败与取消由 Rust 权威判定。复用现有 Class HP 路径，补上本职业包装器差异；不能继承狂战士的物品禁用、常驻狂暴或反魔例外。

必须一起完成的被动与状态规则：

- **挑战身份。** 使用实体实例 ID，不使用怪物种类、坐标或可见列表位置。手动标记与普通近战自动挑战都必须实现。源中某些自动挑战会用本次攻击发出挑战而不造成伤害；不能同回合白送一次受益攻击。反击、空手/种族攻击、友方/宠物、不可见和重复目标逐一审计。
- **装备失效。** 护甲总重量超过 `120 + 3L`（原版重量单位）、盾牌/捕获球、多武器、毒针、反魔会干扰天赋；按真实槽位和装备实例计算。源行为主要是天赋失效，不等于一律禁止装备。切换装备/变形/状态后及时清理挑战，卸下恢复时不得恢复陈旧目标。
- **攻次与属性。** 源基础攻次参数为上限 100、重量 70、倍率 40；有效天赋会将正向额外攻次封顶至一次，负攻次仍可降至零。不得把“最多一次”实现成强制一次。基础 AC −50，天赋有效时增加 INT 索引相关护甲；武器伤害依 DEX 索引、等级和重量计算；双手加成例外从实际消费者核对。
- **对手相关攻防。** 命中/特殊打击只对正确挑战者生效；近战来源的 AC +100、按源顺序减伤和 `15 + L` 额外豁免不能全局加到无关攻击上。远程/法术/恐惧/诅咒等来源也要审计，避免漏分支或重复减伤。
- **成长打击。** 10/15/20/25/40 级的伤害、减速、创伤、震慑和重创覆盖真实 RNG、目标免疫/唯一性、当前 HP、吸血及死亡顺序。源执行顺序含先判 25 级震慑再判 20 级创伤，不按等级排序重排 RNG。
- **其他等级被动。** 5 级改善恐惧时对挑战者出手的豁免，不是免恐惧；30 级提供阻止对手传送玩家及跟随其逃跑的选择；35 级在指定武器近战击杀路径中免费重选挑战。30/35 级必须保留动作中途选择与后续执行顺序，不能自动接受、自动拒绝或推迟到下一玩家回合。
- **物品与任务。** 当前集成已经实现共享生成、随机神器和正式任务；本职业涉及的基础分配、Acquirement、职业 bias、自动拾取/销毁、公会及奖励都是实际可达消费者，不能沿用旧文档“系统尚未实现”而跳过。需要新增的固定神器按已有 ID/来源流程导入，技能激活复用公共效果。

## 验收与版本

**核心最小行为集：** 普通出生与种族装备合并；真实经验升级到能力/打击边界及 50 级；标记 A 后攻击 A/B、由 A/B 近战/施法/恐惧攻击的差别；睡眠唤醒、自动挑战只挑战不攻击、重复标记与取消；装备重量阈值两侧、盾牌/捕获球/双持/反魔导致失效；恢复天赋不复活旧标记；额外攻次封顶和负攻次为零。

**能力与交叉：** 八项全部实际执行；HP 减耗、不足/恰好等费、目标取消、无目标、效果前后扣费、吸血/接触伤害/死亡时序；冲锋路径阻挡、其他怪物占位、实际落点陷阱/危险地形、野外滚动、目标移动与永久墙；传送禁用/抗性/跟随；孤立排除标记者并使用专用 DEX 豁免。30 级接受/拒绝/成功/失败与额外能量、35 级指定近战击杀免费重选/取消和其他死亡不触发必须覆盖。冬贝利出生禁配与后天形态例外分开验证；复用冬贝利手套负攻次、托姆特装备合并、幽灵穿墙/恢复及已有形态/突变测试，不复制全种族矩阵。

**保存与契约：** 至少一条“标记 → 普通攻击或冲锋 → 保存 → 加载 → 相同命令”链比较完整状态和 RNG；另覆盖各类中途选择保存后继续，不重复怪物动作、RNG 或付款，并检查目标已删除或错层引用的拒绝/清理边界。新增持久挑战/待选择字段预计影响 save payload 和 State Hash Schema；DTO 变化再升级协议并由工具生成绑定，具体版本在该步确定。依据实际哈希输入变化执行完整 active 契约检查，刷新须解释差异；不得把内容 hash 当状态哈希输入或用全量刷新掩盖失败。

**检查范围：** 按[验证与契约](testing.md)选择当前改动的核心、内容、本地化、协议/保存/回放、Tauri 和前端消费者。复用既有狂战士、心灵术士、移动/传送/装备测试，只补决斗者缺口；普通步骤不默认跑完整 workspace 或桌面 E2E。第五步是明确交付里程碑，运行相关完整回归和职业桌面流程，Android 不附带承诺。

内容修改按[内容开发](content-development.md)更新包版本与 lock；类型变化才生成相应 Schema/协议绑定。五步实施后的版本与实际验收范围集中在[状态页](status.md)，交付包内保留复现命令及证据。

## 协作边界

按[并行协作](parallel-development.md)，种族职业方向在当前 `main` 负责决斗者。规划和后续实现均先确认写入交接；共享文件不是审批点，真实重叠才协调。以当前已合入的随机神器/分配与地牢城镇实现为基础，不恢复退役工作树，不修改其他方向的未提交文件。新增关联发现后直接落入本批必要范围；不能因它跨模块就自动推给别的方向或推迟到入口开放以后。
