# 永久种族转化审计与共享经验模型

第一步实施记录，2026-09-09。承接[实施计划](life-force-race-change-plan.md)，仅完成审计和共享经验修正；永久切换与生命力终点尚未接通。原版来源全部为 `D:/codex/Frogcomposband/master` 的 `master` Git 对象 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`，下文行号均指该对象的 `src/` 文件。

## 1. 经验问题属于共享核心

旧核心把种族、职业、性格的经验因子乘到奖励上，升级门槛保持 100%。原版 `birth.c::calc_exp_factor`、`xtra2.c::exp_requirement/check_experience` 则保留原始经验、提高门槛。这不是幽灵专属问题：所有因子不为 100% 的组合都受影响；幽灵的 250% 将差异放大了。

本批具体决定与实现：

- `CharacterProgress.experience` 与 `maximum_experience` 均存原始整数经验；不新增第二套账本，不对旧开发存档反推历史经验。
- 因子为 `floor(floor(种族 × 职业 / 100) × 性格 / 100)`，等级门槛为 `floor(基础门槛 × 因子 / 100)`。使用本体 `build.race_id`，普通临时形态不改因子；未开放变形怪的例外不虚建。
- 奖励统一走 `apply_player_experience`，移除缩放/不缩放双通路；经验药水与混沌奖励不再需要绕行。投影下一等级门槛及存档校验使用同一因子。角色页文案改为“经验需求”。
- 核对等级先降后升；当前/最高经验不因因子变化重写，`max_level` 不下降，只有突破旧最高等级时才发新的五级属性奖励和按新等级次数触发的种族奖励。现有种族天赋资格检查继续执行。
- 恢复经验令当前值等于可恢复最高值后复核等级。若奖励后仍低于最高值，最高值另增加奖励的五分之一，遵循 `effects.c::gain_exp_64`；当前/最高值均封顶 999999999。已死亡角色不再获得经验。
- 沿用现有整数精度、HP 成长表示及即时经验结算。原版 `exp_frac` 和战斗中的 `PN_EXP` 延迟结算不是此次永久切换必需的新字段；不据此声称完整经验来源和逐随机数模拟已等同原版。后续终点接线仍须验证同一攻击内的刷新次序。

例：同获 100 原始经验，人类战士为 6 级、下级门槛 140；幽灵战士为 3 级、下级门槛 112。幽灵从 111 到 112 才到 4 级。已有 380 经验的人类从 10 级改用幽灵因子会降到 7 级；改回后仍只有原先两次属性奖励。

协议 **1.235**，Save Payload Schema **6**，State Hash Schema **110**；Save Header 仍为 **5**。原因是已有经验字段和共享投影的语义改变；旧开发存档拒绝加载。本批无内容变动，内容包保持 **1.398.0**，不重写 content lock。

## 2. 生命力入口与终点顺序

| `spells3.c:1048`、`r_eye.c:324`、`ragemage.c:682`、`timelord.c:645` | 未开放怪物种族的负向附魔消耗及职业/种族恢复：**未开放系统依赖**，不为本批造玩法 |

UNLIFE 顺序是影子/非生物/生命豁免检查 → `lp_player(-dam)`（含转化或死亡）→ 接触攻击者 `mpower += dam`。强化按传入完整吸取量，不按生命力差值或最终 1000 计算。NETHER 分出的生命力吸取也走该链；第四步须核对分流及余下伤害。

结果 `<= 0` 时，普通玩家先 `randint1(5)`：吸血鬼、骷髅、僵尸、幽灵、英灵战士，固定顺序各 20%。尝试 `change_race` 后按**当前形态**的 `RACE_NONLIVING` 判定：成立设 1000，否则 `DAMAGE_NOESCAPE` 致命伤害。怪物职业留 0。零扣除/已为 0、恰到 0、越过 0 须分别取证，不能预判免疫而省抽签。

`wizard2.c:208` 的 rerate 先触发 `handle_stuff`，之后 `check_experience` 又可能刷新 HP。`xtra1.c::calc_hitpoints` 包含生命力折减，最大 HP 改变时按比例调整当前 HP。`lp_player` 只有最终生命力不同于旧值才发最终 HP 更新标志；旧 1000→耗尽→新 1000 不一定有最终刷新。第四步须测试负中间值、多次缩放取整与实际刷新次序，不能简单合并成一次回血。

## 4. 最少持久字段决定

本步**零新增字段**：现有经验、最高等级、未消费属性点、生命成长表和本体身份够用；语义变更由 payload 版本隔离。

第三步必需增量限定为实际消费者：

- **学习顺序及暂忘记录**：对应 `xtra1.c::calc_spells` 的顺序遗忘/记起，现有已学集合承载当前可用能力，保留 proficiency/cast count，不能用字母序替代学习顺序。
- **原先穿戴标记**：对应 `OM_WORN`，为身体变化自动穿回补物品标记及存档/哈希消费者，不建装备历史系统。
- **不新增通用突变来源账本**：目前锁定突变唯一生产写入是种族奖励；旧本体奖励定义与 active/locked 集合足以识别人类弱点等现有天赋。未来出现其他锁定来源再扩模型。
- **不新增出生/历史种族字段**：原版 `old_race1/2/3` 消费者为 `py_info.c:1284` 历史及 `files.c:3024` 狂战士幽灵计分；`start_race` 还用于 `xtra1.c:344`、`dungeon.c:6780` 出生昼夜偏移和旧存档时钟。当前绝对 `world_tick` 已记录出生夜间起点，转化保留即可；`tasks.rs::campaign_score` 只用任务、征服、胜利、回合，不用种族。未来接入历史/计分时再补字段，本批不虚建 UI。
- **不新增**独立经验因子、子种族、第二份经验账本、`max_max_exp` 或永久负生命力字段：因子/子种族可派生，额外历史统计没有消费者，负值仅属一次结算的中间态。

武器熟练度不用新字段：保留现有存量，修正上限变化后的有效读取和保存校验。学习/装备增量在第一步交付时尚未实施；现已随[计划第三步](life-force-race-change-plan.md)落地，生命力终点仍待第四步接线。
