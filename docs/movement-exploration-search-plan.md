实施内容：

1. 在 Rust 增加最小搜索模式状态和切换命令。切换本身按源分发不花游戏时间；原有 `s` 仍是耗时的单次搜索。不开一个反复派发 `Search` 的前端循环。
2. 在符合源条件的移动结算位置调用已有隐藏地形／箱子陷阱搜索逻辑，产生正常发现事件并更新地图。不推进第二次移动回合，不给传送或失败移动随意追加搜索；核对位移调用标志，测试相关真实消费者。
3. 接入现有派生速度与能量系统，落实通常速度减 10，并核对已有光速、骑乘等覆盖顺序；前端不自行延时模拟减速。HUD 明确显示模式和代价，沿用本项目的速度展示规则。
4. 模式进入保存、恢复、状态哈希和回放。按原版 `disturb(stop_search, ...)` 区分只停止跑步／旅行与关闭搜索；普通取消不能无条件擦除模式。休息、钓鱼等占用角色行动的切换点逐项核对现有消费者，采用源互斥语义，不预造全局行动管理器。
5. M1 跑步、M2 探索、M3 旅行都走同一移动搜索入口；搜索有发现时按源打断规则停止自动行走。普通移动继续可用，输入与界面不被“搜索中”锁住。
6. 源同时存在普通移动的概率自发搜索。先查当前消费者；若当前没有，此批不暗中为所有关闭模式的移动新增随机抽样，把该差异记入未完成项。本步保证搜索模式追加搜索的次数、概率与代价，既有关闭模式行为保持可验证。

**验收：**开关不耗时；开启后真实移动搜索、关闭后无额外模式搜索；减速影响实际怪物行动节奏；搜索发现、失败移动、传送、骑乘和模式互斥边界正确。保存恢复后相同下一命令产生相同事件／RNG／状态哈希；与前三步组合时可停止且不重复结算搜索。

## 每步的落点与完成标准

优先修改已有职责：[旅行](../crates/rfb-core/src/game/travel.rs)、[移动](../crates/rfb-core/src/game/movement.rs)、[地形搜索](../crates/rfb-core/src/game/terrain.rs)、[取物规则](../crates/rfb-core/src/game/mogaminator.rs)、[输入控制](../web/src/input-controller.ts)、[命令快捷键](../web/src/command-shortcuts.ts)。跑步算法可放职责单一的核心模块，避免把算法继续堆入 `game/mod.rs`。只有新增状态／命令确实需要时才扩展协议与快照，生成绑定及 Schema，不手改生成物。

每步遵循[验证与契约](testing.md)：

- 核心用最小地图／物品 fixture 验证本步语义，复用相关移动、旅行、Mogaminator 和搜索覆盖。前端验证真实命令入口与连续取消，执行受影响测试和 typecheck。
- 新增持久状态、改变 RNG／哈希输入或公共投影时，执行相应保存恢复、回放及受影响契约；必要时扩大全局契约验证。刷新 fixture 必须解释真实行为差异。
- 更新当前键盘操作和状态文档，分别记录规则、入口、自动测试、桌面实按。每步无需重复全量桌面构建。
- 四步完成后作为一次里程碑，合并现有待做的 K5：在 Tauri 实按两套预设和组合行为，特别验证 `.`／`,`、大小写方向、`Z`、`H`／`Ctrl+E`、`S`／`#`、取消和保存。通过后生成 standalone 并做原生产物烟测；此前不能宣称可玩 EXE 已包含本批功能。

当前下一项为 **K5 原生桌面组合验收与 standalone**。M1–M4 的规则与入口已实现；桌面实按和新 EXE 尚未验收。
