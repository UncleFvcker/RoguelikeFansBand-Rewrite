1. **核源并补底材。**每组重新确认 RFB `master`；仅导入该组 kind，复用现有同步工具与稳定 ID，逐字使用权威中文名。核对 W／A／P／flags、销毁规则、Ego／随机神器 eligibility；W 等级不能替代 A 分配，底材固定附魔不能丢失。

3. **沿真实入口验收。**从新角色经正式完整普通池生成，明确受控深度；实际拾取、未知保存、鉴定、装备／攻击／激活，再保存续演。组内共用生成／唯一性检查，差异消费者按表中边界补有效断言，不每件复制整套测试。激活覆盖失败、目标取消或无目标行为、冷却中保存与再次使用，按源行为选择适用分支。
4. **同步与关闭。**内容包版本／lock、分配报告、源 C 估值新增实例和现有生成审计随组更新；类型变化才生成 Schema。运行直接受影响的既有核心测试、内容／本地化及来源检查、适用性审计和相关 Clippy；普通池改变后检查受影响的 active 契约，不机械刷新 fixture 或扩大为全 workspace。每组独立通过并提交，完成细节留提交说明，计划只更新状态与依赖。
