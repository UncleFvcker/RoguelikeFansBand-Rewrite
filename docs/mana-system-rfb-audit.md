## 对照结论

**最明显的偏差是恢复机制；普通施法者的基础法力上限已有原版公式，不能整体推倒重做。**

| 项目 | 当前实现与差异 | 处理 |
| --- | --- | --- |
| 普通法力上限 | `player_abilities.rs::casting_resource_maximum` 已使用 RFB 属性表、有效等级、种族修正、手套和负重扣减等。人类心灵术士 1 级、感知 16 的基础上限为 9，与原版相符。 | 保留已对齐部分，逐项核对边界及特殊配置。 |
| 自然恢复量 | `resources/mana.json` 仍定义等待 +1、休息 +3，再由职业和装备修正；`ResourcePool` 只有整数当前值与上限。原版按上限计算小数恢复并累积。 | 优先改为原版定点结算。 |
| 自然恢复时机 | `finish_duelist_player_world` 在等待后恢复，其他普通行动只处理负维持费。原版恢复随世界时间推进，移动、攻击等同样会跨过恢复周期。 | 接入共同世界结算点，去掉动作结束处重复恢复或扣费。 |
| 恢复修正 | 当前恢复路径依赖固定基础量和 `resourceRecoveryPercent`，未包含原版整条饥饿、恢复属性与动作状态计算链；法力恢复装备使用 `max(200)`。原版正恢复还会乘法力恢复倍率。 | 对照各修正的来源和叠加顺序；不能把同一布尔能力按职业与装备重复计算。 |
| 宠物维持 | 当前正恢复会整数截断，超过 100% 的损失按整数向上取整。原版正负恢复均有小数，负恢复还存在专门的加速阈值。 | 保留现有宠物维持百分比入口，替换它影响法力的算法及结算时机。 |
| 上限变化 | 当前公共刷新只改上限并截断当前值；属性变化另有比例缩放。原版 `calc_mana` 在上限变化时统一处理比例和小数。当前比例公式与原版分步取整也不同。 | 核对升级、装备、临时属性和变形调用者，收口处理，避免重复缩放。 |
| 施法耗蓝 | 当前书本法术已有熟练度与减耗公式；职业能力有独立成本路径，失败通常仍扣费。不能认定全部错误。 | 按实际已开放能力核对特殊减耗、取消退款与失败回调，不统一套一种公式。 |
| 休息与显示 | 当前“是否能恢复”依赖一次恢复的整数值大于 0，HUD 显示等待/休息固定整数。 | 改用真实恢复能力判断，更新恢复速率显示，避免小数恢复被当成不能恢复。 |

### 原版自然恢复的可核对基准

原版 `process_world` 每 `TURNS_PER_TICK = 10` 个能量推进单位进入周期结算。实现时必须先确认它与当前 `world_tick`、速度及能量消耗的对应关系，不能直接把一次用户命令视作一次原版周期。

无特殊限制、正常饥饿状态、恢复倍率 100%、无宠物时，每个原版恢复结算周期：

- 普通状态：恢复 `(法力上限 × 197 + 524) / 65536` 点法力。
- 休息或搜索状态：恢复 `(法力上限 × 394 + 524) / 65536` 点法力。
- 原版累积到 `csp_frac`，满蓝时清空小数；休息翻倍的是变量部分，不是常量 524。

以法力上限 9 为例，普通恢复约 0.035 点/周期，休息约 0.062 点/周期。从零小数开始，分别需 29 和 17 个结算周期才增加第一个整数法力。这是恢复周期示例，不是现实秒数，也未计入头脑清明等额外动作。

负维持费需保留原版 `percent < -47674` 的加速分支及分步整数运算；不能用“每个动作至少扣 1 点”替代。

## 修改顺序

### 1. 自然恢复与维持费共用世界时间和小数状态

目标：同样的世界时间与角色状态下，走路、攻击、等待具有相同的自然回蓝；低恢复量能累积，恢复与维持费都只结算一次。

- 从 `game/turn.rs::advance_until_player_ready` 及现有世界时钟确定结算频率，保留速度、耗时动作和不耗时操作的区别。
- 在现有资源状态中加入法力小数累计所需的最小字段，采用确定性的整数定点运算，保持原版取整次序、借位、满蓝和归零语义。
- 将自然恢复与负维持费迁入同一个周期入口，移除等待/休息及 `finish_duelist_player_world` 中对应的重复结算。主动回蓝效果仍由原有能力入口执行。
- 同步持久化、恢复、状态哈希与完整性校验。法力整数为 0 但仍有小数时，宠物强制遣散条件也必须与原版一致。
- 修改“休息到恢复”的判断：每周期不足 1 点仍属可恢复；净恢复为零或负值时按原版条件结束，不空转。

主要涉及：`state.rs`、`game/turn.rs`、`game/player_abilities.rs`、`game/pet_upkeep.rs`、`game/abilities/duelist_choices.rs`，以及实际存档与哈希入口。

### 2. 补齐恢复修正与特殊职业行为

目标：在步骤 1 的共同结算上复刻修正顺序，保留职业差异。

- 对齐饥饿、普通恢复能力、休息/搜索、特殊动作禁止恢复、法力恢复能力和宠物维持的组合；负维持费使用原版普通恢复基准，不能因休息而加重损失。
- 清点职业 `resourceRecoveryPercent` 的来源。区分“职业赋予法力恢复能力”与独立倍率，防止装备同类能力重复加倍。
- 保留狂法师不自然回蓝、武士超额法力和蓄气、吞魔者装置充能等已实现特殊路径；不得把所有资源和职业套进普通 MP 恢复。
- 头脑清明需区分手动施放和休息自动调用：原版休息直接 `cast_clear_mind()`，不是再走一次普通施法失败率判定。保留 `2 + 等级/30`、宠物限制及资格条件，并核对它与自然恢复的先后顺序。
- 不直接复用生命恢复的全部禁止条件：原版中毒、流血等抑制 HP 的处理发生在 MP 恢复之后。逐项核对环境、变形与大地图限制。

### 3. 统一上限变更，再补施法扣费的实际缺口

目标：装备、等级和属性改变后的法力行为一致，技能列表显示成本与实际支付一致。

- 保留普通上限已对齐公式，补对起始施法等级、属性极值、种族施法属性、容量加成以及负重边界。
- 在共同上限刷新处按原版顺序处理当前法力比例、小数和超额法力；删去调用者中的重复比例缩放。验证从无蓝到有蓝、上限降为零、当前值为零等分支。
- 原版先计算整数百分比再缩放；当前 `rescale_u32` 直接计算乘除，不能只用大致比例断言替代逐步取整对照。
- 分别核对书本法术、职业法术、天赋能力。当前 `class_ability_resource_cost` 主要接入心灵之石减耗；需对照原版各施法者的减耗资格，而不是给所有职业能力无条件减耗。
- 用已开放能力检查失败扣费、成功后取消退款、目标取消不耗时及特殊失败回调。原版存在特殊退款分支，但本轮尚未逐个能力确认项目缺口，不先批量改写。

### 4. 调整投影、内容与相关验证

目标：玩家看到真实恢复速度，且规则、数据和存档表达一致。

- 去掉法力 HUD 中误导性的固定“等待 +1 / 休息 +3”。由 Rust 投影当前自然恢复/损失速率、明确的游戏时间单位及无法恢复的必要原因；前端仅格式化，小数不足 1 点不能显示成完全不恢复。
- 整理 `resources/mana.json` 中固定恢复值及受影响职业配置；不为本批之外的资源提前设计通用恢复框架。
- 内容变更同步正式包版本与 lock；类型改变时按现有命令生成 Schema/协议绑定，不手改生成物。新增状态按实际影响更新存档与状态哈希契约，不维护旧开发存档兼容。
- 用户明确要求编译验证后才执行下述相关检查；不跑全量 workspace、全量前端或发布构建。

## 本轮验证关注点

优先扩展现有资源、休息、宠物、职业和进度测试，仅补缺少的行为：

1. 小数积累、满蓝清零、扣除借位、连续存取档后下一周期结果一致。
2. 相同世界时间的移动/攻击/等待恢复一致；休息与搜索修正有效；速度与耗时差异不额外创造恢复，不耗时查看菜单不恢复。
3. 饥饿、恢复能力与法力恢复能力的组合；宠物维持在 100% 两侧及原版负恢复加速阈值两侧的结果。
4. 当前蓝为零但小数未耗尽时不提前强制遣散；休息能累积小数，也能在确实无法恢复时结束。
5. 心灵术士休息自动头脑清明、带宠物限制；武士蓄气与超额衰减、狂法师禁自然回蓝、吞魔者独立充能不被重复结算。
6. 基础上限 9 的原版样例，以及升级/换装/属性变化的上限重算、分步取整和零值分支。
7. 挑选已接入的书本法术、职业法术、天赋能力，验证实际成本、失败支付、取消退款；不复制所有技能为静态矩阵。
8. HUD 只做相关组件/投影检查，覆盖小数正恢复、零恢复、负维持费及单位文案。

实际通过范围与未穷举的原版行为以上方记录为准；不以这些检查宣称全部职业、法术和自然游玩流程完全对齐原版。
