## 本轮交付范围

新增`demo.class.magic-eater`及一个`demo.build.magic-eater`，不分领域。中文职业名“食魔者”、能力名“吸收魔法”和三类“魔杖／法杖／魔棒”均取自`src/magic_eater.c`；创角分类采用`src/py_birth.c:1354`的“魔法装置”。在当前目录没有其他变化时，开放后为14职业、103个Build。

保留源三类各10个固定槽位。吸收将真实装置实例移入体内，保留效果、难度、费用、当前/最大SP、恢复小数、Ego/实例属性、名称和铭刻等；不转成累计法术次数或玩家公共MP。吸收后完整鉴定，原物品消失；覆盖旧槽需要确认，并可选择继承旧铭刻。支持浏览、同类换位、铭刻、目标选择、连续使用、恢复及保存续演。

正式支持当前已经实现且可获得的三类装置效果；不以职业接入为理由一次导入全部上游装置。出生、职业任务及自动消费者需要而当前缺失的装置随本批补齐，并沿正式底材/激活profile入口接入。未开放效果逐项列出来源与依赖，不能替换成相似效果或把不能使用的内容计为完成。

## 现有基础与最小实现边界

- [ItemInstance与ItemLocation](../crates/rfb-core/src/state.rs)已经保存动态激活、SP、恢复进度、Ego/固有属性及铭刻。已确定增加受约束的Absorbed位置（类别＋槽号），保持一份实例权威；空槽由投影派生，保存使用明确体内容器和复用物品字段，覆盖确认保存源/目标实例身份。
- [item_use.rs](../crates/rfb-core/src/game/item_use.rs)已有动态profile、效果计划、目标、检定与支付，但入口依赖普通物品位置，而且现有流程在检定前检查SP。抽取实际相同的效果/支付原语，体内入口明确表达源不同的检查顺序和取消成本；不临时把体内物品搬回背包绕过约束，也不复制整个效果分发器。
- [inventory.rs](../crates/rfb-core/src/game/inventory.rs)的`absorb_device`目前是耗装置充能并获得营养，法师也有既有吞噬机制；这些不是食魔者的整件吸收。新增职业流程进入职责明确的`game/magic_eater.rs`等现有Game子模块，复用鉴定和物品操作，不扩张`game/mod.rs`成规则实现文件。
- [turn.rs](../crates/rfb-core/src/game/turn.rs)已有带小数/随机舍入的装置恢复；[player_abilities.rs](../crates/rfb-core/src/game/player_abilities.rs)的休息需求目前只看HP和可恢复公共资源。体内恢复只在专用周期处理一次，排除普通背包恢复；按三类和槽位稳定顺序消费RNG，保存后相同时间推进必须一致。
- [mogaminator.rs](../crates/rfb-core/src/game/mogaminator.rs)已有实际自动鉴定；[item_knowledge.rs](../crates/rfb-core/src/game/item_knowledge.rs)、移动/探测职责模块和[town.rs](../crates/rfb-core/src/game/town.rs)接各自消费者。体内位置不计背包重量/容量、不当作穿戴装备提供被动、不参加出售/丢弃/摧毁/怪物吸取；这些由真实位置边界约束。
- 保存、回放、状态哈希和协议投影沿[save.rs](../crates/rfb-core/src/save.rs)、[协议](../crates/rfb-protocol/src/lib.rs)与[snapshot.rs](../crates/rfb-core/src/game/snapshot.rs)。校验职业资格、三类槽号0—9、槽位/实例ID唯一性、正式装置身份、SP/恢复进度及属性引用；确认覆盖要核对源实例及当前目标，取消/过期确认不得删除或复制物品。

## 协作与缓存

本方向在当前`main`工作树实施，沿[并行协作](parallel-development.md)交接。普通共享文件不是审批点；若装置效果或设施出现真实并发重叠，再协调单一写入者。必要出生/奖励装置若已有正式身份就直接复用；实际缺失的profile随本批职责接入，不预造通用装置框架或等待无关重构。

三个开发工作树已配置共享main中间编译缓存、各自workspace wrapper和最终输出，正常运行现有命令即可；不覆盖本机Cargo配置、不共用最终EXE、不清旧缓存。并行构建等待缓存锁是正常情况。桌面沿现有WebDriver/CDP和进程定向控件接口，不使用Computer Use或全局输入。
