## 推进顺序

按 **P1 → P2 → P3 → P4 → P5 → P6 → P7** 交付。P1 建立当下需要的权限状态，后续逐项扩展；不先提交一套未被使用的开关或空菜单。

### P1：开门与自主拾物

在现有宠物命令旁增加明确的权限字段和零耗时设置命令，由 Core 保存、校验和投影；`p` 菜单同步开放开门／拾物切换。默认均关闭，开关不能赋予怪物本来没有的能力。

开门权限接入怪物门交互及寻路判断，核对开门、撞门、穿墙／毁墙和坐骑的源边界，避免只在最后执行时拦截而使宠物反复走向同一扇门。普通敌方怪物行为不受宠物选项影响。

自主拾物指经过物品时按怪物能力拾取，不新增跨地图追逐物品 AI。复用已有神器、有害物品等过滤及 `CarriedBy`。按 `cmd5.c` 实现从开启切为关闭时宠物放下携带物；复用正常落物规则处理当前位置不可落物的情况。核对死亡、解散、失控、换层、离开大地图及存读档时的物品去向。当前 `remove_pet_at` 会移除携带物，须按源解散语义明确保留或调整，不能未经核对统一改为掉落。

验收：相同宠物开启／关闭开门及拾物的实际行动差异；无能力宠物不越权；关闭拾物后物品数量、ID、知识状态正确，保存恢复无悬空引用；设置不耗回合或 RNG；菜单取消不发命令。

主要入口：`pet_commands.rs`、`movement.rs`、门交互职责模块、`pet_upkeep.rs`、保存／投影及 `pet-menu.ts`。

P1 实施记录：Rust `SummonCommandDto` 增加默认关闭的 `open_doors`／`pickup_items`，`SetPetOption` 免费设置并沿已有玩家保存／投影链流转；菜单使用源“宠物开门”“宠物拾取物品”的开／关字符串。开门与撞门共同受权限约束，寻路和执行一致；穿墙／毁墙维持现有能力判断。宠物拾物仍要求自身能力，不进入怪物毁物分支。

关闭拾物只放下当前层受控宠物携带物，沿用 `ground_drop_position` 的确定性落点；无可落地位置时采用现有物品销毁规则并清理知识引用。这与原版 `drop_near` 的随机落点／堆叠选择仍有既有适配差异。死亡沿用既有掉落；解散与消失沿用源 `delete_monster_idx` 的携物移除，失控后物品仍属于该活实体；解散菜单和原有“解散全部”按钮均明确确认携带物会丢失。

补正楼层转移的携物归属：坐骑携物跟随坐骑，普通随行宠物成功放置后携物从原层转移；无空间而留在原层的宠物保留其携物。荒野切换已有对应坐骑携物分区，本步保留。补充了权限、物品去向、菜单确认及坐骑／宠物跨层用例源码，尚未运行。

Rust 源协议暂为 1.278、payload 34、State Hash Schema 139；生成物仍停留前批 1.277，active 契约仍为 v338，均待上述统一生成／验证。内容包与 lock 不因本步改变。当前只完成源码核对和 rustfmt 排版，不提供编译或运行通过结论。

### P2：繁殖控制与维持约束

复用 `try_original_reproduction`，增加宠物专属禁繁殖选项。源规则是维持负担 **大于 80%** 时禁止宠物繁殖，恰好 80% 仍可进入后续条件；与已有全层繁殖抑制、数量上限、拥挤、空位判断共同生效。

按源调用顺序放置宠物门槛，特别保留拥挤等随机检查与宠物拒绝的先后次序。验证后代玩家归属、维持计算、召唤身份与寿命，不直接认定复制全部父代字段就是完整源语义。普通敌人不受玩家禁繁殖选项影响。

验收：禁繁殖、80%／超过 80%、全层抑制、无空位、后代归属及维持增长；同种子保存恢复后的后代和 RNG 一致。菜单显示“禁止繁殖”的实际开关含义，不和全层抑制混为一个状态。

主要入口：`monster_ecology.rs`、`turn.rs`、`pet_upkeep.rs`、宠物权限与菜单。

P2 实施记录：新增默认关闭的 `no_breeding`，沿用 `SetPetOption` 的免费设置、玩家保存和投影；`p` 使用原版“禁止繁殖 (目前：开／关)”字符串。繁殖继续依次检查全层抑制／数量限制、调和美德随机门槛、拥挤随机门槛，然后对受控宠物检查禁繁殖或维持负担大于 80%，最后才选空位和生成后代。修复原先只消耗调和随机数却未比较实际美德值的遗漏；正调和值可阻止普通怪物及宠物繁殖，因此后续契约核对不能预先假定只有哈希差异。

后代保留当前 `controller_id`／`SummonIdentity` 的归属和剩余寿命；永久宠物后代保持永久，有限召唤后代不重新获得完整时长。此处明确沿用本项目已有有限寿命模型：原版 `monster2.c::multiply_monster`／`place_monster_one` 还建立 `parent_m_idx` 关系，本项目没有该父子图，父代死亡引发的完整源亲子行为未在 P2 新建，须在 P4 控制继承范围继续核对。补正有限召唤到期处理，复用实体移除与携物／骑乘清理，避免无主携物。

已补禁繁殖保存及零耗时、80%／81% 边界、后代维持与控制、保存继续、有限寿命继承、调和／拥挤／全层抑制／无空位随机边界、到期携物清理及菜单切换用例源码，均未执行。既有繁殖数量上限用例保留，待统一运行。Rust 源协议 1.279、payload 35、State Hash Schema 140；生成物仍为 1.277、契约仍为 v338，内容包／lock 不变。仅完成源码核对、rustfmt 排版与差异检查，不宣称编译或测试通过。

### P3：宠物施法、传送与波及玩家控制

让宠物行动调用现有 `monster_ai.rs`／`monster_abilities.rs` 流程，保留频率、冷却、状态、禁魔、能量和 RNG 规则。选择实体 ID、距离命令及对怪目标限制要在施法与近战／移动之间一致；宠物不能把玩家或同阵营宠物误选为敌方目标。施法与移动的先后次序以源为依据。

开放攻击法术、传送和“允许范围法术波及玩家”三个有实际消费者的选项。按 `_ai_think_pet` 过滤源禁止的尖叫、黑暗、陷阱及特殊能力；同时应用对怪施法限制。复用已有治疗／自我增益消费者，禁止攻击法术不等于禁止所有法术。

`PF_BALL_SPELL` 是波及玩家控制，不能直接当作“是否允许施放所有球形法术”。当前共享规划器会拒绝任何友方风险，必须核对其与源玩家风险限制、坐骑例外、其他友军及实际伤害结算的差异；只改候选允许而伤害端仍过滤玩家，也不算完成。普通敌方施法的既有风险判断不能被一并放宽。

这一批实际施法和风险保护必须同时交付。召唤候选在 P4 完成控制继承前暂不开放，菜单也不提供尚不可用的召唤开关；作为明确阶段限制记录。

验收：单体攻击、自疗／增益、传送、射线／范围及呼吸代表路径；指定目标、遮挡、禁魔、状态及冷却；开关关闭时相应能力不被选中；波及玩家关闭／开启以及坐骑例外有实际 HP／状态结果；敌方怪物施法相关回归通过。

P3 实施记录：来源仍为 `master@a0d92b6378d148c5262cc236b8fa6ed2ca06a54c` 的 `birth.c`、`melee2.c`、`monspell.c`、`cmd5.c` 和 `spells1.c::project_p`。宠物在移动／近战前进入现有施法管线，复用频率、冷却、禁魔、候选权重与伤害结算；混乱保留频率抽取后拒绝的边界。施法目标复用已有指定目标和距离筛选，并要求投射可达；先有合法敌人，才考虑自疗、增益和传送。保留本项目确定性目标次序及已有几何／权重适配，不宣称复刻原版随机择敌。

新增默认开启的 `attack_spells`／`teleport` 和默认关闭的 `allow_player_damage`，通过已有免费命令、保存和投影流转；菜单中英文同步，中文逐字采用上述源菜单。攻击开关过滤吐息、球、箭、射线和诅咒；传送开关过滤战术／逃离及传送目标。原版跳跃爆炸属于战术组，只受传送开关控制；飞鸟特殊技同时要求攻击和传送。禁止尖叫、黑暗、造陷阱、遗忘、时间停止及当前对怪不支持的吸魔／楼层传送；普通／分类召唤、复活及未开放特殊变换在 P4 前仍不进入候选。

### P4：宠物召唤与控制继承

开放召唤选项及候选，复用现有召唤分配、唯一数量、地形空位和反召唤规则。沿普通、分类、固定／特殊召唤的实际入口核对归属，避免只修普通召唤而留下特殊能力仍生成敌方或无主实体。

区分召唤来源和玩家控制：新增宠物须被既有归属判断、全局指令、维持计算、解散及骑乘资格正确识别；不为此先建多层主人图或第二套宠物注册表。后代寿命、召唤者死亡、失控和切层按源及既有实体生命周期处理，具体特殊能力缺口逐项记录。

验收：召唤开／关、空间不足、唯一上限、反召唤环境、普通与特殊代表路径；召唤物可受控攻击／解散、维持立即计入；来源死亡及保存恢复不产生悬空 owner 或永久误继承。只验收当前正式包实际支持的能力分支，不声称所有未导入法术完成。

P4 实施记录：本批重新核对 `master@a0d92b6378d148c5262cc236b8fa6ed2ca06a54c` 的 `monspell.c` 召唤／筛选、`monster2.c::place_monster_one`／召唤入口、`melee2.c` 父代消失及维持分支、`cmd5.c` 菜单。新增默认开启的 `summon_spells`，沿已有免费设置、保存和投影链流转；`p` 中文采用“允许施放召唤法术 (当前: 开启／关闭)”源字符串。固定、分类、家族特殊和死亡独特怪物召唤解除 P3 的阶段限制，原版禁止的 Banor/Rupart 特殊变换仍不向宠物开放。复活属于源 ANNOY 组，仍可在关闭召唤组时施放；本项目当前复活目标仍按正式内容映射为复生奴仆，未扩展尸体来源还原。

各怪物施法生成入口复用同一个归属初始化函数：普通子代继承玩家控制，独特怪物／unique2 只成为友军，不进入指挥／维持／解散宠物列表；普通友军施法者按源非愚笨、9/10 友好继承分支处理。召唤来源仍记录在已有 `owner_id`，新增 `owner_dependent` 明确区分活父代依赖与历史来源，避免把“施法者 ID”直接当成玩家控制 ID。既有魅惑转宠路径也标记父代依赖。宠物召唤还要求与玩家投射可达；继续使用现有数量、地形、唯一上限与候选规则，修补分类、家族和死亡独特召唤遗漏的反召唤装备检查。城镇竞技场／观战模式尚无本项目状态，不把名为 arena-room 的地牢误判为该限制。

依赖者在自己的下一次行动检查父代：父代已死／移除时，普通受控子代连同携物按既有消失路径清理；当前坐骑或已非宠物的实体解除依赖，保留独立寿命。父代仍活着但失控不自动撤销子代控制，之后新生成的子代按施法者当时阵营处理。持久楼层中的活父代仍算存在，跨层不误删；待处理消失可以保存恢复。`owner_id` 在解除依赖后保留为来源记录，不再作为活引用消费；加载拒绝自指和循环依赖，当前层及已保存层均校验召唤状态。

保留正式法术的有限时长，不因继承而重置或变成永久；修正怪物复活的 `remaining_turns == 0` 永久语义及对应保存校验。已具召唤身份且依赖父代的宠物繁殖时，后代改为依赖直接父代并继承剩余寿命。P2 普通永久宠物繁殖仍沿用没有召唤身份的模型，本批没有为它们另建父子图；该既有适配不等同于原版全部繁殖亲子规则。固定／分类／特殊召唤仍沿本项目已有施法者周围选点、确定性放置和有限寿命适配，未改造成完整源召唤分配器。

已补源码用例：真实施法开关与保存续演、固定／分类控制和维持、特殊家族及独特友军／数量上限、父代消失与携物、坐骑解除依赖、跨层及失控、复活永久寿命与循环存档拒绝、无空间及四种召唤入口的反召唤检查；同步更新 P3 的阶段性拒绝断言、P2 继承断言、协议及前端菜单用例。所有用例待统一执行，未编译、未生成绑定／Schema、未刷新契约。Rust 源协议 1.281、payload 37、State Hash Schema 142，生成物仍为 1.277、契约仍为 v338，正式内容包／lock 不变。特殊召唤／复活候选效用与友军继承、反召唤、永久寿命修复会影响对应既有怪物场景，统一验证须核对行为与 RNG 差异。
