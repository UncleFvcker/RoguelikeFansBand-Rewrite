2. 复用 `MonsterArtifactDropDefinition` 和 `game/loot.rs` 的命名神器掉落：前三者当前普通身份10%，蜈蚣5%。源怪物猎犬／猎犬契约术士的50%和怪物蜈蚣首领奖励不属于当前普通身份；保留源码位置，开放身份时再补真实消费者。
3. 在已开放地牢用完整正式全局分配取得代表怪物，验证实际到达与遭遇；可显式准备深度和重复抽样，但不只生成固定actor后宣称自然入口已接通。随后用核心真实攻击杀死目标，覆盖掉落成功／失败、拾取、未知保存、鉴定、装备、卸装及读档后的相同下一动作。
4. 共用掉落边界只补缺失的有效案例：Bad Luck、已生成仍按源消耗概率抽取但不重复创建、玩家宠物不发专属奖励、落地失败不错误占用唯一性；现有测试已覆盖的边界复用。三条项圈只验证各自真实属性／自由行动／速度差异，不复制整套矩阵。
5. Q1核心通过后，用新角色在普通Tauri standalone做一次代表“击杀→拾取→装备→保存恢复”；准备等级、怪物或命中种子须写入报告。此处通过即可交付Q1，不能等Q5结束才让首批可审查。

## 责任与验证

法术道具方向负责神器／必要底材、构造、激活、装备和战斗消费者；地牢城镇方向负责本批确实缺少的地点、任务、守卫及生态。已有actor和已有世界入口上的有界奖励挂接可随物品小组完成；需要改整条地点／任务链时才按[并行协作](parallel-development.md)交接。交接以提交、源ID、正式物品ID、入口和已运行证据为准，不默认启动新对话或并行代理。

验证按小组完成：源名称／参数／获取调用链 → 核心实际获取、使用与保存 → 相关现有消费者 → 普通Tauri standalone代表流程。Q2同构组可在阶段末合并一次桌面检查；Q3特殊战斗、Q4任务和Q5独有玩法随各自完成点验证。之前“等五步全部实现后再编译”的约定已用于常规底材，本计划不自动继承整批延迟验证。

内容变化同步正式包版本、lock、源C估值和现有来源／生成审计；类型确实变化才生成Schema／协议。共享初始化、状态哈希输入、RNG或协议受影响时，按[验证指南](testing.md)执行对应active契约；纯内容hash变化不刷新fixture。普通批次不自动扩大到全workspace、全前端、全地牢或Android。

每组交付必须说明正式入口是否开放、实际执行的检查与结果，以及未开放身份；准备式桌面验收不宣称自然练级／通关。完成记录留在提交与已有逐项清单中，本计划只保留排期、长期边界和下一小组。
