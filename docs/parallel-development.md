这是当前已经启动的工作方式，不是创建新任务的要求。先检查 `git worktree list` 与各树状态，复用现有目录。

| 对话 | 工作树 | 分支与责任 |
| --- | --- | --- |
| 种族职业 | `D:/codex/RoguelikeFansBand-Rewrite` | `main`；直接开发、测试并提交本方向 |
| 主线集成 | 同上 | `main`；日常只读审查，接管后合并、修复冲突、验证与推送 |
| 法术道具 | `D:/codex/RoguelikeFansBand-Rewrite-realms-items` | `codex/realms-items`；领域、书本、物品、Ego、神器、装置 |

## main 的写入交接

集成的 merge、生成文件、冲突修复和提交都会改变文件、索引与 HEAD。两个对话不能因为“集成不开发功能”就同时写同一个目录。

日常由种族职业写入。需要集成时：

1. 种族职业完成当前小批次的必要检查与独立提交，交出提交号并暂停写入。
2. 集成确认没有未保存的功能修改，再合并和验证。无关未跟踪文件如 `release/` 原样保留，不要求清空整个目录。
3. 集成提交、推送并报告新的 HEAD；种族职业重新读取状态和实际相关 diff 后继续。

没有交接时，集成可以审查已提交内容，但不自动 stash、提交其他人的修改或开始合并。集成期间种族职业不启动会修改同一构建目录或生成文件的检查。两个独立工作树仍可并行推进。

## 文件与内容的归属

归属按行为/稳定 ID 判断，不把每个共享目录设成审批关卡：

- 种族职业负责自身的 Class/Race、成长、出生、专属能力和新职业 Build。
- 法术道具负责领域书本、通用物品与效果；已有职业的新领域 Build 随领域接入。新职业同时依赖新领域时，明确该 Build 的单一负责人。
- 地牢城镇负责世界与地点定义、设施/任务、生态与守卫；奖励、库存和出生物引用同一物品定义，不复制近似物品。
- 法术召唤与地牢生态共享已有 actor。没有独立的全怪物导入方向，新增必要怪物随实际调用它的工作安排。
- Fluent、图集、协议和核心共用文件按本批所需接入。只有实际并发重叠或未满足依赖才协调。

两方确实需要同一项新机制时，由一个方向先交付可验证的底座，其他方向同步后使用。仅服务本批的必要改动直接随本批提交，不强制切成多个等待阶段。

## 提交、同步与集成

每批交付简要说明：提交号、目标行为、稳定 ID/共享文件、版本或 RNG/状态影响、验证结果和剩余问题。未变的协议/存档等合并成一句，无需填写无关检查清单。

两个独立分支在自己的修改已妥善保存后，用普通 merge 同步最新 main；不改写已被依赖的历史，不强推。集成按冻结的交付提交处理依赖和冲突。种族职业的提交已经在 main，无需再次 cherry-pick。

集成时把内容定义正确合并后再确定 pack 版本与 hash；不要选某一侧 lock 直接了事。生成物由最终定义生成。验证范围取实际交叉影响，不因普通合并运行全部历史测试；规则见[验证与契约](testing.md)。

各树默认保留自己的构建输出与前端依赖，不强制共用一个 `target/`。不要清理、修改或运行其他方向的工作文件。

## 已启动对话如何采用新文档

此次整理把日常指南迁到 `docs/`。旧入口如 `design/class-race-import-handoff.md` 和 `design/parallel-development-handoff-20260909.md` 留有迁移链接。档案可只读查证，但不继续向旧批次日志追加当前状态。

给正在运行的对话发送：

```text
继续当前任务，保留正在做的修改。项目文档已重新整理：
请读取当前根目录 AGENTS.md，以及 docs/ 中与本任务相关的指南。
旧 design 文档和 docs/archive 只作历史资料，不继承其中的旧待办、固定测试矩阵或审批步骤。
复用现有实现与测试；只补当前缺失行为，相关检查通过就交付，真实状态和并发边界仍保留。
本工作树尚未同步新文档时，先按这条消息执行；不要为同步文档强行 merge、stash 或重开任务。
用几行说明本批最小实现和验证范围，然后继续推进。
```

集成在正常同步时带入文档调整。若分支仍修改了旧交接文件，合并时保留其中的新事实到当前状态/相应指南，必要的历史证据进档案；不要把旧日志整段恢复为当前规则。
