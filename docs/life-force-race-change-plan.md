# 生命力耗尽后的永久种族转化实施计划

状态：五步已完成，2026-09-10 通过最终专项验收；详见[永久转化审计与共享经验修正](life-force-race-change-audit.md)及[五目标运行依赖审计](life-force-race-change-targets-audit.md)。规划基线：`4359de538`（幽灵正式开放）。原版唯一依据为 `D:/codex/Frogcomposband/master` 的 `master` Git 对象 `a0d92b6378d148c5262cc236b8fa6ed2ca06a54c`，以下源文件均指该对象。此项承接[幽灵审计第六节](spectre-race-audit.md)，不扩大为所有永久变形来源的接入。

## 目标与已确认规则

闭合真实 UNLIFE 攻击造成生命力耗尽后的流程：扣除 → 选择目标 → 尝试永久转化 → 按当前形态判定恢复生命力或死亡 → 正常完成回合、保存与继续行动。

`change_race` 本身没有重新执行出生函数，也没有重抽一套出生美德。转化不发出生装备、不改成夜间、不重新命名或创建存档。临时形态如何覆盖新本体及结束后的恢复必须按源代码链验证，不能为保证成功擅自清掉状态。

## 当前实现与需要先解决的差异

- [progression.rs](../crates/rfb-core/src/game/progression.rs) 的 `apply_life_force_drain` 只做饱和扣除；第四步已由 `drain_player_life_force` 接通有符号耗尽终点及 HP 刷新。[monster_combat.rs](../crates/rfb-core/src/game/monster_combat.rs) 的生产调用保留豁免、非生物排除、攻击者强化及事件，并接入幽冥伤害分流。
- 本体保存在 `build.race_id`；`character_definitions` 用临时 `granted_race_id` 覆盖当前形态。永久转化应修改已有本体身份，不能伪装成永久不消退的状态。
- 临时免疫函数包含龙人蜕变；身体重整已有 `reconcile_player_body_slots_for_current_form`。永久流程只复用语义相同的部分，不原样调用整条临时变形路径。
- “新生”物品已复用 `CharacterProgress::roll_hp_progression`，但同时改变属性潜力和突变，不能调用整个物品效果替代 `do_cmd_rerate`。
- 第一步已把共享经验改为原始经验账本及本体种族/职业/性格门槛，按原版分段截断，并复核已有经验对应的升降级。旧开发存档拒绝加载，不反推历史奖励；具体边界和测试见审计第一节。
- 第二步已补齐[吸血鬼定义](../packs/rfb-demo-original/races/vampire.json)的非生物/不死、保持生命、感知、吸血补给、日照和灯具伤害等运行消费者，并复验五目标的能力、身体、补给及保存。昼间熄光区域作为持久状态保存，吸血鬼本体可读档；新增创建入口不在本步范围。

## 分步实施与完成条件

### 第一步：补齐永久转化审计和经验语义（已完成）

沿 `lp_player → change_race → check_experience / rerate / equip` 逐项建立原版与重写映射，补查所有生命力变化入口、HP 更新次序、攻击者强化顺序，以及现有正式种族中人类/半神/龙人的天赋清理。核对原版旧种族记录、出生身份、技能熟练度、已学能力及美德的实际消费者。

本步必须给出经验处理的具体决定：若原始经验与种族门槛不可由当前状态正确表达，先完成最小的共享经验模型修正，再推进终点接线；不能将这个差异埋进转化函数。明确当前/最高经验、当前/最高等级与等级奖励的处理，防止等级下降后再次升级重复发放奖励。

完成条件：每个原版副作用均标记为现有可复用、必须补齐或未开放系统依赖；确定需要新增的最少持久字段及其消费者。未开放怪物职业、竞赛模式不新增虚拟玩法或开关；未来接入时再验证对应分支。

### 第二步：补齐五个转化目标的运行依赖（已完成）

重点完成吸血鬼专项：枚举原版直接引用及旗标消费者，补齐非生物/不死、保持生命、红外、光照与日照受伤、吸血能力和营养、普通食物/药水分支及临时形态区别。复验骷髅、僵尸、幽灵、英灵战士的转化后被动、能力、补给与身体规则。

仅对本流程要求的“转化后能正确运行”补齐规则；出生卷轴、出生时钟和吸血鬼创建页面随其独立开放计划处理。保持五种目标和固定抽签顺序，不通过移除吸血鬼、重抽可用种族或失败直接选幽灵绕过依赖。

完成条件：五种目标均可由核心显式本体前置验证生存、行动、资源与保存；吸血鬼在日间转化、饥饿及吸血补给的实际效果通过测试。

### 第三步：实现最小永久本体切换操作（已完成）

在核心增加一个承担本次需求的内部操作；优先放在现有进度/种族相关模块，只有现有文件职责确实不适合时再拆文件。输入目标种族，输出可供调用者判断的实际切换结果及领域事件，不新增通用事务框架、任务队列或外部命令。

按审计确认的顺序处理：

1. 检查本体、当前形态、目标及永久免疫条件；拒绝时不消费生命成长随机数，也不部分改写角色。
2. 清理原种族专属天赋、锁定来源和子种族关联，保留无关突变、职业、性格、装备实例和进度。天赋撤销可能改变身体，避免重复卸装或递归触发转化。
3. 更新本体及必要的历史身份；按原版调用运气美德增加 2（沿用美德缺席时的现有规则），保留已有美德槽位，不按新种族重新抽取美德。
4. 重算经验/等级、生命成长、技能与派生资源。复用生命成长算法和模拟 RNG，不重抽属性潜力、不执行“新生”的突变清理，不默认满血满蓝。
5. 按仍有效的当前形态重整身体和装备，处理槽位冲突、箭袋/容器及背包溢出；保持物品数量和身份。更新光照、能力、速度、抗性与骑乘资格，必要行为严格依原版。

完成条件：成功、同种族拒绝、永久免疫、带临时形态、原种族天赋撤销、等级变动与装备重整分别通过聚焦测试；保存后本体身份不会恢复为创建种族。

实现入口为 [progression.rs](../crates/rfb-core/src/game/progression.rs) 的内部 `change_player_race`，返回实际切换布尔值并追加 `PlayerRaceChanged` 等领域事件。目标沿用可运行本体范围（正式种族及第二步允许保存的吸血鬼），拒绝在任何状态改写及 RNG 消费之前完成。种族天赋按原奖励定义撤销锁定及突变；龙人蜕变允许永久切换。保留身份、属性潜力、生命力、美德槽位、物品实例及历史进度；重掷生命成长并重算等级、资源和派生值，不默认回满。临时形态继续覆盖新本体。

新增状态仅为 `ability_learning_order` 和物品 `previously_worn`。暂忘集合由学习顺序减去当前已学集合得到；降级及容量变化按原版先忘后记的结果保留最早可用的学习，熟练度不丢失。装备按旧身体槽位顺序放入新身体第一个兼容空槽，先处理箭袋/容器容量与溢出，再自动穿回；`@mimic` 等原版铭文抑制标记。背包使用现有投影和保存的 ID 顺序，保存前后后续整理一致。武器熟练度保留存量，只在有效读取时受当前上限约束。

12 项新增聚焦测试覆盖永久切换拒绝与 RNG、生命成长/资源/美德、临时形态、人类和龙人天赋、等级下降再恢复、武器熟练度、装备与铭文、箭袋/容器溢出、槽位优先级、学习顺序及暂忘恢复。核心全量 957 项、前端 185 项及类型检查通过；活动契约 26 项复验通过，逐字段确认只变更 41 个哈希值。协议 `1.237`、payload `8`、状态哈希 schema `112`，旧开发存档不兼容；包内容未变。本步没有接通 UNLIFE 终点，也没有新增外部命令、创建入口或试玩构建。

### 第四步：接通生命力终点及战斗事件（已完成）

将终点处理放在可访问完整游戏状态与事件的层级；保留纯扣除函数的简单职责。正常非零扣除不多消耗 RNG；归零/越过零按原版先抽目标再尝试切换，不能因预判免疫改变抽签顺序。

尝试后按当前形态的非生物资格将生命力重置为 1000，或走现有不可逃避伤害及死亡流程。保留怪物攻击的实际扣除量、攻击者强化和事件语义，明确“扣除后的 0”与“转化后的 1000”，避免 UI 将整条流程错误显示成生命力未变化。以审计结果决定 HP 缩放和重算的先后，避免先缩到极低值再恢复造成额外取整伤害。

完成条件：通过真实 UNLIFE 攻击命令触发五种目标；边界包括恰到 0、越过 0、零扣除、已为 0 的可达调用、免疫/豁免不触发、相同本体目标、切换失败后仍为非生物、临时活体形态使终点判定失败，以及同一攻击剩余击数在转化/死亡后的行为。禁止添加 1 点生命力保底或无条件复活。

生产近战与接触效果现已进入该终点：按固定五目标顺序抽签，使用第三步永久切换操作，再读取当前形态判定生命力恢复或不可逃避死亡。怪物近战、法术及接触光环的幽冥伤害按抗性结算后分出 15% 进入同一流程，接触攻击者按完整分流量强化，远程施法者不强化；转化成功后继续剩余伤害，死亡后终止。

扣除期间以有符号运行值保留越零量，首次种族刷新使用扣除前已结算的最大 HP，避免多加一次旧身体缩放。存档及快照仍只允许 0..1000。事件同时提供扣除后值和终点完成值，文案区分耗尽与恢复。原版延迟 HP 缓存和重写即时派生的边界详见[审计第六节](life-force-race-change-audit.md#6-第四步生命力终点实施)。

11 项新增聚焦测试覆盖五目标真实 Wait 攻击、保存后继续行动及 RNG、恰到/越过零、零扣除、已有零值、同本体拒绝、当前非生物、保持生命豁免、永久免疫及临时活体的不可逃避死亡、剩余攻击效果及击数、接触光环死亡和幽冥近战/远程/光环分流。协议 `1.238`；payload `8`、状态哈希 schema `112`、内容包 `1.399.0` 均未变。六职业连续流程、界面及桌面专项现已由第五步验收。

### 第五步：保存、界面与专项验收（已完成）

角色页、HUD、能力列表、光照/营养与事件文案应随权威状态更新；清理已失效的能力选择和快捷操作。名称继续使用原版中文表；文案区分生命力耗尽、永久转化、生命力恢复和死亡。

六个正式职业至少覆盖一次真实攻击触发到继续行动的连续核心流程；五种随机目标、不同原本体和关键形态边界用最少的独立用例覆盖，不机械扩成全部组合。固定种子核对目标抽签、生命成长、攻击者强化、事件顺序和保存前后后续 RNG 一致性。桌面专项抽查转化后的身份、能力、物品、存档及继续行动；若用测试前置降低生命力，记录中明确注明，不声称正常短程游玩自然达到。

只刷新行为发生变化的契约类别。若第一步需要改变持久状态或共享经验/初始化，按项目规则调整相应 schema 并扩大回放验证；内容变动更新包版本与 lock，不能仅因 contentHash 变化就改状态哈希版本。无旧开发存档兼容。需要交付试玩包时使用 standalone Tauri，区分普通构建与 WebDriver 验收构建。

完成条件：相关核心/内容/导入/前端检查及受影响契约通过，新增字段正确保存并参与必要的状态哈希；记录真实测试范围后，才从幽灵审计中移除“永久转化缺失”。

最终实现与取证见[审计第七节](life-force-race-change-audit.md#7-第五步保存界面与最终验收)。角色页显示生命力，HUD 生命条提示同步精确值；耗尽、永久转化、恢复、不可逃避死亡、经验吸取/降级及吸血鬼光照伤害均有前端本地化分支。种族名复用原版内容键。已有目标协调器会取消已移除或不可施放的能力选择，能力面板按投影重建；快捷栏目前仍为未接入占位，没有需要迁移的旧绑定。

六职业通过同一组明确前置触发原版古墓尸妖的真实攻击，并验证物品身份、职业/性格、事件顺序、攻击者强化、存档及后续行动/RNG。前置为 19 级、生命力 1、相邻清醒怪物、局部熄光及固定模拟 RNG；不固定命中、吸取量或转化结果。既有 11 项终点测试覆盖全部五目标和形态/死亡边界。桌面抽查战士与弓箭手转为吸血鬼、死亡高阶法师由小恶魔转为幽灵，核对界面、种族能力目标选择、物品、导出/载入及继续移动。该过程不声称正常短程游玩自然耗尽生命力。

## 交付边界

实施顺序为：**审计与经验语义 → 五目标运行依赖 → 永久切换 → 生命力终点 → 专项验收**。前两步是接通生产终点的前置条件，可先独立提交；中间版本不宣称已闭合生命力耗尽。

不顺带接入混沌自变形、其他永久变种族道具、变形怪菜单、怪物职业、竞赛模式或计分系统。已有消费者必须正确处理；尚不存在的历史统计/UI不为本批虚建。若审计确认现有字段不足，应明确补最小状态，不能以避免 schema 变更为由省略正确性。
